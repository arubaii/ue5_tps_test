# Widget Paths (skill trees, talent webs, flowcharts, maps)

> **Standing expectation (the request's own words):** "There could be more use cases that users desire that I haven't thought of, but would be expected in a production-grade application." The section *Beyond the request* lists what was added for it; *Still open* lists what is still expected and not done.

## What it is
- **Widget Path Layer** (`Widgets/Paths/WidgetPathLayer.h/.cpp`; `UWidgetPathLayer`, `SWidgetPathLayer`, palette NameTBD): one widget that draws every line ("connection") between widgets of the same Widget Blueprint (its "nodes"). Put it in the same tree as the nodes - usually behind them, filling the area they are in (an Overlay or Canvas slot set to fill) - and list Connections (From / To are dropdowns of the tree's widgets, `GetOptions = GetWidgetOptions`). Lines follow their nodes wherever they are laid out, animated, constrained or scrolled. Hit Test Invisible by default (never blocks its nodes).
- **Nodes' Slate widgets are found lazily:** each line carries its nodes' `UWidget`s (`FWidgetPathSlateEdge::FromWidget / ToWidget / OrbitCenterWidget`) and the Slate layer re-reads `GetCachedWidget()` every tick and paint (`SWidgetPathLayer::ResolveNodes`). A layer synchronized before its nodes are built (it comes first in its panel - the usual "behind the nodes" place) or after the designer rebuilt them (a compile) used to keep null Slate pointers until the next push - lines vanished on compile and in game only came back once a hover pushed again.
- Data types, routing geometry and presets: `Widgets/Paths/WidgetPathTypes.h/.cpp`; pictures / materials shared with Pointer Effects: `Widgets/WidgetEffectImage.h/.cpp` (`FWidgetEffectImage` - Image Source, brush, SVG, Material Parameters -, `FWidgetEffectMaterials` - a dynamic instance per key, live inputs set only on change). Widget-name dropdowns for any setting: `Widgets/WidgetTreeLookup.h/.cpp` (finds the tree through outers - Widget Tree, User Widget, or an outer with a `WidgetTree` object property, read by reflection so the runtime module needn't know `UWidgetBlueprint`).
- **Designer tool** (`NameTBDEditor/Private/WidgetPathConnectTool.h/.cpp`, `FWidgetPathConnectExtension`): select two or more widgets in a Widget Blueprint that has a layer, and a toolbar over the first offers **Connect** (each widget to the next, ordered along the way they are spread - left to right or top to bottom - so a row of nodes is chained in one click; existing links kept) and **Disconnect** (links among them). One transaction; edits the template and the designer preview's layer. Tooltips `NameTBD::Tooltips::WidgetPathTools`.

## How production tools do it (researched)
- **Node editors / diagram libraries** (React Flow, JointJS, GoJS, Unreal's own graphs): edge types Straight, Bezier ("default"), Step and **Smooth Step** (orthogonal with rounded corners), markers (arrow / arrow closed) at either end, animated (marching) dashes, ports on a node's sides, edges routed from the side facing the target. Taken: Straight / Curve / Elbow (with Round / Sharp / Chamfer corners) / Step, sides with Auto, Start/End markers, marching dashes, spread ports.
- **Game skill trees** (Path of Exile's passive tree, Diablo IV, Last Epoch, Borderlands, Ghost of Tsushima): line style by the state of both ends - locked (dim), allocatable (lit edge from an allocated node), allocated (bright, often with light flowing); hovering a node **previews the route** to it from the allocated set (PoE) and shows the cost; unlocking **draws the line on** from the reached node; radial trees route along **orbits** round a center. Taken: state rules, Derive Available, Hover Highlight Route To, Find Route (for costs), Draw On transitions from the reached end, Orbit route.
- **Transit maps / PCB art**: octilinear (45-degree) runs with round or chamfered bends, a casing (outline) under a colored line, station markers. Taken: Diagonal route, Outline, Dot markers, presets Metro / Circuit.
- **Line renderers technical artists build with** (Niagara ribbons, Unity's LineRenderer / Shapes, Rive / Lottie strokes, Illustrator's path effects): a material per line with UVs along (stretch or tile by distance) and across, width over length (curve / taper), several stacked strokes, per-instance random and dynamic parameters, sprites along the path, end caps as images, path effects (wave, zig-zag, roughen). Taken: all of these (Strokes, taper + Width Curve, material instances with live inputs, Flow / Marker / Glow Images, Distortion).
- **Skill tree node states** (Path of Exile, Diablo IV, Last Epoch): locked, available, allocated - and unavailable (a level requirement, a mutually exclusive branch) shown greyed and skipped by path previews. Taken: the four built-in states picked from a list, custom names for the rest.

## Routing (`FWidgetPathRouting`, `WidgetPathGeometry`)
- `EWidgetPathRoute`: **Straight**, **Curve** (cubic leaving each end along its side or the route axis, reach = Curvature x max(|dx along axis|, 0.3 x length, 24)), **Elbow** (Manhattan: out, across at Elbow Position, in; goes round the back with stubs when the target is behind; same-direction sides go out past the further; perpendicular sides make an L, or stub-L-stub), **Step** (one bend: To side picked across the first run; level nodes go straight in), **Diagonal** (straight + 45-degree + straight, the slant at Elbow Position, on the longer axis), **Arc** (circular arc through a sagitta of Bend x half the chord; exact circle, sampled to Tolerance), **Orbit** (round Orbit Center widget or Orbit Point, radius lerped between the ends - a spiral when they differ, a spoke when they share an angle; Long Way), **Waypoints** (through the points, cornered, or Catmull-Rom with Smooth Waypoints).
- `EWidgetPathCorner` Round (circular fillet of Corner Radius - tangent R tan(turn/2), held to half of each run, all of an end run - drawn as a cubic arc approximation, 4/3 tan(turn/4)), Sharp (miter join), Chamfer.
- Orientation Auto: across when the nodes' gap (centers apart minus half sizes) is wider across than down.
- Sides (`EWidgetPathSide`): Auto (Center for Straight / Arc / Orbit / Waypoints; the side facing along the axis otherwise), Center, Left / Right / Top / Bottom. Side ports sit at the side's middle + Gap; Center ends are clipped where the line leaves the node's outline + Gap (`ClipStart` / `ClipEnd`: walk to the first point at Gap, then bisect 24 times).
- **Node outline** (`EWidgetPathNodeShape`): Auto reads the node (`UDropShadowComponent::ReadCaster`: Rectangle / Glass Panel / rounded brushes / pills; `UEllipseShape` = ellipse; through a User Widget's root and Size Box / Scale Box / Overlay first child, 4 levels), Box, Ellipse, Point. Distances: rounded-box SDF (`WidgetEffectsDraw::RoundedRectDistance`), ellipse along the ray.
- **Spread Ports**: lines on the same side of the same node are spread Port Spacing apart, ordered by where their other end is along that side.
- Nodes are measured where they were last painted (`GetPaintSpaceGeometry`, transformed into the layer's space, as an axis-aligned box), so a node moved by anything is followed; a layer painted before its nodes is one frame behind a node that moves (put it after them if that matters - lines end at node edges, so they don't overlap).
- Routes are resampled to 6-unit steps (gradients and pulses are per vertex) and cached per line by a hash of both boxes, the routing, port offsets and tolerance.

## Looks, styles and rules
- **`FWidgetPathLook`**: Width, **Start / End Width Scale** (taper) and **Use Width Curve** + Width Curve (width along the line); Paint Color / **Gradient Along Path** (stops from From to To) / **Image** (Image Source Texture 2D or SVG - the image-source rule - laid along: U along (once, or every Image Tile Length), V across; Image Scroll Speed; **Material Parameters** for a material); Cap; Dashes (length, gap, **Dash Speed** marching); Outline (casing); Glow (a wide stroke whose anti-alias fade is the glow: width + Glow Size, fade Glow Size; or **Glow Image** - a texture / material / SVG across the glow, hard-edged, tinted Glow Color); **Breathe** + Breathe Rate (glow, flow and strokes set Breathe With Look pulse 1 - Breathe .. 1); **Flow** Pulse (bands of light by the vertex's distance along: sin^2 bump Flow Length long every Flow Spacing, moving Flow Speed) / Dots / Arrows (marks every Flow Spacing, fading at the piece's ends, pointing the way of the flow; **Flow Image**: a picture per mark instead, Flow Size across, its top along the flow - one mesh, one draw); Start / End Marker (Arrow, Open Arrow, Dot, Diamond, Bar; arrowheads pull the line back so it doesn't poke through; **Start / End Marker Image**: a picture instead, its top at the line's end toward the node, no pull-back); **Strokes** (`FWidgetPathStroke`: under or Above Line, Width, sideways Offset (+ right of From->To), Start / End Width Scale, Paint Color / Gradient / Image (`FWidgetEffectImage`), tile / scroll, dashes, Opacity, Breathe With Look - casings, rails, cores, material beams); **Distortion** (`FWidgetPathDistortion`: Wave Amplitude / Wavelength / Wave Speed, Jitter Amplitude / Spacing / Rate (pattern changes Rate times a second - lightning) / Smooth Jitter, End Fade so the ends still meet the nodes; every part of the look follows it); Opacity; **Draw Order** (higher over lower: drawn in groups, each group glow -> outline + strokes under -> line -> flow -> strokes above + markers on its own layers).
- **Materials (for technical artists):** any material in a look (line Image, Glow / Flow / Marker Images, Stroke Images) gets a dynamic instance per line, look and part (`SWidgetPathLayer::MaterialKey`; kept by `FWidgetEffectMaterials`, pruned in `SetEdges`, reset in `SetLooks`), its Material Parameters, and live scalars: `PathLength`, `PathWidth`, `PathRandom` (0..1, stable per line), `PathRevealStart` / `PathRevealEnd` (the drawn part - the draw-on), `PathProgress`, `PathHighlighted`, `PathHovered`, `PathSelected`, `PathTileLength`. UV0: U along (per tile or once), V across. Vertex color: tint x opacity. A look with a material counts as animated (repainted every frame, so its Time moves).
- Varying width (taper / curve), strokes and Glow Images are built with `WidgetPathGeometry::BuildRibbon` (per-vertex width and offset along the resampled route, miter normals clamped at 4x, AA fringe each side, flat ends; dashes = one ribbon per dash, `BuildRibbons`); everything else with the shapes' stroke builder as before.
- **Styles** (`FWidgetPathStyle`: Name + Look - the Look shown as its own group, not flattened, see Decisions) and **Rules** (`FWidgetPathStyleRule`: **From State / To State** picked (`EWidgetPathStateFilter`: Any, Locked, Unlocked, Available, Unavailable) + **From / To Custom State** (wins when given), Either Way, Highlighted / Hovered / Selected each Any / Yes / No, Style). First rule that holds wins; nothing: the first style. A connection's Style (or Set Connection Style) wins over the rules.
- **Node states** are picked, not typed: `EWidgetPathState` **Locked, Unlocked, Available, Unavailable** (+ **Custom**, what a state of the game's own reads back as), each beside an optional **Custom State** name that wins (`WidgetPathStates::Resolve`; internally states are names - "Locked"... - so rules match a custom name exactly as before). Layer: **Default Node State** + Default Custom State, **Unlocked State** + Unlocked Custom State, **Available State** + Available Custom State, **Routes Avoid Unavailable** (default on: routes neither pass through nor end at an Unavailable node). Set Node State(s) > read from the node (`IWidgetPathNode::GetWidgetPathNodeState(State, CustomState)` -> bool "answers", 10 Hz, with Read States From Nodes) > the authored Nodes list (Widget, State, Custom State) > Default Node State. **Derive Available**: a default-state node linked to an unlocked one reads Available (from raw states, so it doesn't spread; with Routes Follow Direction only along From -> To; an Unavailable node stays Unavailable).
- **Old assets:** the FName fields were renamed to the Custom ones by CoreRedirects (`Config/DefaultNameTBD.ini`: Rule From/ToState -> From/ToCustomState, Node State -> CustomState, layer DefaultNodeState / UnlockedState / AvailableState -> *CustomState) and `PostLoad` (`NormalizeStates`, the preset asset's too) moves a custom name that is a built-in's into the enum - so a rule saved as "Unlocked" loads as Unlocked, picked.
- **Highlight**: route to the selected node (Set Selected Node; Preview Selected Node in the designer) from the nearest unlocked node (BFS back from the target; Routes Follow Direction makes it one-way; Unavailable nodes are dead ends); Hover Highlight None / Connections / Route To (runtime, polled every frame with `WidgetAnimInput::IsPointerOver` - Diegetic Screen pointers too); manual Highlight Route / Highlight Node Connections / Clear Highlight.
- **Presets** (`EWidgetPathPreset`, `WidgetPathPresets::Apply`): Skill Tree (default), Constellation, Circuit, Flowchart, Metro, Organic, Radial; each five styles (Locked, Available, Unlocked, Highlighted, and **Unavailable** - the Locked look faint, red-grey, dotted, draw order -1) and the same five rules (Highlighted; any end Unavailable; Unlocked-Unlocked; Unlocked-Available; the rest Locked). Editing Routing / Styles / Rules makes it Custom.
- **Preset assets** (`UWidgetPathPresetAsset`, a Data Asset "Widget Path Preset"): Apply Routing, Routing, Styles, Rules. The layer's **Preset Asset** applies it when picked (Preset becomes Custom; editing the look clears it); **Save As Preset** (CallInEditor on the layer) makes one through the editor's Save Asset As window (`WidgetEditorHooks::CreateAsset`, set by NameTBDEditor with `UDataAssetFactory` + `CreateAssetWithDialog`) and picks it; Blueprint Apply Preset Asset / Copy To Preset Asset (runtime theme editors). Applying is a copy, not a link: an edited asset is applied again with Apply Preset Asset.
- **Preset changes reach the Widget Blueprint:** the Details panel edits the designer's preview copy and migrates only the edited property; `PostEditChangeProperty` then also writes Preset, Preset Asset, Routing, Styles and Rules onto the Widget Blueprint's own widget (`SyncLookToTemplate`, via `WidgetEditorHooks::FindDesignerTemplate`: preview's User Widget class -> `UBlueprint::GetBlueprintFromClass` -> its WidgetTree by reflection -> widget of the same name), so what a preset wrote survives the next compile.

## Animation
- **Transition** (`EWidgetPathTransition`) when a line's style changes: **Draw On** (the new look over [0, c] and the old over [c, 1] from the end that changed first - each node's `ChangeSerial`: drawn toward the node that changed last), Fade (cross-fade), Instant; Duration + Motion (`EWidgetMotion`). A line added while shown draws on.
- **Progress**: a connection's Progress (0..1, Set Connection Progress animates) fills it from its From node with Progress Style (None: the style named Unlocked State).
- **Intro** (None / Draw On / Fade): each line from its node's depth from the roots (BFS from nodes nothing leads to) x Intro Stagger; played once when shown at runtime, again with Play Intro.
- The Slate layer's active timer runs while it has lines (it notices nodes moving by a hash of their paint transforms and repaints), and calls the UMG layer's polling at runtime.

## Beyond the request (production expectations added)
- The Unavailable state routes avoid; Is Node In State / Get Node State Name; preset assets usable at runtime (Copy To Preset Asset - an in-game theme editor); every look part takes a texture, material or SVG with live per-line material inputs; extra strokes (casings, rails, cores, beams), taper and width curves, wave / lightning distortion of the path, picture flow marks and markers - the toolset of a line renderer (Niagara ribbons, Unity's LineRenderer) for technical artists; the presets kept as quick starts.
- Graph queries for game logic (Find Route for "points needed" / buy-route, neighbours, nodes in a state), Derive Available so the game only reports what is unlocked, nodes reporting their own state (interface).
- Spread ports, node-outline-exact endings with gaps, Draw Order, progress fills on a line, intro reveal by depth, breathing "available" glow, flowing energy, arrows for direction, image/material/SVG along lines, Diegetic Screen hover, runtime-built trees (connections by widget reference), designer Connect tool, preview of the selected route in the designer.
- A Follow Path constraint can run a widget along any connection (orbs travelling the tree).

## Decisions made without asking
- One layer drawing every line (not a widget per connection): hundreds of lines cost one widget, rules see the whole graph.
- Node states are picked from an enum (Locked, Unlocked, Available, Unavailable) with an optional Custom State name beside every state field and parameter, which wins; inside they stay names, so a game's own states ("Maxed", "Disabled") plug into the rules. `EWidgetPathState` has a Custom value only so Get Node State can report a custom one; setting Custom with no name clears what was set.
- The old FName fields became the Custom ones (CoreRedirects + PostLoad normalization) rather than being dropped, so existing layers keep their states; Blueprint nodes calling Set Node State / Get Node State / Get Nodes In State, the interface's implementations and On Node State Changed bindings change signature (the feature is new; refresh those nodes).
- Unavailable blocks routes by default (Routes Avoid Unavailable) and never becomes Available.
- Preset assets are applied as a copy (like the built-in presets), not linked: the layer's own Styles stay editable, and the asset is applied again on demand.
- Style Looks, Routing and Pointer Effects' Outputs are no longer `ShowOnlyInnerProperties`: fields inside them shown by an EditCondition (a gradient's stops, an image) could stay hidden in that combination (the Constraints report) - each is now its own expandable group.
- Tapered / curved / stroked lines are built with a ribbon builder of their own (flat ends; joins are miters on the 6-unit resampled route) - the stroke builder takes one width.
- Nodes measured from their last paint (no layout pass of its own); one frame behind a moving node when the layer paints first.
- Spread ports group by side and order by the far end's position (not by connection order).

## Still open
- A preset asset linked live (edits to it re-applied to every layer using it) rather than copied when picked.
- Round caps and AA end fringes on tapered / stroked ribbons; a per-mark material index for Flow Images (one instance per line's marks today).
- Lines that avoid other nodes (obstacle-aware orthogonal routing, as diagram tools' "avoid nodes"); bundling of parallel lines; jump-overs where lines cross.
- Hit-testing a line (hover / click a connection), and a tooltip on it.
- Editing Waypoints by dragging on the canvas (today: the Details list); a designer gizmo for Orbit Center.
- Node outlines for rotated nodes (an axis-aligned box of the rotated node is used).
- A per-state node look (the layer styles lines only - nodes style themselves, e.g. from their state machine).

## Unverified (no engine here: written, not compiled or run)
- The diagnosis of "lines removed on compile / only after a hover": nodes' cached Slate widgets null or stale at the layer's sync (fixed by resolving them every tick and paint); that the active timer runs at design time once lines exist.
- That the UMG Details panel edits the preview copy (hence `SyncLookToTemplate`), `UBlueprint::GetBlueprintFromClass` from the runtime module in editor builds, and CallInEditor buttons (Save As Preset) showing in the UMG Details for a widget.
- Material inputs: a dynamic instance per line made during Slate paint (`UMaterialInstanceDynamic::Create` with the transient package, kept by `TStrongObjectPtr`); custom verts drawn with a material brush; the ribbon's dash offset sign matching the stroke builder's marching direction; `FRuntimeFloatCurve` (Width Curve) as a member of a struct inside an array.
- CoreRedirects for struct members inside arrays (`WidgetPathStyleRule.FromState` etc.) loading the old FName values into the Custom fields.
- `SetVisibility` in the constructor (CDO) for the Hit Test Invisible default; `GetOptions` on fields of structs inside arrays (Connections, Routing) resolving `GetWidgetOptions` on the layer.
- `GetPaintSpaceGeometry` of nodes painted after the layer (one frame old), nodes inside a retainer/Shape Box warped content (different paint space).
- The stroke builder with very large AA widths (the glow), dash offset sign (marching direction), `FWidgetSVGBrush::Get` at tile size along a line.
- The designer tool: `FWidgetReference` order, preview geometry for ordering, the preview layer updating after `SynchronizeProperties`.
