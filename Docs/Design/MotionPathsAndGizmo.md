# Motion Paths and Widget Gizmo

## Motion paths (MotionPaths v1)
- **What:** where the open animation moves a widget, drawn over the UMG designer's canvas, the way After Effects / Rive / Blender draw motion paths: a line through every moment (through the widget's Render Transform Pivot), a **dot per frame** (spacing = speed), a **diamond per key** (fix5: exactly the Track Editor's key colors - `WidgetAnimEditor::Key` / `KeyHovered` / `KeySelected` + `KeySelectedGlow` / `KeyOutline` / `KeyReadOnly`), a **dashed line without dots for a jump** (Hold / step), the played stretch fainter than what is ahead, and - while the panel poses the preview - a **ring where the widget is now**.
- **Which widgets:** (fix3) every widget the open animation moves (Target Widgets of Transform/Slide/Shake layers), plus the widgets selected in the designer and the widgets of the tracks / keys selected in the panel (max 8). **No selection needed** (fix8, final): see Hosting below. (History: fix5 laid a canvas into an `SOverlay` from an `FTSTicker`; fix6 laid it into the editor window's overlay from `FDesignerExtension::Tick` and disabled the selection fallback once laid - nothing showed; fix7 was a compile fix of fix6. All replaced by fix8.) Shown whenever the Widget Blueprint's Widget Animations panel has an animation open (Animation Timeline or Edit Existing Asset) - **on screen or not** (fix1: the status bar drawer closes as soon as the designer is clicked, so v1, which needed the panel posing, never showed a path from the drawer); the builder too since fix4 (its own live preview); not for a component's Additive Anim Layers list.
- **Data path:** `IWidgetAnimPanelSource::GetPosedAnimation(FPosedAnimation&)` - the flattened settings (setting N = layer N), the baselines, the preview (fallback widget), `bIsOutAnimation`, `bPosed`, and a `Version` that counts up whenever settings are rebuilt or baselines recaptured (only `FWidgetAnimAssetPanelSource` implements it; `PosedVersion`). Panel on screen: its posed `Flattened` + `Baselines` (`bPosed`). Panel off screen (fix1): `UnposedSettings` built with `BuildFlattened` on the preview as authored, and `UnposedBaselines` = only the targets' current render transforms/opacity (no `CaptureWidgetAnimBaselines` - capturing material parameters would give widgets dynamic materials); rebuilt when asked after an edit (`bUnposedStale`, set by `OnObjectPropertyChanged`, `NotifyInteractiveEdit`, `ResetPlayback`) or every 0.5 s; never posed. The overlay finds the panel by Widget Blueprint (`WidgetAnimScripting::FindLastUsedPanelForBlueprint`), fans the settings out once (`ExpandSettings`), keeps only the layers targeting the widget or one of its parents (up to the preview), and samples them with **`UWidgetAnimLibrary::EvaluateExpandedStackAtTime`** (new: `ApplyWidgetAnimationsAtAlpha` without applying - it now calls it) + **`GetResultPose`** (new: a widget's render transform from a result, composed over its baseline exactly as `ApplyResultInternal` does). Nothing is posed and no cue fires, so every easing, segment curve, spring, overshoot, stagger and delay is in the path exactly as the preview plays it.
- **Sampling:** at Dots Per Second (or the panel's Frame Rate while Show Time In Frames is on) with up to 240 samples/s in between for a smooth line; at most 6000 samples per path. Poses are cached per chain widget per sample and worked out again only when `Version`, the widgets shown, the dot rate, the panel's pass length or Invert change (the source rebuilds `Flattened` every 0.5 s and on every edit, so ~2 rebuilds/s idle, one per frame while dragging).
- **Rest poses (fix8):** the poses a path is sampled over never come from the preview's live render transforms. The source's `UnposedBaselines` are the widgets **as authored** - `GetWidgetAnimAuthoredTransform(PreviewWidget, Blueprint, &Opacity)` (`WidgetAnimPanelSource.h`): the Widget Blueprint's own widget of the same name, or the generated class's CDO for the preview root; before fix8 they were re-read every 0.5 s from the preview, so anything playing on it (the designer toolbar preview) made the path and keys jump. `Rebuild` also gives every chain widget that no layer moves and that has no baseline its authored pose (`ChainBaselines`, used by `GetResultPose`), instead of `GetRenderTransform()` as it stands. Only the "now" ring follows the playhead.
- **Mapping (every frame, fix5: layout only - drift-free):** per chain widget (widget, then each parent up to the highest one the animation moves) `ReadChain` keeps `GetAccumulatedLayoutTransform()` (+ inverse), pivot and current pose; the top widget's Slate parent's render transform + layout inverse carry the result onto the screen (zoom/pan, anything above). A sampled pose is put on through `PivotedPose` level by level (`LevelToAbsolute` / `MapChain`). Render transforms of the animated widgets are never read back, so nothing moves while the preview plays or a key is dragged (fix4 and before took this frame's pose off last frame's geometry, which shook). Drag units: `UnitsToScreen` (finite-difference 2x2) / `ScreenToUnits`, read at the press.
- **Keys:** diamonds at the panel's own key times (`GetLayerSpans` + `GetKeyTimes`, mapped by `GetPassSeconds` to the preview's pass; mirrored with Invert), for Transform (Content Transform) and Slide tracks on the widget or a parent, and Scale / Rotate on a parent. A value-key track with no keys between its start and end gets its start and end as smaller "edge" diamonds. Click = `SelectKey` (Ctrl toggles / Shift adds via `SelectKeyWithModifiers`); an edge = `SelectLayer` + `ScrubToSeconds`. **Drag a Transform key's diamond** = `SWidgetAnimTimeline::BeginKeyPositionDrag` / `UpdateKeyPositionDrag(Delta)` / `EndKeyPositionDrag` (one transaction "Move Key on Motion Path", Interactive notifies, preview held on the key, Translation rounded to 0.1, Use Authored Transform switched off, the rest of the key's pose kept; a click without a move cancels the transaction). The screen delta is turned into the moved widget's Translation units through its place on screen at the press (works for a parent's key too); Shift locks to the screen axis moved along most. `IsDragging()` includes it.
- **Hosting (fix8):** no widget is laid anywhere. `FWidgetAnimMotionPathExtension` overrides `FDesignerExtension::Paint(Selection, AllottedGeometry, MyCullingRect, OutDrawElements, LayerId) const`, which `SDesignerView::OnPaint` calls for every extension on every frame it draws, right after its preview, with or without a selection. On its first paint it makes a `WidgetAnimMotionPathImpl::FMotionPathLayer` (plain `TSharedFromThis`, one per designer) and calls `Layer->Paint`: the designer's own geometry is the canvas (diamond/handle/label sizes are designer units), everything is clipped to it (`PushClip(FSlateClippingZone(DesignerGeometry))`), and the designer's selection comes from the `Selection` argument. Gone with the designer when another tab is in front (not painted). No `Tick`, `CanExtendSelection` or `ExtendSelection` overrides any more.
- **Mouse (fix8):** the diamonds and handles are drawn by `FMotionPathLayer::PaintKeys`, not widgets. `FMotionPathInput : IInputProcessor` (registered by `FSlateApplication::RegisterInputPreProcessor` while any layer exists - `AcquireInput` / `ReleaseInput`, refcounted) hit-tests what each layer drew this frame or the last (`IsOver` = painted recently + `Designer.IsUnderLocation`, `HitTest` = handles first, then diamonds), then checks the designer itself is under the mouse (`LocateWindowUnderMouse` path is the layer's paint window and contains an `SDesignerView`) - so menus, drawers and other windows over it keep their clicks. A left press there is consumed (`Press`), moves while pressed drive `PressMove` (threshold in designer units, then `BeginKeyDrag` / `BeginHandleDrag` + `UpdateDrag`, unchanged), release = `Release` (click picks the key, or the drag ends; a release lost to another window is caught in the processor's `Tick` and ends the drag without a click). Right press + release on the same diamond opens `OpenMarkerMenu(Index, ScreenPosition, OwnerPath)`, pushed over the designer's own widget path. Moves without a press only set the hovered diamond/handle (`SetHover`) and are never consumed. No cursor change on hover (Slate's cursor query would override it); hover is shown by the diamond's highlight.
- **Curved paths (fix5):** `FWidgetTransformKeyframe::PathShape` (`EWidgetKeyPathShape` Linear "Corner" / Smooth / Bezier, DisplayName "Path") + `PathHandleIn` / `PathHandleOut` (relative to the key's Translation). `FWidgetTransformAnim::GetPathHandles` (Smooth: direction = normalize(next - previous), each handle 1/3 of the distance to that neighbour) and `EvaluatePath(Segment, Alpha)` (lerp when both inner handles are zero - identical to before; else cubic Bezier, arc-length reparameterised over 24 steps, straight extrapolation past either end for overshoot). `UWidgetAnimTransformLibrary::Evaluate` uses it for Translation only. Splitting a segment (`SampleKeyframes`) makes the new key Smooth when either side was curved.
- **Whole-track easing (fix5):** `FWidgetTransformAnim::EasingSpan` (`EWidgetKeyEasingSpan` EachSegment / WholeTrack, DisplayName "Easing Across"). WholeTrack: `LocalTime = EvaluateEasedAlpha(Settings, Alpha) * Duration`, no per-segment `TrackEase`, `bExtrapolate` on (as springs do). The panel hides Curve To Next Key for such tracks (`LayerUsesSegmentCurves` / `UsesSegmentCurves`, note `WholeTrackKeyCurveNote`); the motion path places such keys (and spring keys) where the eased progress passes them (`FindEasedPassing`).
- **Editing on the path (fix5):** picked non-Corner keys show two handle grips (`SWidgetAnimMotionPathHandle`); dragging one mirrors the other (keeping its length) unless Alt; Alt-drag a diamond pulls fresh mirrored handles out. Timeline API: `BeginKeyHandleDrag` (transaction "Edit Path Handles") / `UpdateKeyHandleDrag(In, Out)` (sets Bezier, rounds to 0.1) / `EndKeyPositionDrag`; `SetKeyPathShape(Layer, Keys, Shape)` (Bezier keeps the current handles); `SetLayerEasingSpan`. Right-click a diamond: `FMenuBuilder` + `PushMenu` - Path radio (Corner / Smooth / Bezier Handles, for the key and the other picked keys of its track), Smooth / Straight every key, Ease Each Segment / Ease Whole Track. Key time labels sit off the path: along the upward normal of the path's tangent at the key, pushed until the box clears the diamond (`LabelGap`).
- **Constrained widgets:** a widget with a Constraints component is drawn on its path where its constraints put it at each sample (`UWidgetConstraintComponent::PreviewTransform`, a stateless solve over the sampled Render Transform), with its **Constraint tracks'** values at that moment applied for the sample and put back - and a widget with a Constraint track gets a path even without a Transform track (a ball whose Path Position is animated draws its ring). Constraints set While Animated: Follow the Keys take the keyed place as their target, so a pupil's keys are shown inside its eye. See ConstraintsAndPointerEffects.md.
- **Order:** the factory is still registered **first** among the designer extension factories, so other extensions draw over the paths.
- **Settings** (`UWidgetAnimEditorSettings`, category Motion Paths): Show Motion Paths (also the **Motion Path** toggle in the panel's Track Controls pill, icon `Resources/WidgetAnim_MotionPath.svg`), Dots Per Second (30), Path Range (Whole Animation / Around Playhead) + Seconds Around Playhead (0.5), Show Key Times. Palette `NameTBD::Colors::MotionPath`. Tooltip `MotionPathsTooltip`.

## Widget Gizmo (WidgetGizmo v1 + fix1 + fix2)
- **What:** a transform gizmo over every widget selected in the UMG designer - not a widget, nothing to place. It edits the widget's **Render Transform** (Translation, Scale, Shear, Angle) about its **Render Transform Pivot**, and sits on that pivot. Unreal's viewport colors (X red, Y green, ring blue, hovered/dragged yellow), Blender's keys. Files: `NameTBDEditor/Private/WidgetGizmo.h/.cpp`, `WidgetGizmoSettings.h/.cpp`; keying in `SWidgetAnimTimeline` (see Keying).
- **Modes** (one for every designer, not saved; `GizmoMode()` in `WidgetGizmoImpl`):
  - **Move**: X arrow and **Y arrow pointing up** (fix1; along the widget's *parent's* axes - what Translation moves along, not turned with the widget's Angle; drawn along `-AxisY`, the drag still projects on the real +Y step) and a square between them (free; Shift = the axis moved along most). Translation rounded to 0.1.
  - **Scale**: 8 handles on a **frame `FrameGap` (10 px) outside the box as drawn** (fix1: `FTarget::Frame[8]` - each edge pushed out, corners by `FrameGap / sin(angle between edges)`, so a sheared box's frame is 10 px off every edge; clear of the designer's own selection outline and Canvas slot handles). **Corners scale in proportion** (fix1; Shift = free 2-axis), edges one axis (Shift = both in proportion); always **about the pivot**. The drag solves for the true box point (`GetHandleCanvas` returns `Points`, the press offset carries the 10 px). Rounded to 0.001.
  - **Rotate**: a ring about the pivot; every turn counted (unwrapped), swept arc drawn; Shift = steps of Rotation Snap (15). **Rotation Magnet** (fix2): without Shift the angle catches on every multiple of Rotation Magnet (45; 90 = quarter turns only; 0 off) within Rotation Magnet Range (4 deg). Direction flips if the canvas mapping is mirrored.
  - **Shear**: a grip on each frame edge middle. The component (Shear X or Y) is picked at the press as whichever moves the grip along its edge most. Solved in tan(angle) space, clamped to +-89; Shift = steps of Shear Snap (5).
- **Smart guides** (fix2): moving (arrows, square, G Grab following the mouse) and scaling (handles) catch the widget's box edges and middle on the edges and middle of its Slate parent (the panel it is laid out in) and of every visible sibling in its `UPanelWidget` parent, within Smart Guide Distance (6 px); the guides used are drawn magenta (`Palette::Guide`) from the box they come from to the widget. Ctrl = free. Only for an **upright** widget (`IsUpright`: no turn/shear in `BoxToCanvas`); scale snapping also needs the widget's own Angle and Shear at 0 (an edge then sits at pivot + distance x scale on its own axis - one division). Proportional scaling uses whichever axis is nearer its guide for both. Guides gathered once per edit (`GatherSnapLines`: render bounding rects, desktop -> canvas), never from the widgets being edited. Move/Grab translations snapped to a guide are rounded to 0.01 instead of 0.1.
- **Pivot** (every mode): drag the gizmo's middle. The pivot goes to the box point under the mouse and **Translation is compensated** (`CompensatePivot`: `T' = T + (P - P') - A(P - P')`) so the widget doesn't move. Snaps to the 9 box points within Pivot Snap Distance (8 px; Ctrl = free). The pivot is never keyed.
- **Keys / typed values (fix1, Blender-style, `FGizmoLayer::FSession`)**: **G** grab - every selected widget follows the mouse with no button held (a click or Enter sets it, Escape / right click puts it back; X / Y keep it to an axis, drawn as a line across the designer); **S / R / Z** switch to Scale / Rotate / Shear **and** open a session. In a session a number typed sets the value **absolutely**: `R 90 Enter`, `S 1.5 Enter` (both axes), `S X 1.5 Y 1.25 Enter`, `G X 100 Y -20 Enter`, `Z X 10 Enter`. X / Y / Tab pick the axis (Scale typed both ways first carries its value into both); Backspace deletes; minus flips the sign; numpad works. Once anything is typed a Grab stops following the mouse (untyped axes stay at the start). Applied live; Enter / a left click / any other key sets it (the other key then goes on as usual); Escape / right click puts it back. S / R / Z again with nothing typed: back to Move. H hides/shows. A **typing bar** under the chips shows the fields (typed value with a caret, else the current value dimmed) and hints. A session's edit begins on the first character (Grab: at once) and spans every selected widget.
- **Right-click a handle** (fix1): a menu to reset what it edits - Pivot: Reset Pivot to Center (compensated, the widget stays); X arrow: Position X / Position; Y arrow: Position Y / Position; square: Position; Scale grip: Scale (1,1); ring: Rotation 0; Shear grip: Shear (0,0); every menu also Reset Render Transform (all four, pivot kept). Section title says "(keyed at the playhead)" when that channel is keyed. Opened on release over the same handle (`FGizmoInput::RightPressed`).
- **Chips** above the first selected widget: Move G, Scale S, Rotate R, Shear Z, Hide H (key names from the settings), plus an **Auto Key** chip (red, record dot, not clickable) listing the keys whose edits are keyed. **Show Mode Chips** off (fix1): no chips (the typing bar takes their place).
- **Edits (fix1, `FGizmoLayer::FEdit`)**: drags, sessions and resets all go through `BeginEdit(targets, channels, bPivot)` / `SetPose(i, pose, pivot)` / `EndEdit(bCancel)`: one `FScopedTransaction`, template `Modify()`. Each channel goes to a key (see Keying) or onto the template **by the change since the begin** (Translation/Shear/Angle add the difference, Scale multiplies by the ratio - `Rescale`), so a posed widget's template gets the edit, not the posed value; unposed the two are the same. The preview is set to the shown pose at once. End: kept, or (cancel / nothing changed) everything put back and the transaction cancelled. On keep, each template whose transform/pivot changed is marked dirty (`BS_Dirty`) and **`OnObjectPropertyChanged` is broadcast** for `RenderTransform` / `RenderTransformPivot` (ValueSet) - `FWidgetAnimAssetPanelSource::OnObjectPropertyChanged` then restores its poses, copies the edit onto its preview and re-reads the authored state (v1 broadcast nothing).
- **Keying (fix1; fix2 gating)**: while `SWidgetAnimTimeline::CanGizmoKey()` (fix2: **Auto Key** on - `UWidgetAnimEditorSettings::bGizmoAutoKey`, the toggle between Linked Edges and Motion Path in Track Controls - and `IsShownOnScreen()`: the panel and every parent visible up to a shown, unminimized `SWindow` - a closed drawer, a background tab or a Details panel no longer showing it detaches it; before fix2 the Builder's source, which reports `bPosed` whenever its live preview exists, keyed with the panel closed; plus animation open, editable, not dragging, `GetPosedAnimation().bPosed`) the gizmo shows the widget **as posed** (the panel preview's widget - found by name like the motion paths - `GetRenderTransform`) and keys. Timeline API (public): `CanGizmoKey`, `GetGizmoKeyableChannels(PanelWidget)`, `BeginGizmoKeying(Widgets, Channels, OutKeyed)`, `UpdateGizmoKeying(WidgetIndex, StartPose, NewPose)`, `EndGizmoKeying(bCancel)`; channel bits `WidgetGizmoChannel::{Translation, Scale, Shear, Angle, All}` (namespace in `SWidgetAnimTimeline.h`).
  - `FindGizmoKeyTracks`: tracks on that widget (`Source->GetLayerPreviewWidget(i) == PanelWidget`), not value-driven, not hidden, `CanEditKeys`, whose run contains the playhead (+-half a preview frame; inverted tracks mirrored). Rank: Scale track for Scale and Rotate track for Angle = 0, Transform = 1 (all four). Per channel: the lowest-rank track **with a key at the playhead** (Transform: curve key time x TimeScale; value tracks: any point incl. start (point 0 = Start Scale/Angle) and end (End Scale/Angle) at fraction x run, within half a frame); else the lowest-rank track without - it gets one via `AddKey` (value at that moment, as the panel's own Add Key; selects it). A Transform key that Uses Authored Transform is switched off at its current (identity) pose.
  - Writes: Transform key fields by the change (Translation/Shear/Angle add, Scale ratio; rounded 0.01 / 0.0001); Scale track point (Value, ValueY) by ratio; Rotate point Value by difference (`WidgetGizmoKeying::SetPoint`). `NotifyGroupsChanged(Interactive)` per update, `ValueSet` + `RefreshDetails` at the end. Cancel: the layers copied at the begin are put back (keys added go, selection cleared).
  - Not keyed: Slide (a distance along a fixed direction, not a position), Shake/Pulse, value-driven tracks, the pivot. Spring-timed / whole-track-eased Transform tracks are keyed by the same delta, but their pose at the playhead isn't exactly the key's value.
- **Cursor** (fix2): the gizmo's cursor (a drag's, a Grab's CardinalCross, a lit handle's) is also put in `NameTBDDesignerCursor::Override()` (`DesignerCursorOverride.h`), which `FMotionPathLayer::GetDesignerCursor` - the designer widget's `Cursor` attribute, claimed by the motion paths - returns first. Before, only the platform cursor was set and every cursor query Slate made of the designer (e.g. its synthesized moves while the grabbed widget moved under the mouse) answered the arrow: the cursor flickered in Grab. Updated after every input event and Tick; reset when the last gizmo goes.
- **Input** (`FGizmoInput`, registered at index 0, ahead of motion paths; fix2: the event handlers wrap `HandleButtonDown/Move/ButtonUp/KeyDown/TickInput` and update the cursor override after each): left press on a handle/chip consumed; drag after 2 px; Escape / right press mid-drag cancels (both releases swallowed); Shift/Ctrl changes re-evaluate (polled in Tick); a lost release commits. Session routing: while a session exists its keys go to it (unless an `*EditableText*` has focus - then it is set and the key passes); gizmo keys switch session; a left press sets the session (a Grab's click is swallowed, otherwise the click goes on); right press cancels a Grab / typed session. Gizmo keys without a session: only when the designer has focus (or the `SDesignerView` above the painted rect) or the mouse is over it, never in a text field, and only with a usable target. Exact chord match (Ctrl+Z stays Undo). Repaint requests are skipped while the designer paints (`bPainting`).
- **Panels in the designer:** the designer draws a panel (Vertical Box, Canvas Panel...) inside a wrapper of its own - an `SOverlay` of the panel's Slate widget and its dashed outline (`SBorder`, takes no hits). A Render Transform on the panel's own widget moved its children while its box (outline, selection, slot) stayed put. Each paint, `HoistDesignTransform` puts the preview panel's Render Transform (and pivot) on that wrapper and takes it off the panel's own widget; `Place` measures the wrapper (`GetLaidOutWidget`). The wrapper is recognised by shape (`FindDesignWrapper`: an `SOverlay` with exactly the panel's widget and a hit-test-invisible `SBorder`, neither belonging to the panel's or its parent's children); anything else is left alone. Design time only, gizmo targets only (the selected widgets).
- **Hosting:** `FWidgetGizmoExtension::Paint`, one `FGizmoLayer` per designer, factory registered last (draws over other extensions). Up to 8 selected widgets each get a gizmo (sorted by name); locked widgets get none.
- **Settings** (`UWidgetGizmoSettings`, Editor Preferences > Plugins > **Widget Gizmo**, `EditorPerProjectUserSettings`): Enable Widget Gizmo (on), **Show Mode Chips** (on, fix1), Gizmo Size (1), keys **Grab (G, fix1)** / Scale (S) / Rotate (R) / Shear (Z) / Hide Gizmo (H) as `FInputChord`s, Rotation Magnet (45, fix2), Rotation Magnet Range (4, fix2), Rotation Snap (15), Shear Snap (5), Pivot Snap Distance (8), Smart Guides (on, fix2), Smart Guide Distance (6, fix2). Palette `NameTBD::Colors::WidgetGizmo` (fix1 added `Frame`, `FrameGap`, `KeyChip*`, `Typing*`; `Box` removed; fix2 `Guide`).
- **Known overlaps:** the pivot handle sits in the middle of the widget, so the designer's own drag can't start from that ~12 px spot; X / Y / Tab / digits / Enter / Escape belong to an open session (S/R/Z sessions stay open until set, so pressing S then using the arrow keys sets it and the arrows go on to the designer).

## Unverified
- Constrained paths: `FindConstraintComponent` finding the preview's component while sampling; temporarily setting a constraint's channel during a rebuild and putting it back (no other preview reads it meanwhile).
- Panels in the designer: that the designer's wrapper is an `SOverlay` + `SBorder` as described, and which of the two `UWidget::GetCachedWidget()` returns in 5.7 (both cases are handled). A panel moved by a Widget Animation (not the gizmo) in the designer still moves inside its box.
