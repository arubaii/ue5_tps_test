# Diegetic UI (UI in the world)

## What diegetic UI covers (researched for DiegeticUI v2)
- **Taxonomy** (Fagerholt & Lorentzon, "Beyond the HUD", 2009): diegetic (in the fiction and in the 3D space - Dead Space's RIG and holographic inventory, Fallout's Pip-Boy), spatial (in the space, not the fiction - waypoints, outlines), meta (in the fiction, not the space - a speedometer, blood on the screen), non-diegetic (neither - the classic HUD). This feature serves **diegetic** UI, and spatial UI that wants to be drawn in the world.
- **The setups games actually use** (each built from the screen's own settings - Display, Placement, Use, Presence, Updates, Glass; there is no one-click kind):
  - **Wall terminals / computers** the player walks up to and uses (Fallout, Doom 3, Alien: Isolation) - green/amber CRT look, the camera moves in, mouse or gamepad.
  - **Monitors, TVs, consoles** - the picture on a modelled screen's material slot, not a floating quad.
  - **World holograms** (Dead Space stores, sci-fi signage) - additive, scan lines, glitch, turned toward the player.
  - **Projected menus** that keep the game running (Dead Space inventory, map) - in front of the player, used without moving the camera.
  - **Device / equipment displays** (Pip-Boy, Dead Space RIG health spine and weapon ammo counters, Metro's watch) - small displays on a mesh or a socket, redrawn only when the value changes.
  - **Signs, kiosks, room labels** - mostly static.
  - **Glass panels** (sci-fi cockpits and HUD panes) - glass that blurs, bends and tints the world behind (Glass).
  - **Control desks / cockpits** - several screens used together (Focus Group), sharing one data source (Context).
- **Background Blur in the world:** Epic marked it Won't Fix (UE-41001): the scene behind a 3D widget isn't rendered when the widget draws, and Slate's blur renders opaque there. Only a material sampling the scene behind (Scene Color) can blur it - what the glass material does.

## As built (DiegeticUI v1, runtime `NameTBD/Diegetic/`, editor `NameTBDEditor`)
- **What:** UI that lives in the world - terminals, wrist displays, signs, holograms - made from ordinary Widget Blueprints, with the plugin's own systems working on them as on the HUD. Four pieces: **Diegetic Screen** (`UDiegeticScreenComponent`, a `UWidgetComponent`), **Diegetic Interactor** (`UDiegeticInteractorComponent`, a `UWidgetInteractionComponent`), the **Diegetic UI Subsystem** (`UDiegeticUISubsystem`, a tickable world subsystem, Game/PIE worlds only) and **Project Settings > Plugins > Diegetic UI** (`UDiegeticUISettings`). Plus `ADiegeticScreenActor` (drop-in actor: plain root + screen, Physical Size on), `UDiegeticUILibrary` (Blueprint), the **Diegetic Screen Widget** interface (`IDiegeticScreenWidget`, `DiegeticTypes.h`) and **Copy To Project** (v2; was Create Screen Material) in the screen's Details.
- **Editor worlds:** a screen redraws as a plain Widget Component there (`bScheduled` false; the engine's redraws), with its material, look and Glass, and its Background Blur widgets taken over as in game (`CollectBlurWidgetsInEditor`, from `DrawWidgetToRenderTarget` before the draw: no subsystem ticks there); a Mesh Surface only shows in game worlds (in the editor the mesh keeps its slot's material and the screen's own panel isn't drawn - `bRenderInMainPass` / `bRenderInDepthPass` off - else it would sit on the display face and flicker against it). Everything else below is runtime.

### Diegetic Screen (`DiegeticScreenComponent.h`)
- **Sizing:** Draw Size (engine) or **Physical Size** (cm) + **Pixel Density** (px/cm, default 12 -> 160 x 90 cm = 1920 x 1080): `ApplySizing` sets Draw Size and the component's relative Y/Z scale (exact size whatever the pixel rounding; X untouched) in `OnRegister` (before Super, so the window/body are made at that size) and on edits. **Texture** (read-only) shows the render target's pixels and MB (BGRA8, no mips).
- **Redraws:** `ShouldDrawWidget` (engine's checks first - shown, rendered in the last 0.5 s or Tick When Offscreen, Redraw Time, Manually Redraw) then the scheduler's `bDrawScheduled` for this frame. `DrawWidgetToRenderTarget` records the time (`GetRedrawsPerSecond`) and hands Screen Look to the material instance. A redraw also ticks the widget (its Tick, UMG animations) with the real time since the last one; Widget Animations keep their own clock and are only *seen* at the redraw rate.
- **Update Mode** (`FDiegeticUpdateSettings`, `EDiegeticUpdateMode`): **Every Frame** (engine behaviour, outside the budget), **By Distance** (default: Near / Mid / Far rate by camera distance - defaults 500 cm every frame, 2000 cm 20/s, beyond 4/s), **When Changed** (By Distance rates, but only while something changes: a Widget Animation posed something on it (`NoteAnimating`, from `UWidgetAnimationComponent::RuntimeTick` when `bPosedLastTick`), a UMG animation plays (`IsAnyAnimationPlaying`), it is aimed at or used, a pointer button on it, or **Mark Content Changed** - then Settle Time (0.6 s) more; Heartbeat Rate (1/s) whatever happens). **Max Update Distance** (5000 cm: keeps its last frame beyond), **Cull Distance** (0 = off; `SetCullDistance` - only when > 0, so a Rendering Max Draw Distance set by hand stays), **Full Rate While Interacting** (on), **Skip When Facing Away** (one-sided flat screens, every camera behind), **Budget Priority**.
- **Presence** (`FDiegeticPresenceSettings`): Wake Distance from the nearest local pawn (0 = always awake - default), Sleep Margin (hysteresis), While Asleep: **Freeze Last Frame** (default) / **Hide** (`SetHiddenInGame` once the widget has played out; unhidden before waking) / **Keep Updating**; **Play Anim In / Out** (the root widget's Widget Animation Component `PlayIn` / `PlayOut` on wake / sleep transitions, not on the first evaluation). An asleep screen redraws only while its widget animates or for 0.25 s after falling asleep (`WantsRedrawWhileAsleep`), can't be aimed at. Kept awake while in use or by **Set Keep Awake**.
- **Use** (`FDiegeticUseSettings`): **Point And Click** (default), **Focus View**, **Not Usable**; Reach Distance (0 = the interactor's), View Fill, Camera Blend Time, Camera Offset (screen space), Block Pawn Input, Show Mouse Cursor.
- **Glass** (`FDiegeticGlass`) and **Screen Look** (`FDiegeticScreenLook`): see "Materials, glass and looks" below. Handed to the Widget Component's material instance and the Mesh Surface's, only when an instance or a value changed (`LookAppliedTo` / `LookApplied` / `GlassApplied`, compared with `CompareScriptStruct`).
- **Sound** (`FDiegeticSoundSettings`): **Play Sounds In The World** (on): every UI sound of a widget on the screen - `FUISoundPlayer` Play / PlayOneShot / PlayFaded, so buttons, cards, Flow Lists and Sound cues - plays from where that widget is on the screen (`GetWorldLocationOfWidget`: the middle of its drawn box, window space -> `WidgetToWorld`), with the screen's Attenuation asset, or a sphere of Inner Radius (150 cm) fading over Falloff Distance (1500 cm) (`bOverrideAttenuation`). An audio component from `CreateSound2D` with `bAllowSpatialization` turned on (still a UI sound: plays while paused). The place is worked out at request time; a delayed sound plays where its widget was. HUD widgets: unchanged (`PlaySound2D`).
- **State machine inputs** (`Set State Machine Inputs`, on): ScreenAwake, ScreenAimedAt, ScreenInUse (Bool), ScreenDistance (Number, cm from the nearest camera, sent when it moved 5 cm) on the root widget's machines - through what plays them, `UWidgetAnimationComponent::FindWidgetAnimationComponent` (its own Widget Animation Component, or the one its State Machine Component made); never the State Machine Component itself, which can make objects. A machine without the input ignores it. Pushed again when the widget or its window changes: `SyncRegistration` only notes it (`bPushWidgetState`) and the subsystem's tick passes it on (`FlushWidgetState`).
- **Recompiles during PIE** (fix2): nothing touches the widget from `SetWidget` / `InitWidget` (a Blueprint recompile calls them while it replaces the widget), and every call into the widget - machine inputs, the interface, Anim In / Out, `IsAnyAnimationPlaying`, focus - goes through `GetSafeWidget()`: valid, not being destroyed, its class without a newer version (`CLASS_NewerVersionExists`), not during garbage collection, and already built into the window.
- **Interface / events:** `IDiegeticScreenWidget` on the root User Widget: On Screen Wake / Sleep / Aim Changed / Use Changed / **On Screen Back** (return true = handled, stay in use). Component delegates On Screen Wake / Sleep / Aim Changed / Use Begin / Use End.
- **Lookups** (`FindScreenForWidget`, static; `AnyScreensExist` makes everything free with no screen): the outermost User Widget of the widget's outer chain against the screens' root widgets, else a Slate parent walk from it to a screen's `SVirtualWindow` (widgets made at runtime and added to a panel on a screen). Game thread only; kept by `SyncRegistration` (registration, `InitWidget`, `SetWidget`, every scheduler tick) and `Unregister` (removes by value).
- **Map check** (`CheckForErrors`): Space = Screen, no Widget Class, texture over 4096², Receive Hardware Input on with a usable Use Mode, Glass or a Screen Look with Material Engine Default; info when Start Shown is off (nothing shows in game until Set Screen Shown / Open Diegetic Menu).

### Diegetic Interactor (`DiegeticInteractorComponent.h`)
- **Aim** (`UpdateAim`, before the engine's tick, handed over as the **Custom** hit - `InteractionSource = Custom` - with its `Distance` from the pawn, as reach is measured, never from the camera: the Widget Interaction Component holds the hit to Interaction Distance, which behind a third-person camera left only screens within 400 cm of the camera clickable): ray from **Camera** (the player's view point - TPS-safe), **Mouse Cursor**, or **This Component** (forward axis; VR hands). Flat Diegetic Screens by **ray-plane intersection** (no collision needed; one-sided ones only from the front (+X face); inside `[0, CurrentDrawSize]` via `GetLocalHitLocation`), curved ones by `LineTraceComponent`. Reach measured **from the pawn** (Camera / Mouse) - the screen's Reach Distance or Interaction Distance. One `LineTraceSingleByChannel` (Trace Channel; ignoring the pawn and the found screen's own actor) for occlusion, and - with **Aim At Widget Components** - plain Widget Components hit by collision (the engine computes their local hit). The used screen (Focus View) is the only candidate while in use, unlimited reach, no occlusion.
- **After the engine's tick** (`UpdateAimedState`): `GetHoveredWidgetComponent` changes -> `NotifyAimed` on screens, `OnAimedScreenChanged`; the screen's pointer position (`Get2DHitLocation`).
- **Presses:** `PressScreenPointer` / `ReleaseScreenPointer` (Blueprint) count on the screen (`NotePointerButton`: left/right presses, right releases, positions; the screen the press started on hears the release) and forward to `PressPointerKey` / `ReleasePointerKey`. **Click Screen** = enter Focus View on a Focus View screen not in use, else the left button. Back -> `OnScreenBack`, else `EndUsing`. Accept (in use) -> `Enter` key down/up (Slate's Accept) to the virtual user's focus. Navigate -> D-pad key press+release (Slate navigation moves the virtual user's focus), held = repeat after 0.4 s every 0.12 s. Scroll -> `ScrollWheel` (wheel: notches; stick: Stick Scroll Speed x tilt x delta).
- **Input:** Enhanced Input when the player has it (`UEnhancedPlayerInput`): an `UEnhancedInputComponent` of its own pushed on the controller's stack, and two mapping contexts at **Input Priority** (100): **Aim** (Click, Secondary Click, Scroll) only while over something interactable / focusable on a widget component, at a Focus View screen, or holding a click; **Use** (Back, Accept, Navigate x4, Scroll Stick; priority + 1) while a screen is in use - their actions consume their keys (so a click on a screen button doesn't fire a weapon; Escape doesn't open the pause menu while in use). `bIgnoreAllPressedKeysUntilRelease` (Enhanced Input's default) stops a held trigger swept onto a button from clicking it. Project overrides: Aim Input / Use Input + the actions (Advanced). Unset: made once (transient) from **Default Keys** (settings): Click LMB / Gamepad Left Face; Secondary RMB; Scroll Mouse Wheel Axis; Scroll Stick Gamepad Right Y (dead zone); Back Escape / Backspace (Escape stops PIE in the editor) / Gamepad Right Face; Accept Gamepad Bottom Face / Enter; Navigate D-pad / left stick directions / arrows. Old input system: the Default Keys polled (`WasInputKeyJustPressed`) while there is something to act on (can't consume them).
- **Focus View** (`BeginUsing` / `EndUsing`): releases held pointers; Block Pawn Input (`SetIgnoreMoveInput` / `SetIgnoreLookInput`, balanced); Show Mouse Cursor (`bShowMouseCursor`, `FInputModeGameAndUI` without cursor hiding or lock; restored to the previous cursor state, `FInputModeGameOnly` when it was hidden); a transient `ACameraActor` attached to the screen at `ComputeFocusViewTransform` (centre + face x distance so the screen fills View Fill of the view across or up, from the player's FOV and viewport aspect; + Camera Offset), `SetViewTargetWithBlend` (cubic) and back to the previous view target (pawn when none), destroyed after the blend; gamepad focus to the root widget's `GetDesiredFocusWidget` or the first widget that supports keyboard focus (`SetFocus`). In use with the cursor shown the aim follows the cursor; without it (gamepad) there is no pointer, focus drives it. `GetUsedScreen`, `OnUseBegin` / `OnUseEnd`, the screen's `SetUserInteractor`.
- **Auto add** (subsystem, Auto Add Interactor on): each local player's pawn, once per new pawn, unless the pawn or controller already has a `UWidgetInteractionComponent`: transient, Interaction Distance from settings (400 cm), **Virtual User Index = local player index** (split-screen users hover and focus apart; set before registering, when the virtual user is made), attached to the pawn's root.

### Plugin systems on a screen
- **Widget Animation / state machine pointer inputs** (`WidgetAnimInput.h`): `FWidgetAnimInputContext` carries `bWorldPointer` + `WidgetAnimInput::FWorldPointer` (surface, position in the screen's window space, over, left/right down, press/release counts). `WidgetAnimInput::ReadPointer` fills it at both context builders (`WidgetAnimLibrary.cpp` value inputs, `WidgetAnimStateMachineRuntime.cpp` machine inputs) through a resolver the module registers at startup (`SetWorldPointerResolver` -> `FindScreenForWidget` + `GetWorldPointer`); desktop otherwise, as before. Pointer Position, Hover/Press/Focus and Drag read it (`IsButtonDown`, `IsPointUnder(Context, ...)` = the surface's `GetHitWidgetPath`, hover gated on `bOver` so a left pointer hovers nothing); the machines' Double Clicked / Right Clicked read its counts (no double-clicks are made in the world). Hover itself is still Slate's (`IsHovered` - per-user hover covers the virtual user). Accept / Back / key pulses: the interactor's key events go through `ProcessKeyDownEvent`, so Slate's counter sees them already.
- **Sounds:** see Sound above. **Focus-based** inputs (Focused, Accept) work through the virtual user's focus.

### Subsystem (`DiegeticUISubsystem.h`)
- Each tick (after the world's; real time; ticks while paused): drops dead entries, gathers local players' view points (`GetPlayerViewPoint`) and pawn locations, adds interactors, then per screen: `SyncRegistration`, distances (`Bounds.ComputeSquaredDistanceFromBoxToPoint`), any camera in front, `SetMeasurements`, `UpdatePresence`, then the schedule for the next frame: Every Frame and interacting screens always (not counted); the rest skipped when frozen / past Max Update Distance / facing away / When Changed with nothing changing / not yet due (half a frame of slack) / not rendered in the last 0.5 s; candidates sorted by Budget Priority then overdue ratio, the first **Max Redraws Per Frame** (6; `NameTBD.Diegetic.Budget` overrides; 0 = no limit) scheduled.
- `stat NameTBDDiegetic` (Schedule Screens, Screens, Redraws Scheduled, Waiting On Budget, Asleep), `NameTBD.Diegetic.Debug 1` (mode, camera distance, redraws/s, asleep/aimed/in use over each screen; green drawn lately, yellow waiting, grey asleep), `NameTBD.Diegetic.Freeze 1`.

## Materials, glass, looks, display (v2; core rendering reworked in v3)

### Materials (`EDiegeticMaterialMode`, `EDiegeticMaterialVariant`, `DiegeticScreenMaterial.*`)
- **Material** (`MaterialMode`): **Automatic** (new screens) = the plugin's own materials, picked per variant (`GetWantedVariant`): **Glass** when Glass is on or the widget holds Background Blur widgets (and Background Blur Widgets is on), else **Opaque** for Blend Mode Opaque, else **Panel** (Masked and Transparent alike). A see-through widget alone never picks Glass. **Engine Default** = the Widget Component's own (a plugin material left in Materials is removed). **Custom** = Materials element 0, Glass and look parameters still handed over. Screens saved before v2 load as Engine Default (custom version `DiegeticScreenVer` 1, `PostLoad`), so nothing changes under them.
- **Made by the editor** (`DiegeticScreenMaterial::Get` / `MakeMissing`): `M_DiegeticScreen`, `_Glass`, `_Opaque` in `/NameTBD/Diegetic` (the plugin's Content, when the plugin is the project's and writable; else `/Game/NameTBD/Diegetic`, the settings' paths updated and a warning to cook it). Made (v2_fix1) once the editor is idle after a screen first asks - a 0.25 s ticker waiting while anything is dragged (making, compiling and saving assets mid drag-drop is unsafe), a transaction is open, a slow task runs, a game plays in the editor (`PlayWorld`, `IsPlaySessionInProgress`, simulating, `GIsPlayInEditorWorld`), Blueprints are reinstanced (`GIsReinstancing`), packages load or garbage is collected (`CanMakeNow`, checked again by `MakeMissing` itself - a rebuild during a Widget Blueprint recompile in PIE stopped on an engine check); each variant at most once a session (`bMadeThisSession` - a failure is logged, never retried in a loop); compiled as an edit is (`PreEditChange` / `PostEditChange`, shaders in the background, no blocking slow task); saved straight to disk (`UPackage::SavePackage`, no dialogs or source-control prompts; a read-only file is warned about); then every registered screen refreshed (`RefreshMaterial`). The builder lays nodes out in columns 0-8 (`FBuilder::NumColumns`, checked): its row counters once held only 8, and the output masks in column 8 overran the stack, which the security cookie ends at once (0xc0000409, no crash reporter or log) - the editor's "silent freeze" on placing the first screen. Rebuilt in place when their `DiegeticMaterialVersion` parameter node (read off the graph, not the compiled parameter data, which lags a fresh build) is older than the builder's (4). Until made, screens draw with the engine's material. Screens ask on every registration (a dragged actor re-registers every frame), so the editor only finds loaded objects then; the disk is looked at once per variant (`bSearchedMissing`), and the provider never falls back to loading by path. A packaged game loads them by the settings' paths (`UDiegeticUISettings::ScreenMaterial` / `GlassScreenMaterial` / `OpaqueScreenMaterial`, warning once when missing); the plugin's `Config/DefaultGame.ini` always cooks `/NameTBD/Diegetic`, and screens saved in levels reference them through Materials too.
- **Core rendering** (every variant): surface, unlit, emissive x (1 / Eye Adaptation) by **IgnoreSceneExposure** (1 = auto exposure undone), **Responsive AA** (not on Glass), no vertex fog. The translucent variants (Panel, Glass):
  - **AlphaComposite** (premultiplied - Slate draws into the transparent-black render target premultiplied; the engine's Translucent widget materials multiply by alpha twice, which darkens soft edges). A widget's opacity (its alpha, Render Opacity, the component's Tint alpha) is only opacity: the world shows through plainly.
  - **Output Depth and Velocity** (`bOutputTranslucentVelocity`), threshold the **Opacity Mask Clip Value 0.9** (`SolidOpacity`): pixels at least 0.9 opaque write depth and motion vectors, so the world's particles and other translucency behind a screen's solid parts stay behind them whatever order translucency is sorted in, depth of field treats the screen at its own distance, and TSR / TAA move its picture with the screen instead of with the world behind it (no smearing over a moving background). Fainter parts are ordinary translucency (sorted by distance, blended over what is behind).
  - **Before DOF** (`MTP_BeforeDOF`): the pass most translucency (particles) is drawn in and Scene Color is read in - so screens sort with particles instead of being composited over them from another pass.
  - Two-sided with the back face hidden in the graph (`TwoSidedSign`) unless the screen is Two Sided (`ShowBackFace`), so one material serves both. The tonemapper still applies (see Still open).
- **Opaque** variant: Blend Mode Opaque; depth from the base pass (one-sided).
- Every variant is flagged Used With Skeletal Mesh (a Mesh Surface on a skeletal mesh in a cooked game).

### Glass (`FDiegeticGlass`, `EDiegeticGlassPreset`; glass variant)
- The screen as a pane of glass with the widget drawn on it: under the widget's see-through parts (`Color += Through * (1 - Alpha) * Mask`, `Alpha += (1 - Alpha) * Mask`) the world behind as seen through the glass. Lowering the widget's opacity shows more of the glass; with **No Glass** (default) the world shows plainly.
- **Presets** (`MakePreset`; picking one keeps Corner Radius and Background Blur Widgets - the pane's shape and the widget's, not the glass's look; `SetGlassPreset`, `SetGlass`): **No Glass**, **Clear** (bend 8, split 1, sheen, faint rim), **Frosted** (blur 20, frost 1.5, cool tint), **Heavy Frost** (blur 40, frost 3), **Smoked** (dark tint, blur 4, sheen), **Sci-Fi Pane** (blur 8, bend 14, split 3, cyan tint, glowing cyan rim), **Custom**.
- **Values** (widget pixels, so the same at any Draw Size / Pixel Density; material parameters `Glass*`): Blur, Frost (static per-1.5-px scatter of where the world is taken from), Refraction + Bevel Width (the bevel's bend: the world from just outside the pane drawn in along the rim, x bevel²), Ripple (two sine octaves across the pane, slowly moving), Chromatic Aberration (red / blue taken from either side, growing from the middle to the edges), Tint (multiplies what is let through, by its alpha), Brightness, Sheen (x (1 + 2 x sheen x grazing²)), Edge Highlight (rim light, bevel⁶ + 0.15 bevel², exposure-fixed like the widget), Corner Radius (rounded pane; outside, the widget alone). Glass off hands a neutral pane (`GlassPane` 0), so Background Blur widgets alone only blur.
- **Graph** (custom nodes, each beginning with the widget position code - `At`, `Span`, and `ToScreen`, the inverse of `ddx`/`ddy` of the widget-pixel position, so blur and bend happen in the pane's plane):
  - **Glass Area** (float4): mask (the pane's rounded-rectangle signed distance, smoothed over the screen pixel outside it; plus each Background Blur region, smoothed over a screen pixel), blur radius (widget px: the pane's, or a region's where larger), bevel (1 at the rim, 0 a Bevel Width in), signed distance.
  - **Glass Bend** (float4): bend (bevel along the rounded rectangle's outward gradient + ripple + frost) and the colour split, in the view's UV (`ToScreen` / View Size), at most 0.1 / 0.03 of the view.
  - **Glass Frame** (float4): the blur's 2 x 2 spread (unit disk -> view UV), turned per pixel and per frame by interleaved gradient noise (`PixelPosition` + 5.588 x frame, frame = Time x 60 mod 64), at most 8% of the view.
  - **24 taps** (8 per channel, Vogel disk turned 120° per channel, Gaussian weights exp(-2r²)): Glass Tap custom nodes (`ViewportUV + Bend.xy + Bend.zw x side + Frame x disk`, clamped inside the view) -> Scene Color (Coordinates, viewport UV) -> **Glass Average** (each channel its own taps). The per-pixel turn makes temporal AA resolve a smooth blur (a fixed pattern shows the world behind as a ring of ghost copies); the glass has no Responsive AA so the history is kept.
- **Background Blur widgets** (`CollectBlurWidgets`, from `FlushWidgetState` in game, from the redraw in the editor, when the widget changes and every 2 s): every `UBackgroundBlur` in the widget and nested User Widgets; their own drawing turned off (`SetBlurStrength(0)`; the strength kept, given back when the widget leaves the screen, Background Blur Widgets is turned off, or the screen unregisters, and taken again if Blueprint sets it); each redraw their drawn box (`GetRenderBoundingRect`, window = widget pixels), corner radius (`CornerRadius.X`, by reflection) and Blur Strength x 2 (pixels) go to BlurRegion*/BlurShape* (only what changed). Up to 8. Pure blur (no bend); the pane's tint etc. apply only with Glass on.

### Screen Look (`FDiegeticScreenLook`, `EDiegeticLookPreset`) - sample looks
- Sample looks of the plugin's material for testing (a game's own look - a hologram, a CRT - is its own material, Material Custom): Preset Clean, Terminal (Green), Terminal (Amber), Hologram, LCD Panel, Custom (`MakePreset`; picking one in the Details or `SetLookPreset` sets the values). Values: Brightness, IgnoreSceneExposure, PhosphorColor + Monochrome, Glow + GlowRadius (16 taps, widget pixels), ScanlineIntensity / Count / Speed, RollingBar, Curvature, ChromaticAberration, Vignette, Flicker (24 Hz), Noise, PixelGrid (RGB sub-pixel stripes per widget pixel), Hologram: Additive (opacity scaled down - AlphaComposite with low opacity adds light; no depth written), EdgeFade (camera vector . vertex normal), Glitch (rows jump). Pixel Grid fades out below 4 screen pixels per widget pixel (gone at 1.5) and scan lines fade to their average past half a line per screen pixel (no moiré on small or distant screens). Set by the screen: ScreenPixels (Draw Size), ShowBackFace, UVRegion (Mesh Surface), BlurRegion0..7 / BlurShape0..7 / BlurRegionCount.
- **Copy To Project** (the Details' Screen Material row, `DiegeticScreenDetails.*`): duplicates the variant the screen is drawn with into `/Game/Diegetic`, sets Material Custom and Materials[0] through the Details handles (one transaction) - the starting point for a game's own screen material.

### Display and placement (`FDiegeticDisplaySettings`, `FDiegeticPlacementSettings`)
- **Mesh Surface** (game worlds only - the editor's mesh keeps its material, so no transient material instance is saved with the level): a `UMaterialInstanceDynamic` of the screen's material on the mesh's slot (by name, else 0; the slot's material given back on tear-down), with SlateUI (the render target - set again whenever the Widget Component remakes it), TintColorAndOpacity, OpacityFromTexture and UVRegion (UV Min/Max of channel 0). The screen's own panel: not drawn (`bRenderInMainPass` / `bRenderInDepthPass` off), no collision, Tick When Offscreen, flat. The scheduler measures and checks visibility on the mesh (`GetDisplayPrimitive`), Focus View and sounds use the mesh's bounds (`GetDisplayCenter` / `GetDisplayWorldSize`, measured along the screen component's Y / Z - point its X out of the display face).
  - **Keep Mesh Material** (`bKeepMeshMaterial`, off): the screen's instance goes on the mesh's **Overlay Material** (`SetOverlayMaterial`; the overlay it had put back on tear-down) instead of a slot: the mesh keeps every material, and the screen covers only UV Region (outside it the screen material has no colour, opacity or depth; where the widget is see-through the mesh's material shows). Slot None = any face whose UVs fall in UV Region; a named slot only restricts clicking to that slot's faces (its own material, not the screen's).
  - **Clicking it** (`TraceMeshSurface`): the mesh's complex collision with face index -> the face's material must be the screen's -> `UGameplayStatics::FindCollisionUV` (Project Settings > Physics > Support UV From Hit Results; map check warns) -> UV Region -> widget pixels -> the same place on the undrawn panel (`WidgetToWorld`), handed to the engine's interaction as the hit.
- **Placement** (subsystem tick, first local player's view, awake screens only; made Movable when needed): **Face Camera**, **Face Camera (Upright)** (+X toward the camera, yaw only), **In Front Of Player** (Follow Distance, Follow Offset right/up, Follow Lag = exponential ease of location and rotation, Keep Upright; snaps on the first frame and after being hidden).
- **Shown / hidden** (`SetScreenShown`, `bStartShown`): hidden = asleep with Hide whatever its Presence (plays out, then `SetHiddenInGame`), stops whoever uses it. `UDiegeticUILibrary::OpenDiegeticMenu(Player, Screen)` shows it and begins use, and hides it again when use ends (Back) - `SetHideWhenUseEnds`; `CloseDiegeticMenu`.

### Use, context, terminal
- **Focus View** gained **Move Camera** (off: input goes to the screen, the camera stays - projected menus, raised devices) and **Focus Group**: screens on one actor with the same group are framed together (the box of all their corners on the used screen's plane, at the frontmost depth) and all of them can be pointed at while one is in use (`GetFocusGroup`).
- **Context** (`SetScreenContext` / `GetScreenContext`: set, else Context Actor (instance-editable), else the owner): the widget hears it through `IDiegeticScreenWidget::OnScreenContextChanged` (when set, and as a widget comes on); `GetDiegeticScreenContext` / `GetDiegeticScreenOwner` from inside the widget - an ammo counter finds its weapon with no wiring.
- **Terminal Text** (`UDiegeticTerminalText`, a `UTextBlock`, palette NameTBD): Type Line / Type Lines (queued, Characters Per Second, Line Pause), Print Line, Finish Typing, Clear Terminal, Max Lines (older scroll off), a blinking Caret (lit while typing), Type Sound every Sound Interval characters (through `FUISoundPlayer`, so from the screen), On Line Typed / On Typing Finished; its own Text typed out when shown (Type Text When Shown). A core ticker only while typing or blinking; each change marks its screen changed (When Changed screens). Defaults to phosphor green; the font is the user's to make monospaced.

### Decisions made without asking
- Built on the engine's Widget Component / Widget Interaction Component (subclasses), not a render path of its own: every engine feature (cylinder geometry, invalidation, blend modes, Window Visibility) keeps working, and a screen is a drop-in for a Widget Component.
- Redraw throttling defaults on (By Distance, budget 6) - a new type, so no old behaviour to keep; Every Frame is one setting away. Presence defaults off (Wake Distance 0).
- Interactors added on their own by default (settings switch), never next to an existing Widget Interaction Component.
- Default Click keys are LMB and the gamepad's left face button (the bottom one is commonly jump); the Aim context is only added over something clickable, so the game keeps LMB elsewhere.
- Info Cards are not moved into screens (see Still open): they still open on the HUD.
- (v2) Material Automatic is the default for new screens; screens saved before keep the engine's material (custom version), per the rule that new fields keep old behaviour.
- (v3) No Quick Setup: a screen is set up from its own settings; the fundamental setup tools are Glass presets (and the sample Screen Looks). Saved Quick Setup values are dropped on load (the settings it had set are saved on their own and stay).
- (v3) Glass is its own struct and effect, never implied by a see-through widget; Screen Look lost Background Blur / Glass Tint / Blur Brightness and the Frosted Glass preset (`EnumRedirects` loads a saved Frosted Glass look as Clean). Screens saved with a Frosted Glass look need a Glass preset picked again - no migration (the feature was days old).
- (v3) Depth threshold 0.9: a screen's solid parts hide translucency behind them; a half-transparent pane stays ordinary translucency (blended, sorted) rather than hiding particles behind it completely.
- (v3) Every translucent screen in the Before DOF pass with depth written: depth of field blurs a screen at its own distance (as the world at that distance), which a screen used to escape (After DOF).
- (v3) Blur by 24 temporally turned taps rather than more fixed ones: smooth under TSR / TAA; noisy without temporal AA (see Still open).
- (v2) The plugin's materials are generated by the editor, not shipped as .uasset in the patch (a patch can't carry them); they go into the plugin's Content so they ship with it.
- (v2) Glass is a separate material (24 extra scene samples per pixel only where it is used).
- (v2) Background Blur widgets keep their Blueprint API: their Blur Strength is read and their own drawing turned off on screens only.
- (v2) Terminal Text doesn't force a monospaced font (no engine font asset can be relied on in every install).
- Runtime debug colours live in `DiegeticUISubsystem.cpp` (the runtime module can't use `NameTBDColors.h`).

### Still open (diegetic UI)
- **Info Cards on a screen:** an Info Card Anchor on a Diegetic Screen opens its card on the HUD, placed by viewport maths from the anchor's window-space geometry - only To Viewport placement is right. Wanted: a popup layer in the screen's window (`UpdateWidget` override wrapping the root in an overlay) and the card's placement maths given the screen's window instead of the viewport.
- **Flow List** magnify-by-pointer (`SFlowList`) still reads the desktop cursor on a screen.
- Resolution LOD (a smaller render target far away) - the engine's Widget Component has no render scale; would need `UpdateRenderTarget` overrides.
- Double clicks in the world (the interaction component makes none); touch / multiple pointers per interactor.
- Typing into a text box on a screen: the interactor forwards no keyboard characters (`SendKeyChar`) yet.
- (v2) The tonemapper still shapes the screen's colours (whites a little grey, saturated colours shifted). Exact UMG colours need the Post Process Volume's Tone Curve Amount 0 (scene-wide); a per-material inverse tone curve was left out.
- (v2) Background blur over the widget's own content (a panel blurring a picture behind it on the same screen) - only the world behind is blurred.
- (v3) Blur quality: 24 taps turned per pixel and frame - smooth only with temporal anti-aliasing (TSR / TAA); without it (FXAA, none) the glass is grainy. A separable blur would need a render target of the scene.
- Keep Mesh Material shows the screen on every section of the mesh whose UVs fall in UV Region (the overlay covers the whole mesh); give the screen area its own UV island.
- (v3) Translucency behind glass (particles, other screens) isn't seen through it: Scene Color is the opaque scene, and the glass's depth hides what is drawn after it there. The engine's Refraction pin (distortion pass, which does see translucency) can bend but not blur.
- (v3) Parts of a screen fainter than 0.9 opacity are sorted with other translucency by distance (bounds origin): a large particle system whose bounds' middle is nearer than the screen can still draw over those parts. Blend Mode Opaque, or the component's Translucency Sort Priority, settle it for a given screen.
- (v2) Body-attached devices raised into view (Pip-Boy): the screen and mesh attach to a socket as any component does; the raise animation and camera are the game's.
- (v2) Projected world markers / floor locator lines (Dead Space's locator) - VFX / decals, not widgets.
- (v2) A widget's MVVM view model set from the screen's Context automatically.
- The Aim context comes in only over something interactable or focusable: the mouse wheel over a Scroll Box with nothing clickable under the aim still reaches the game.
- A designer preview at physical size, and a level-editor gizmo for Physical Size.
- Cylinder screens: Focus View frames the chord; `WidgetToWorld` (sounds, Get Diegetic Widget World Location) uses the chord plane.
