# Shapes

## Shapes: outline materials and the Rectangle (Buttons v1)
- **Outline materials:** `FWidgetShapePaint` has **Image Mapping** (`EWidgetShapeImageMapping`: Stretch Over Shape / **Along Outline**) and **Image Tile Length**, shown only for an Image paint. Along Outline (strokes only; hidden on the Fill by `FWidgetShapeDetails`): U runs along the outline (0..1 once round each contour, or one per Tile Length px), V across the stroke (0 inside edge, 1 outside). Dashes and Trim Path keep their place on it.
  - Geometry: `FWidgetShapeMeshVertex` carries `Along` (distance, across) and `OutlineLength`; `FStrokeBuilder` fills them (sections carry `Along`; `AcrossAt`; round caps; a closed run ends on a copy of its first section one outline further, so U never runs back across the last edge). `TrimRun` / `DashRun` report where each piece starts. `CutAlong` lerps them. `FWidgetShapePaint::GetOutlineUV` maps them; used by `SWidgetShape::PaintMesh` (stroke only) and `SFlowListScrollBar::PaintMesh` (scroll bar lines too).
  - Blueprint: `SetStrokeMaterial`, `SetFillMaterial`, `GetDynamicStrokeMaterial`, `GetDynamicFillMaterial`. `GetImagePaint()` = the stroke's paint when it is drawn with an image, else the fill's (what a Design Target's texture/material channels act on).
  - `UShapeWidget::SetExternalPainter`: another Slate widget repainted by `InvalidateShape` (the Context Menu Button's Background Shape).
- **Material paint** (`EWidgetShapePaintType::Material`, appended - asked for by name): **Material** + **Material Parameters** (`TArray<FWidgetMaterialParameter>`, EditFixedSize, listed from the material by `WidgetMaterialParameters::SyncFromMaterial` - scalars, vectors, textures in the material's order, each keeping its value by name and kind, new ones the material's default - as the Context Menu Button's Design Target lists them, textures too). Listed in `UShapeWidget::PostEditChangeProperty` (preview and the Widget Blueprint's own widget via `WidgetEditorHooks::FindDesignerTemplate`), `UWidgetCurvePresetAsset` and `UAdvancedProgressBar` likewise. Drawn by `SWidgetShape::PaintMesh` through `FWidgetEffectMaterials::GetMaterialBrush` (one dynamic instance per shape and part: key 0 fill, 1 stroke; parameters re-applied only when their hash changes), laid over the box or Along Outline (Image Mapping / Tile Length apply to it), tinted by Color, and handed live values: **ShapeSize** (box width, height), **OutlineLength** (first contour), **TrimStart**, **TrimEnd**. Blueprint: `SetPaintMaterial(bStroke, Material)` (lists the parameters, turns the part on), `SetPaintScalarParameter` / `SetPaintColorParameter` / `SetPaintTextureParameter` (set or add in the list), `GetDynamicStrokeMaterial` / `GetDynamicFillMaterial` (the instance the shape draws with, once drawn). `DrawsMaterial()`; `MapsAlongOutline()` includes it. Elsewhere a shape paint is drawn (`PaintMeshWithPaint` without a material cache: Glass tint, Flip Card, Flow List scroll bar) a Material paint shows its Color.
- **SVG paint:** an Image paint has **Image Source** (`EWidgetImageSource`, default Texture 2D: the Image brush, as before) and **SVG** (shown for Image Source SVG; the brush is then hidden and ignored). `DrawsSVG()` / `DrawsBrush()`. `SWidgetShape::PaintMesh` takes the paint's `FWidgetSVGBrush` (`FillSVG` / `StrokeSVG`) and draws the SVG at the size of the shape's box on screen (`Frame.Size` through the render transform), stretched over the box or laid Along Outline like a texture, tinted by the paint's Color; the mesh isn't painted until the first drawing is ready. Design Target texture / material channels and `SetFill/StrokeMaterial` set Image Source back to Texture 2D. See SVG.md.
- **Rectangle** (`URectangleShape`, `ShapeWidgets.h`): Corner Rounding (px, held to what fits), **Fully Rounded** (pill), Individual Corners + Corner Radii (X TL, Y TR, Z BR, W BL). Shape value Corner Rounding. "Pill" added to a Custom Shape's Start From.

## Shape Box corners
- **Chamfer with one leg:** a Chamfer corner's leg left at 0 (or below) follows the other (`ShapeBoxPrivate::GetChamferLegs`), so X alone cuts a 45-degree corner X along each edge; it used to need both legs above 0, and X did nothing until Y was set (on a Context Menu Button's shape and every other Shape Box alike). Bevel is unchanged (X alone leans a side). Tooltips and the Key Values description say so.

## Shapes hold a child (Shapes v1)
- **What:** every shape (`UShapeWidget`: Ellipse, Rectangle, Triangle, Star, N-gon, Custom Shape) is a **`UContentWidget`** now and holds one widget drawn over it, as a Border does - a star button's label, a badge's count, an icon in a circle; no Overlay needed. The split stays: **shapes = vector background with content on top; Shape Box = bending/warping the content itself.**
- **Slate:** `SWidgetShape : SCompoundWidget` (was `SLeafWidget`): paints the fill/stroke meshes exactly as before (layers LayerId, LayerId+1), then the hit cells (below), then the child via `SCompoundWidget::OnPaint` at `MaxLayer + 1`. `OnArrangeChildren` places the child in the **Content Area** (`GetContentArea`), then the slot's padding and alignment (`AlignAxis`, mirrored right-to-left). `ComputeDesiredSize`: `DesiredSize` when there is no child (or it is Collapsed), or Size To Content is off - so a shape without a child reports exactly what it did; else `ComputeSizeForContent`. Both the area and the size are cached by hash (mesh hash + size + content aspect). Arg **`PaintOnly`** (the Context Menu Button's Background Shape painter, `SContextMenuSlateButton::SetBackgroundShape`): no content, no hit cells, Desired Size. **`SetUnfilledBrush`**: while the shape's Fill is off, its inside is painted with that brush instead (Image paint over the shape's box when it has a resource, its tint as a Color paint otherwise); the fill mesh is then built (hash includes it) and cut for the paint actually used - the Context Menu Button's own brush inside an unfilled Shape Style.
- **Slot:** `UShapeWidgetSlot : UPanelSlot` ("Shape Slot"): **Padding**, **Horizontal / Vertical Alignment** (default **Center / Center**, padding 0), setters; `BuildSlot(SWidgetShape)` pushes content + layout (UBorderSlot pattern). `UShapeWidget::GetSlotClass / OnSlotAdded / OnSlotRemoved / RebuildWidget` build it (a plain `UPanelSlot` still works, without layout).
- **New settings on the shape** (category **Content**):
  - **Content Area** (`EWidgetShapeContentArea`): **Bounds** (the box, as a Border), **Inside Stroke** (the box less the stroke's inner width - `GetInnerStrokeWidth`: all of it Inside, half Center, none Outside), **Inscribed** (default: the largest rectangle inside the outline and its stroke, at the content's aspect - padding included; the widget's aspect when the child asks for nothing). Follows Fit, Shape Scale and Shape Rotation (it is computed on the outline built through `MakeFrame`).
  - **Size To Content** (`bSizeToContent`, default on): with a child, the shape asks for the size that gives the child its desired size in the Content Area (Bounds: content; Inside Stroke: + 2 x inner stroke; Inscribed: up to 6 passes of "grow evenly by what is missing" - an Inscribed circle round text ends ~1.41x the text). Grows evenly, so the shape takes the content's proportions.
  - **Hit Test Outline** (`bHitTestOutline`, default off): only the outline's inside is hovered/clicked. At runtime only (never in the designer): the UMG widget routes its visibility through the Slate shape (`SyncShapeVisibility` -> `SWidgetShape::SetRequestedVisibility`, the Shape Box pattern) - Visible becomes **Self Hit Test Invisible** and the fill is tiled with invisible `SWidgetShapeHitCell`s (leaf widgets painted with the shape as paint parent, so the bubble path is cell -> shape -> its parents), built with the mesh from `WidgetShapeGeometry::BuildFillRects` (rows >= 2 units, <= 96 rows, rows with the same span merged: a rectangle is 1 cell, a circle ~45). Cells are painted before the child, so a button inside is hit first. While routed, a Blueprint binding on Visibility is replaced by the property's value (as on Shape Box) - only when Hit Test Outline is on.
  - Blueprint: `SetContentArea`, `SetSizeToContent`, `SetHitTestOutline`, `GetContentAreaRect` (the area as last arranged).
- **Geometry** (`WidgetShapeGeometry`): **`FindInscribedRect(Outline, Aspect, Margin, OutRect)`** - grows rectangles of one aspect about candidate centers (box middle, area centroid, a 3x3 grid) by bisection until an edge touches them (`SegmentTouchesBox`, Liang-Barsky), keeps the best, then hill-climbs 8 ways with halving steps. A rectangle no edge touches with its middle on the fill is wholly inside, so holes (a ring) are kept out. Checked outside the engine: circle d100 -> 70.71 square (exact), triangle -> the optimal 50 square at the base, ring -> fits in the band. **`BuildFillRects`** as above. **`CutAtLevel(Mesh, Level, ValueOf)`**: the cut `CutForGradient` makes at a stop, along any linear function of position - the effect widgets' exact progress gradients and moving bands (EffectWidgets.md).
- **Kept out of Looks, Shape tracks, Flow List item looks and presets:** `UShapeWidget::IsContentProperty` (Content Area, Size To Content, Hit Test Outline), skipped by `WidgetShapeAnimation::GetProperties` and `WidgetShapePresets::GetPresetProperties`, as Desired Size is. `Slots` (UPanelWidget's) is never gathered: those filters keep only properties owned by `UShapeWidget` subclasses. So existing Look / Shape key bags keep their layout.
- `UShapeWidget` now has an `FObjectInitializer` constructor (default argument), as `UContentWidget` requires. `InvalidateShape` invalidates Layout (not just Paint) when the shape sizes to a child.
- **Not done (follow-up):** **Clip To Shape** (mask the child to the outline). Slate clips only to rectangles/quads, so it needs an offscreen render like Shape Box's warped path (virtual window, render target, input mapped back) - opt-in, cost only when on. Deferred rather than half-built.


## Curve (`Widgets/Shapes/CurveShape.h/.cpp`, math in `Widgets/Shapes/CurveFitting.h/.cpp`)
- **What:** `UCurveShape` ("Curve", palette NameTBD) - a line of your own: a swoosh under a heading, an arrow pointing at a button, a divider, a wave, a tutorial path, a sparkline, a signature drawn live. A **`UCustomShape` subclass**, so the canvas path editor (Edit Shape, Pen, Pencil, drag, Shift-click / double-click to add, Delete), the shape Preset row (`.wshape` files), Start From, Fit / Flip, Trim Path, dashes, gradients, Along Outline materials, Looks and Shape tracks all work on it unchanged. Defaults for a line: Fill off, Stroke on (4 px, Round cap and join, white), Desired Size 200 x 80, Content Area Bounds, Self Hit Test Invisible, the Wave template.
- **Smoothing** (`EWidgetCurveSmoothing`, unchanged): Smooth Through Points (default), Handles As Drawn (the Custom Shape's own handles), Straight Lines. Switching to Handles from Smooth with no handles stored bakes the worked-out handles into Path (`SmoothPath` at the drawn proportions; a B-Spline's points move onto its curve), so the curve keeps its shape.
- **Interpolation** (`EWidgetCurveInterpolation`, a new enum; `Interpolation`, shown for Smooth): how the curve runs through its points, after the production tools (Illustrator's Curvature tool, Figma's auto-smooth, Inkscape's B-spline and Spiro modes, Blender's auto / NURBS handles, d3's curve family). Each turns into Bezier handles per run between corners (`WidgetCurveFitting`: a Disconnected point splits the contour, each run ends there as an open line ends; a corner with a Corner Radius stays Straight so it is rounded):
  - **Balanced** - the original smoothing (handles along the neighbours' line, a third of each side; ends aimed at the neighbour's handle tip; corners Straight), kept as the property's default so saved Curves keep their curve.
  - **Catmull-Rom** + **Catmull-Rom Alpha** (0.5 centripetal: never loops or cusps; 0 uniform; 1 chordal) - the non-uniform Catmull-Rom segment as its Bezier (Yuksel, Schaefer, Keyser), ends mirrored through their end point. **A Curve placed from the palette starts with it** (`OnCreationFromPalette`).
  - **Natural** - natural cubic spline with chord-length knots: curvature continuous (C2), least bending; closed runs solved as a cyclic tridiagonal system (Sherman-Morrison).
  - **Monotone** - Steffen's monotone cubic for charts (never over- or undershoots between points, flat at peaks); a run that doesn't go one way across falls back to Catmull-Rom; Smoothness held to 1.
  - **B-Spline** - uniform cubic B-spline over the points as a control cage (through each run's ends and corners only); vertices moved onto the curve; Smoothness 0..1 blends from the cage.
  - **Smoothness** scales every handle (0 straight, 1 the interpolation's curve, up to 2).
  - All of them (Balanced too) are worked out **at the drawn proportions**: `UCurveShape::BuildCurvePath(Path, PixelsPerBox)` scales positions out of box fractions first and handles back after. It overrides `BuildOutline` (frame size) - the old smoothing in box fractions aimed handles wrong on a stretched widget (200 x 80), which was the kinked look. `BuildPath` (no frame) uses the last drawn size (`GetDrawnPixelsPerBox`, Desired Size before it is shown).
- **The canvas editor on a Curve** (`UCustomShape` virtuals `BuildDisplayPath`, `ShowsControlCage`, `MakeContourFromStroke`; see "Canvas path editor" below): the outline is drawn and hit-tested as the curve draws it (not the straight lines between its points); double-clicking an edge adds a point where the line is drawn; points are circles (smooth) or squares (corners); double-click or the toolbar's **Smooth / Corner** chips switch them (the four vertex-kind chips show only where handles are the vertices' own); the Pen's drag places the new point; a B-Spline shows its control cage, faint.
- **Fitting a line drawn by hand** (`MakeContourFromStroke`; Pencil, `FitCurveToPoints`): Handles As Drawn (and every plain Custom Shape) - Schneider's Bezier fit (chord-length parameters, least-squares handle lengths on fixed tangents, 4 Newton reparameterisations, split at the worst point with a centre tangent), corners where the line turns more than 70 degrees over a short stretch (`FindCorners`; a closed line's seam looked at from halfway round), a closed line with no corner smooth at its seam. Straight Lines - Douglas-Peucker keeping the corners. Smooth Through Points - **the fewest points whose smoothed curve follows the line**: from a sparse Douglas-Peucker start the drawn point farthest from the interpolated curve (its segment and neighbours, 16 samples each) is added until none is farther than the tolerance (at most 256 passes) - so the fit holds for whichever interpolation is set. Checked outside the engine (a stand-in for TArray / FVector2D): natural spline C1 / C2 joins and natural ends to 1e-14, closed too; monotone never overshoots on a step chart; a noisy sine at tolerance 2 -> 13 vertices within 1.9; a V -> 3 vertices with a corner; a circle at 0.5 -> 6; a square -> its 4 corners exactly.
- **Ends:** Start / End Marker (`EWidgetPathMarker`), Marker Size - as before. **Start / End Cap Angle** (degrees from square, clockwise, -80..80): a Butt or Square end with no marker is cut at the angle (a Round cap ignores it) - the same angle both ends slants them in parallel, opposite angles taper. Built by `WidgetShapeGeometry::SlantStrokeEnd`: the piece is stroked longer (`GetSlantReach` = half width x tan + 2 fades) with a flat cap, cut along lines half a fade either side of the slanted edge (`CutAlong`), triangles past it dropped and coverage ramped across the band - only near that end, so a line crossing the cut's line elsewhere keeps it. Works with dashes (offset kept), taper (ribbons) and a Trim Path (its drawn ends).
- **Stroke hook (every shape):** `UShapeWidget::BuildStrokeMesh` / `PaintsStrokeGradientAlongOutline` as before. The Curve's override is used when it has markers, a varying width, a gradient along it or a slanted end.
- **Width:** Start / End Width Scale, Use Width Curve + Width Curve - as before. **Gradient Along Curve** - as before.
- **Shared from Widget Paths:** `WidgetPathGeometry::GetMarkerInset`, `BuildEndMarker`, `BuildDashedRibbons`, `Resample`, `CutBetween`, `SampleAt`.
- **Templates** (`EWidgetCurveTemplate`, `MakeTemplatePath`) as before; Start From lists them first for a Curve.
- **Curve Presets** (`UWidgetCurvePresetAsset`): Path, Smoothing, **Interpolation** (default Balanced, as saved presets had), Smoothness, **Catmull-Rom Alpha**, Apply Look + Stroke, Fill, markers, **cap angles**, widths, Width Curve, Gradient Along Curve. Following, Save Preset, `SyncPresetToTemplate` - as before; the new fields are covered (`GetPresetCoveredProperties`). The asset lists a Material paint's parameters as it is edited.
- **Blueprint:** as before, plus **Set Interpolation**, **Set Cap Angles**, **Fit Curve To Points** (Tolerance in Slate units at the last drawn size: points added as the pointer moved tidied into the few that follow them, per Smoothing - a signature, a gesture), **Reverse Curve**. C++: `BuildCurvePath`, `GetDrawnPixelsPerBox`.

### Canvas path editor (`NameTBDEditor/Private/WidgetShapePathEditor.h/.cpp`; every Custom Shape)
- **No widget picking while editing:** the editing layer (`SWidgetShapePathCanvas`) reaches `OverlayMargin` = 50000 canvas units past the shape on every side (was 160), so it covers the whole designer at any zoom: left clicks anywhere are the editor's - no other widget is selected, the designer's own selection box doesn't start, and editing is never left by a stray click. Plain mouse moves are handled too (the designer doesn't light up other widgets). Leaving takes Done, Enter or Escape (with nothing selected) - **clicking off the shape and double-clicking empty space no longer finish**. The wheel, right and middle buttons still reach the designer (zoom, pan).
- **Drawn over the designer's outline:** the layer paints nothing itself (`OnPaint` returns); `FWidgetShapePathEditorExtension::Paint` (the designer calls every extension's after its preview, as the motion paths and gizmo use) draws `PaintOverlay` in the designer's space, clipped to it - over the designer's selection box and handles. The Widget Gizmo is held off a shape being edited (`FGizmoLayer::GatherTargets` treats it as locked), so its handles and keys don't compete.
- **Shift-click** empty space (Select tool, no drag): a vertex there (`AddPointAnywhere`) - after the selected open end, else where it lengthens the outline least (between two vertices, or past an end, measured in local pixels), or a new contour. Shift-drag is still the additive selection box.
- **Pencil** (N; `ETool::Pencil`, toolbar chip `ShapeEdit_Pencil.svg`): freehand, a point every 1.5 canvas units; on release `MakeContourFromStroke` with the toolbar's **Fit** (`WidgetShapePathEditing::PencilTolerance`, 2.5 by default, shared). Started on an open contour's end it carries it on (the end vertex keeps its place and takes the line's first handle - Disconnected where handles are the vertices' own); ended on the start (or the contour's other end) it closes; a line shorter than the hit radius is a click. Escape while drawing drops it; one undo step ("Draw With Pencil").
- Ctrl-drag (pull handles) only where handles are the vertices' own.

### Curve: production expectations
"There could be more use cases that users desire that I haven't thought of, but would be expected in a production-grade application."
- **Beyond the request (earlier):** smoothing through points with sharp corners kept; arrowheads and end marks that ride a draw-on; taper and width curves; a gradient along the line; twelve ready-made curves; presets as assets that follow later edits; drawing from data (Set Points, Add Point, Plot Values); sampling (point and heading at a fraction or distance, nearest fraction); a curve doesn't block the pointer by default.
- **Beyond the request (this round):** five interpolations (with the Catmull-Rom parameterisation exposed and a charts mode that never overshoots), all at the drawn proportions; a Pencil whose fit is the fewest points for whichever interpolation is set, corners kept, continuing and closing contours; Fit Curve To Points for lines drawn at runtime; the editor drawing and inserting on the real curve, Smooth / Corner points, a B-Spline control cage; slanted ends that work with dashes, taper and draw-on, and the same on the progress bar's curve; a Material paint with listed parameters and live values (ShapeSize, OutlineLength, Trim) on every shape; Reverse Curve, Set Interpolation, Set Cap Angles in Blueprint; the gizmo held off while editing.
- **Still open:** caps on a tapered line (ribbons end flat, slant still applies); markers, taper and slant on closed contours; Spiro / kappa (curvature-extrema) interpolation; per-point width (Illustrator's Width tool) - the Width Curve covers along-the-line; separate start / end cap kinds; a cap angle measured against the screen rather than the line; right-click in edit mode still reaches the designer (its context menu can select the widget under it) - a context menu of editing actions instead; the Pencil's pressure / speed; snapping to a grid; a Curve Preset edited while a Widget Blueprint using it is open reaches it on its next load; markers drawn with an image or material; a glow under the line (Drop Shadow's Glow); Curve values in the Shape track's list; Constraints' Follow Path reading a Curve directly; Material paint in Glass / Flip Card / Flow List scroll bar (drawn as Color there).
