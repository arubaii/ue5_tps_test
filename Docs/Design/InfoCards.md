# Info Cards, tooltips and right-click menus

## Info Card architecture (short)
- **Files:** `Source/NameTBD/Cards/` - `InfoCardTypes.h` (spec, payloads, additive animations), `InfoCardSpecDataAsset.h` (`UInfoCardDataAsset`), `InfoCardAnchor.h/.cpp` (`UInfoCardAnchor : UBorder`), `InfoCardWidget.h/.cpp` (`UInfoCardWidget : UUserWidget`, the spawned card), `SInfoCardDesignerPreview` (designer card), `InfoCardTextWidget` (Text Info Card), `TooltipCardAnchor` (Tooltip Card Anchor, `UInfoCardLibrary`), `ContextMenu/` (menu asset, style, payload, menu and row widgets, Context Menu Anchor). Project settings: `DeveloperSettings/InfoCardDeveloperSettings.h` (Project Settings > Game > Info Card). Editor: `NameTBDEditor/Private/InfoCardDetails.*`, `InfoCardAnchorPreviewToolbar.*`.
- **Sources of an anchor's cards (`InfoCards`, runtime copy):** Use Data Asset (`InfoCards_DA` + Payload Defaults + Settings Overrides + Additive Animation Overrides), Custom (`CustomInfoCards`), or **generated** - a subclass overriding `UsesGeneratedInfoCards` / `BuildGeneratedInfoCards` (Tooltip / Context Menu Anchor); its runtime setters call `RebuildGeneratedInfoCards`, which re-delivers payloads to live cards (and closes one whose entry went away or was disabled). Every rebuild path ends in `ApplyCardTextOverrides` (`Set Card Text`).
- `MakeSpecFromDataAsset` (static): one Data Asset entry as an anchor uses it - payloads duplicated with the given outer, Default Sounds / Default Additive Animations filled in where the entry has none. Shared by the anchor and the Tooltip Card Anchor's template.
- **Data Asset entry layout:** `FInfoCardSpec` fields are in categories Card, Trigger, Placement, Dismissal, Payloads, Animation, Sound, Suppression. `FInfoCardGroupedStructCustomization` (editor) shows them as groups in that order; Card, Trigger and Payloads start expanded. Highlight-only Trigger fields are hidden (not greyed) for other card types. The asset itself: Info Cards (titled by Card ID), Defaults (Default Sounds, **Default Additive Animations**), Suppression.
- **Anchor element rows:** Payload Defaults (`FInfoCardPayloadDefaultCustomization`): the Card ID as the element's title (no Card ID row), the payload's type as plain text in the header (no class dropdown), and the payload's own fields directly under it (found by name under the object node with `GetChildHandle(Name, true)` and only taken when the handle's `FProperty` is that field; falls back to the payload row if none are reachable). Settings Overrides elements: Card ID row hidden, the `Settings` struct flattened into Trigger / Placement / Offset / Tick / Dismissal / Sound / Card Transform groups. Additive Animation Overrides elements: Card ID row hidden.
- **Additive animations (`FInfoCardAdditiveAnimations`), the Use Basic Animations pattern (as the Flow List's transitions):** `bUseBasicAnimations` (default on) shows Play In / Play Out (`FInfoCardAdditiveAnimSettings`: fade, scale, slide, rotate, pulse typed in place); off shows **Anim In / Anim Out** (`TArray<FWidgetAnimEntryBase>`, Widget Animation assets; Mirror In Out plays an entry as the other direction too). Only the shown side plays (`ResolveInto`), the other is kept. `IsEmpty` follows the switch.
  - Migration: the old shared `Animations` list (hidden UPROPERTY) moves into Anim In with the switch off (`MigrateLegacyAnimations`, from `PostSerialize`); the same for the anchor's Additive Animation Overrides (old loose `Animations` / `PlayIn` / `PlayOut` kept hidden, folded into the new `AdditiveAnimations` struct in `UInfoCardAnchor::PostLoad`) and for the Data Asset's old `DefaultAdditiveAnimations` (into `DefaultCardAnimations` in `UInfoCardDataAsset::PostLoad`).
  - Data Asset fallback: an entry whose own set would play nothing gets the asset's Default Additive Animations (whole set, not per side). Additive Animation Overrides mirror that resolved set while Override is off.
- **Designer preview (the real card):** at design time `RebuildWidget` hands the designer an `SInfoCardDesignerPreview` panel: the border as the only child taking part in layout, plus the previewed card arranged outside the box (`FInfoCardDesignerPlacement::FromSpec`, the runtime's `PositionToIconRaw` / `PositionToCursorRaw` arithmetic with the anchor's box at the origin; To Cursor uses the anchor's centre as the cursor; To Viewport shows to the anchor's right; no clamp/flip/overlap). `RefreshDesignerPreviewCard` (every design-time synchronize, before the animation harness) creates the card with the outer User Widget as owner, sets designer flags and calls `UInfoCardWidget::SetupDesignerPreview` (placement fields, Card Transform, payloads - Apply Payloads runs - hit-test invisible; no timers, press watcher, viewport or registration). Which card: **Preview Card** (`DesignerPreviewCardId`, saved, editor only) or the toolbar's pick on the designer copy (`SetDesignerPreviewCardPick`).
  - Animation: `GetPreviewAnimationTarget` is the designer card when there is one (targets inside the card resolve with `GetWidgetFromName`); the harness settings (`DesignerAnimPreview`) are hidden and reset to Off on load. The **Widget Blueprint toolbar** (`FInfoCardAnchorPreviewToolbar`, beside the button preview) shows, with one anchor selected: its name, **Card: [picker]**, **In / Out** (`PlayDesignerCardAnimation`). Picks are remembered per anchor name for the session and re-applied when the designer rebuilds its preview.
- **Nested presses:** `ShouldPressCloseCard`'s Outside Card and Outside Anchor And Card zones count a press on a card nested inside this one (`IsPointOverDescendantCard`) as inside - a submenu's item no longer closes the menu it came from.
- `ShouldReopenOnRepeatClick(Index)` (virtual, default false): a repeat click on the anchor while its card is up opens it again (where the click landed) instead of toggling it shut. The Context Menu Anchor says true.
- `UInfoCardWidget::MarkAsEmbedded()`: a card shown by something else (an engine tooltip) is treated as embedded - never positioned, registered or dismissed by the system.

## Tooltips
- **Tooltip Card Anchor** (`UTooltipCardAnchor`): wrap, type **Tooltip Text** (and optionally **Tooltip Title**), done. Everything else comes from **Tooltip Template** (an Info Card Data Asset; Template Card ID picks the entry, else its first), else Project Settings > Info Card > Tooltips > **Default Tooltip Template**, else the built-in tooltip (`MakeBuiltInTooltipSpec`: Card ID `Tooltip`, Highlight with the project's Highlight Delay preset, above the widget with 6 px, dismissed by any press, a 0.12 s fade mirrored as the exit, card class = Default Tooltip Card Class or Text Info Card). Advanced, each with an inline toggle: Position, Delay (seconds, Custom), Text Style. Empty text and title: the entry is kept but disabled. The generic anchor's source fields are hidden by `FInfoCardGeneratedAnchorDetails`; its own category comes first. Blueprint: `Set Tooltip Card Text`, `Get Tooltip Card Text / Title` (not `SetToolTipText`: UWidget's own UFUNCTION / property names collide case-insensitively).
- **Text Info Card** (`UInfoCardTextWidget`): a card with no Widget Blueprint - Border (`CardBackground`) > Size Box (`CardWidthBox`, Max Width) > Vertical Box > `TitleText` / `BodyText` (wrapping), built in `Initialize` only for the C++ class (a Widget Blueprint made from it owns its tree and is filled by those names). Style `FInfoCardTextStyle` (rounded box with outline, padding, max width, title / body fonts and colours, gap, justification); fonts are the engine's font asset (constructor helper). Reads `UInfoCardPayload_Text`, and `UInfoCardPayload_TextStyle` when present (a re-delivery without it goes back to the class's style).
- **Blueprint:** `UInfoCardAnchor::Set Card Text (Card ID, Title, Body)` - sets the card's text payload (adds one if missing), survives re-reading the Data Asset, shown by the designer card: a Widget Blueprint wrapping an anchor exposes a "Tooltip Text" variable and calls it from Pre Construct (the Blueprint way to make one-field anchors); `Clear Card Text`. `UInfoCardLibrary`: `Set Widget Tooltip Card` (the nearest Tooltip Card Anchor around the widget gets the text; else the widget's engine tooltip becomes an embedded Text Info Card), `Find Info Card Anchor Around`, `Find Tooltip Anchor Around` (walk up panels and out of User Widgets).

## Right-click context menus
- **Data (`ContextMenu/ContextMenuTypes.h`):**
  - `UContextMenuAsset` ("Context Menu"): Entries (top-down), Style, Shortcuts Work While Open. Entry IDs are filled from the label once it has one (`AssignMissingEntryIds`; on load even without text) and made unique (`Copy`, `Copy_1`); kept afterwards, since anchors' overrides point at them.
  - `FContextMenuEntry`: Entry Type (`EContextMenuEntryType`: Button, Submenu, Divider, Text Divider (`Header`), Spacer), Entry ID; Content (Label, Description = row tooltip, Left / Center / Right Icon (`FContextMenuIcon`: Image Source Texture 2D / SVG, optional tint), Right Text, Shortcut (`FInputChord`, shown as "Ctrl+C"), Text Divider text / alignment (left, centre, right) / Show Line (default on), spacer height); Action (Actions - **instanced `UButtonAction`s**, filled in place - Button Tag, Close Menu On Click, Submenu asset); State (Enabled, Check Type None / Check Box / Radio Button, Checked, Radio Group, Emphasis Normal / Destructive); Look (Row Button Preset). Fields show only for the types that use them; the editor groups them (Entry ungrouped, then Content, Action, State, Look).
  - `FContextMenuStyle` in `UContextMenuStyleAsset` ("Context Menu Style"): panel (brush, padding, min / max width, max height then scroll), rows (**Row Button Preset**, row height / padding, native highlight / pressed brushes, icon size, part gap, always reserve the icon column), text (label font, normal / highlighted / disabled / destructive colours, shortcut font / colour), icons (tints per state, submenu arrow, check mark, radio mark; unset: text glyphs ›, ✓, ●), dividers (colour, thickness, padding, text divider font / colour / padding, uppercase), behaviour (submenu delay, close other cards on open, type to select, wrap navigation, Open Animations - an `FInfoCardAdditiveAnimations`, default a mirrored fade + 0.96 grow - Menu Sounds), custom widgets (Menu / Entry / Divider Widget Class). Resolve order: anchor Style Override > menu asset Style > Project Settings > Info Card > Context Menus > **Default Context Menu Style** > built-in (the style asset CDO).
  - `UInfoCardPayload_ContextMenu` ("Info Card Data (Context Menu)"): Menu, Style Override, Entry Overrides, Extra Entries, runtime states (from the anchor), the anchor (weak), focus-first flag. `BuildEntries`: asset entries, overrides (remove, enabled, label, checked), extra entries inserted (start, end, before / after an ID), runtime states, removed rows dropped, then stray dividers (first, last, doubled) tidied. Any Info Card entry whose Card Class is a Context Menu Widget can carry one; the old tag-list payload (`UContextMenuPayload`, "Tag Payload") is also read, a row per tag that has Button Actions data.
- **Menu (`UContextMenuWidget : UInfoCardWidget`):** native frame (Border `MenuPanel` > Size Box `MenuSizeBox` > Scroll Box `MenuScroll` > Vertical Box `EntriesBox`; a Widget Blueprint made from it fills those names). Applies the style's Open Animations / Menu Sounds once when the entry brought none. `BuildRows`: per entry, actions duplicated with the menu as outer (each open menu has its own instances, with a world), a Button Tag's actions instantiated and its text / icons used where the entry has none, then `Is Action Visible` / `Is Action Enabled` (runtime only) hide / grey rows; one row widget each. Keyboard / gamepad: Up / Down (wrapping, skipping what can't be chosen), Home / End, Right opens a submenu (focused), Left / Escape / B close a submenu level and refocus its row (Escape closes the root), Enter / A via the row's button, the entry's shortcut while open, type-to-select by first letter (cycling). Focus: the first row for keyboard openings, else the menu itself (next tick); on close, focus goes back to the anchor's content if the menu still had it. `HandleEntryChosen`: checks first (check box flips, radio clears its group in this menu; remembered on the anchor), inline actions get the whole context (`FContextMenuActionContext`: Entry ID, menu, button, anchor, source widget, all action payloads), tag actions get exactly their expected payloads index for index, then `OnEntryChosen` and the anchor's `On Menu Entry Clicked`, then the whole chain closes if Close Menu On Click.
- **Rows (`UContextMenuEntryWidget`):** button rows are a **Context Menu Button** (`RowButton`) > Border `RowHighlight` > Size Box `RowSize` > Horizontal Box of parts: icon column (`LeftIcon` or `CheckMark`), `CenterIcon`, `LabelText` (fill, ellipsis), `RightText`, `ShortcutText`, `RightIcon`, `SubmenuArrow`. The button never closes a card or toggles an enabled state itself; a Row Button Preset (style's, or the entry's) is applied with `ApplyButtonPreset`, and then the native highlight is off. Dividers: Border `DividerInset` > Horizontal Box with `DividerLine` (and `HeaderText` for text dividers, lines before / after by alignment). Hover moves keyboard focus to the row (only after the cursor moved), so one row is highlighted. A Widget Blueprint row fills the same names; `On Menu Entry Set`, `On Highlight Changed`. **Submenus:** the row's button sits in an Info Card Anchor (`SubmenuAnchor`, Custom source, focus triggering off) with one Highlight entry (`Submenu`): the style's Submenu Delay, Keep Open Until Cursor Leaves, To Icon Right (padding = panel padding), flip on, Close Other Cards Scope Same Source Widget Class, the parent's style and anchor, the parent card's action payloads. Runtime entry states are read live from the root anchor, so they reach submenus.
- **Context Menu Anchor (`UContextMenuAnchor`):** Menu, Open With (Right Click, Left Click, Right Or Left Click, Only From Blueprint), Placement (At Cursor - keyboard openings go below the widget - Below Widget, Right Of Widget), Style Override, **Entry Overrides** (synced from the menu by ID, `EditFixedSize`, unset rows show the asset's values), **Extra Entries**, **Action Payloads** (instanced, duplicated per spec). Generated spec(s): `ContextMenu` (+ `ContextMenuLeft` for Any Click), To Cursor Down Right (2,2) without per-tick updates, clamp + flip, Outside Card, Close Others All Cards (style), no overlap avoidance, Z 1500. Events: **On Menu Entry Clicked (Entry ID, Is Checked)**, **On Context Menu Opening** (before rows are built). API: Open / Close Context Menu, Is Context Menu Open, Get Open Context Menu, Set Context Menu, Set Action Payloads, Set Entry Enabled / Hidden / Label / Checked, Is Entry Checked, Clear Entry Changes (open menus rebuild next tick). Left Click on a wrapped button: the anchor listens to the button's press / click (a press while open closes; a click opens).
- **Button Actions (`Buttons/Actions/`):** `UButtonAction` gained `Execute Menu Action (Context)` (default calls Execute Action with the button and payloads), `Is Action Visible` / `Is Action Enabled`, `Find Action Payload`. Built-in actions (`CommonButtonActions.h`): Run Console Command, Copy Text (or the first Context Button Payload (Text)), Call Function (by name on the source widget / owning player / pawn; no parameters or one Name = Entry ID; problems logged), Open URL, Play Sound.
- **Button Tag label fix:** `UContextMenuButton::ApplyButtonData` worked out the tag's Button Text and never wrote it; it now goes through `ApplyButtonTextFromData` (blank never overwrites authored text).

- Glyph fallbacks (✓, ●, ›) render in the engine's default font.
- Payload Defaults' flattened fields still reach the designer preview and undo like the old nested rows (same handles, same notify hook).

- Hover-moves-focus doesn't fight other anchors' focus triggers.
