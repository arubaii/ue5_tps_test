# Info Cards, tooltips and right-click menus

## Info Card architecture (short)
- **Files:** `Source/NameTBD/Cards/` - `InfoCardTypes.h` (spec, payloads, additive animations), `InfoCardSpecDataAsset.h` (`UInfoCardDataAsset`), `InfoCardAnchor.h/.cpp` (`UInfoCardAnchor : UBorder`), `InfoCardWidget.h/.cpp` (`UInfoCardWidget : UUserWidget`, the spawned card), `SInfoCardDesignerPreview` (designer card), `InfoCardTextWidget` (Text Info Card), `TooltipCardAnchor` (Tooltip Card Anchor, `UInfoCardLibrary`), `ContextMenu/` (menu asset, style, payload, menu and row widgets, Context Menu Anchor). Project settings: `DeveloperSettings/InfoCardDeveloperSettings.h` (Project Settings > Game > Info Card). Editor: `NameTBDEditor/Private/InfoCardDetails.*`, `InfoCardAnchorPreviewToolbar.*`.
- **Sources of an anchor's cards (`InfoCards`, runtime copy):** Use Data Asset (`InfoCards_DA` + Payload Defaults + Settings Overrides + Additive Animation Overrides), Custom (`CustomInfoCards`), or **generated** - a subclass overriding `UsesGeneratedInfoCards` / `BuildGeneratedInfoCards` (Tooltip / Context Menu Anchor); its runtime setters call `RebuildGeneratedInfoCards`, which re-delivers payloads to live cards (and closes one whose entry went away or was disabled). Every rebuild path ends in `ApplyCardTextOverrides` (`Set Card Text`).
- `MakeSpecFromDataAsset` (static): one Data Asset entry as an anchor uses it - payloads duplicated with the given outer, Default Sounds / Default Additive Animations filled in where the entry has none. Shared by the anchor and the Tooltip Card Anchor's template.
- **Data Asset entry layout:** `FInfoCardSpec` fields are in categories Card, Trigger, Placement, Dismissal, Payloads, Animation, Sound, Suppression. `FInfoCardGroupedStructCustomization` (editor) shows them as groups in that order; Card, Trigger and Payloads start expanded. Highlight-only Trigger fields are hidden (not greyed) for other card types. The asset itself: Info Cards (titled by Card ID), Defaults (Default Sounds, **Default Additive Animations**), Suppression.
- **Anchor element rows:** Payload Defaults (`FInfoCardPayloadDefaultCustomization`): the Card ID as the element's title (no Card ID row), the payload's type as plain text in the header (no class dropdown), and the payload's own fields directly under it (found by name under the object node with `GetChildHandle(Name, true)` and only taken when the handle's `FProperty` is that field; falls back to the payload row if none are reachable). Settings Overrides elements: Card ID row hidden, the `Settings` struct flattened into Trigger / Placement / Offset / Tick / Dismissal / Sound / Card Transform groups. Additive Animation Overrides elements: Card ID row hidden.
- **Additive animations (`FInfoCardAdditiveAnimations`), the Use Basic Animations pattern (as the Flow List's transitions):** `bUseBasicAnimations` (default on) shows Play In / Play Out (`FInfoCardAdditiveAnimSettings`: fade, scale, slide, rotate, pulse typed in place); off shows **Anim In / Anim Out** (`TArray<FWidgetAnimEntryBase>`, Widget Animation assets; Mirror In Out plays an entry as the other direction too). Only the shown side plays (`ResolveInto`), the other is kept. `IsEmpty` follows the switch.
  - Migration: the old shared `Animations` list (hidden UPROPERTY) moves into Anim In with the switch off (`MigrateLegacyAnimations`, from `PostSerialize`); the same for the anchor's Additive Animation Overrides (old loose `Animations` / `PlayIn` / `PlayOut` kept hidden, folded into the new `AdditiveAnimations` struct in `UInfoCardAnchor::PostLoad`) and for the Data Asset's old `DefaultAdditiveAnimations` (into `DefaultCardAnimations` in `UInfoCardDataAsset::PostLoad`).
  - Data Asset fallback: an entry whose own set would play nothing gets the asset's Default Additive Animations (whole set, not per side). Additive Animation Overrides mirror that resolved set while Override is off.
- **Designer preview (the real card):** at design time `RebuildWidget` hands the designer an `SInfoCardDesignerPreview` panel: the border as the only child taking part in layout, plus the previewed card arranged outside the box (`FInfoCardDesignerPlacement::FromSpec`, the runtime's `PositionToIconRaw` / `PositionToCursorRaw` arithmetic with the anchor's box at the origin; To Cursor uses the anchor's centre as the cursor; To Viewport shows to the anchor's right; no clamp/flip/overlap). `RefreshDesignerPreviewCard` (every design-time synchronize, before the animation harness) creates the card with the outer User Widget as owner, sets designer flags and calls `UInfoCardWidget::SetupDesignerPreview` (placement fields, Card Transform, payloads - Apply Payloads runs - hit-test invisible; no timers, press watcher, viewport or registration). Which card: **Preview Card** (`DesignerPreviewCardId`, saved, editor only) or the toolbar's pick on the designer copy (`SetDesignerPreviewCardPick`).
  - Animation: `GetPreviewAnimationTarget` is the designer card when there is one (targets inside the card resolve with `GetWidgetFromName`); the harness settings (`DesignerAnimPreview`) are hidden and reset to Off on load. The **Widget Blueprint toolbar** (`FInfoCardAnchorPreviewToolbar`, beside the button preview) shows, with one anchor selected: its name, **Card: [picker]**, **In / Out** (`PlayDesignerCardAnimation`). Picks are remembered per anchor name for the session and re-applied when the designer rebuilds its preview.
- **Nested presses:** `ShouldPressCloseCard`'s Outside Card and Outside Anchor And Card zones count a press on a card nested inside this one (`IsPointOverDescendantCard`) as inside - a submenu's item no longer closes the menu it came from.
- `ShouldReopenOnRepeatClick(Index)` (virtual, default false): a repeat click on the anchor while its card is up opens it again (where the click landed) instead of toggling it shut. The Context Menu Anchor says true.
- `UInfoCardWidget::MarkAsEmbedded()`: a card shown by something else (an engine tooltip) is treated as embedded - never positioned, registered or dismissed by the system.
- **`FInfoCardPositioning`** (`InfoCardTypes.h`, category **Placement**): an entry's Placement fields in one struct for widgets that build their cards, named and ordered as the entry's: **Placement Source** (`Source`: Custom / Use Project Settings) + **Placement Preset** (`PresetName`, dropdown of the project's presets), then Position Mode, Icon Position, Fill Icon Padding, Cursor Position, **From Keyboard** (side used when a To Cursor card is opened from a key), Viewport Position, Card Transform, Card Offset, Icon Anchor Padding, Clamp To Viewport, Flip To Avoid Clipping (a plain bool here, written as Custom), Clamp Padding, Avoid Overlapping Cards, **Follow Cursor** (the entry's Update Position On Tick for To Cursor; To Icon / To Viewport always update per tick), **ZOrder** (default 1000, as the entry). Every field but the source pair hides while Use Project Settings. `Resolve()` (the named preset's fields, never following a preset's own source; a missing name: these), `ApplyTo(Spec, bFromKeyboard)` (resolves first, writes ZOrder too), `FromSpec` (ZOrder too), `MakeBeside(Side, Gap, ZOrder = 1000)`, `MakeAtCursor(ZOrder)`. Used by the Tooltip Card Anchor, Context Menu Style (menus, row tooltips, submenus), Context Menu Anchor's Override Placement, attached menus and submenus.
- **Placement Presets** (Project Settings > Info Card > Placement > `PlacementPresets`, `FInfoCardPlacementPreset`: name + `FInfoCardPositioning`; `FindPlacementPreset`, `GetPlacementPresetNameOptions`): seeded Default (at the cursor, Z 1500), Tooltip (`MakeBeside(Up, 6)`), Dropdown (Down, 2, Z 1500), Flyout (Right, 4, Z 1500). The editor shows a preset as its name and its placement's fields (`FInfoCardPlacementPresetCustomization` hides Source / Preset). An Info Card entry (`FInfoCardSpec`) has the same **Placement Source / Placement Preset** pair at the top of Placement (default Custom; its own fields hide while Use Project Settings); `FInfoCardSpec::ResolvePlacementPreset` copies the preset in when an anchor builds its cards (`MakeSpecFromDataAsset`, the Custom array), before Settings Overrides, which gained **Override Placement Preset** + **Placement Preset** (applied before Override Card Position / Offset).
- **Z order:** `ShowCardAtIndex` puts a card on screen at its entry's ZOrder, raised to one above the card its anchor sits in (`UInfoCardWidget::FindContainingCard`, `GetCardZOrder` / `SetCardZOrder`): a submenu, a menu row's tooltip, any card opened from inside a card always draws in front of it.

## Tooltips
- **Tooltip Card Anchor** (`UTooltipCardAnchor`): wrap, type **Tooltip Text** (and optionally **Tooltip Title**), done. Everything else comes from **Tooltip Template** (an Info Card Data Asset; Template Card ID picks the entry, else its first), else Project Settings > Info Card > Tooltips > **Default Tooltip Template**, else the built-in tooltip (`MakeBuiltInTooltipSpec`: Card ID `Tooltip`, Highlight with the project's Highlight Delay preset, above the widget with 6 px, dismissed by any press, a 0.12 s fade mirrored as the exit, card class = Default Tooltip Card Class or Text Info Card). Advanced, each with an inline toggle: **Position** (`TooltipPositioning`, an `FInfoCardPositioning`: every placement field an Info Card entry has, ZOrder included, or a Placement Preset; default To Icon Up 6 px, the built-in's; while off it shows the template entry's placement, `FromSpec`), Delay (seconds, Custom), Text Style. The old side-only `TooltipPosition` loads into `TooltipPosition_DEPRECATED` (CoreRedirect) and `PostLoad` turns it into To Icon on that side, the rest from the anchor's own template entry (no loading) or the built-in. `SetKeepsOtherCardsOpen` (C++, not saved): Close Other Cards Scope forced to None (menu rows' tooltips). Empty text and title: the entry is kept but disabled. The generic anchor's source fields are hidden by `FInfoCardGeneratedAnchorDetails`; its own category comes first. Blueprint: `Set Tooltip Card Text`, `Get Tooltip Card Text / Title` (not `SetToolTipText`: UWidget's own UFUNCTION / property names collide case-insensitively).
- **Text Info Card** (`UInfoCardTextWidget`): a card with no Widget Blueprint - Border (`CardBackground`) > Size Box (`CardWidthBox`, Max Width) > Vertical Box > `TitleText` / `BodyText` (wrapping), built in `Initialize` only for the C++ class (a Widget Blueprint made from it owns its tree and is filled by those names). Style `FInfoCardTextStyle` (rounded box with outline, padding, max width, title / body fonts and colours, gap, justification); fonts are the engine's font asset (constructor helper). Reads `UInfoCardPayload_Text`, and `UInfoCardPayload_TextStyle` when present (a re-delivery without it goes back to the class's style).
- **Blueprint:** `UInfoCardAnchor::Set Card Text (Card ID, Title, Body)` - sets the card's text payload (adds one if missing), survives re-reading the Data Asset, shown by the designer card: a Widget Blueprint wrapping an anchor exposes a "Tooltip Text" variable and calls it from Pre Construct (the Blueprint way to make one-field anchors); `Clear Card Text`. `UInfoCardLibrary`: `Set Widget Tooltip Card` (the nearest Tooltip Card Anchor around the widget gets the text; else the widget's engine tooltip becomes an embedded Text Info Card), `Find Info Card Anchor Around`, `Find Tooltip Anchor Around` (walk up panels and out of User Widgets).

## Right-click context menus
- **Data (`ContextMenu/ContextMenuTypes.h`):**
  - `UContextMenuAsset` ("Context Menu"): Entries (top-down), Style, Shortcuts Work While Open. Entry IDs are filled from the label once it has one (`AssignMissingEntryIds`; on load even without text) and made unique (`Copy`, `Copy_1`); kept afterwards, since anchors' overrides point at them.
  - `FContextMenuEntry`: Entry Type (`EContextMenuEntryType`: Button, Submenu, Divider, Text Divider (`Header`), Spacer), Entry ID; Content (Label = the left text, Description = row tooltip, **Left / Center / Right Icons** (`TArray<FContextMenuIcon>`: Image Source Texture 2D / SVG, optional tint; unset elements skipped), **Center Text**, Right Text - one text per alignment - Text Divider text / **Text Alignment** (`EContextMenuTextDividerAlignment`: Style Default, Left, Center, Right) / Show Line (default on), spacer height); **Shortcut** (Shortcut `FInputChord`, **More Shortcuts**, **Gamepad Shortcut** (`FKey`), **Shortcut Input Mapping Context** (`UInputMappingContext`: where the action's keys are read from - its key per device, the player's rebinding of that mapping included, shown even while the context isn't applied and in the designer; empty: wherever the action is mapped now) + **Shortcut Input Action** (the picker narrowed to the context's actions), **More Shortcut Inputs** (`TArray<FContextMenuShortcutInput>`: Input Mapping Context + Input Action each, shown and working while open after the first), **Shortcut Display** (`EContextMenuEntryBindingDisplay`: Style Default / Text / Image)); Action (Actions - **instanced `UButtonAction`s**, filled in place - Button Tag, Close Menu On Click, Submenu asset); **Attached Menu** (Button rows: Attached Menu asset, Style (empty: the parent's), Open On `EContextMenuAttachedMenuTrigger` Hover / Press, **Placement** (`AttachedMenuPositioning`, default `MakeBeside(Right, 4)`)); State (Enabled, Check Type None / Check Box / Radio Button, Checked, Radio Group, Emphasis Normal / Destructive); Look (Row Button Preset). Fields show only for the types that use them; the editor groups them (Entry ungrouped, then Content, Shortcut, Action, Attached Menu, State, Look). An Input Action property with meta `ActionFromMappingContext = "<context property>"` gets the narrowed picker in the grouped structs (`InfoCardDetails::MakeActionFromContextRow`, an `SObjectPropertyEntryBox` filtering by the context's mappings); `FContextMenuShortcutInputCustomization` does it for More Shortcut Inputs elements.
  - Migration (`FContextMenuEntry::PostSerialize`, loading only): the old single `LeftIcon` / `CenterIcon` / `RightIcon` and `HeaderAlignment` load into `..._DEPRECATED` fields (CoreRedirects in `Config/DefaultNameTBD.ini`, editor-only data); a set icon becomes the list's first element, a non-Left alignment becomes the entry's own Center / Right (Fill: Left), Left stays Style Default (the style's default is Left).
  - `FContextMenuStyle` in `UContextMenuStyleAsset` ("Context Menu Style"), categories in this order - **what it does first, what it looks like after** (`FContextMenuStyle::GetCategoryOrder`; the header declares them in the same order): **Behavior** (close other cards on open, type to select, wrap navigation); **Placement** (`Positioning`, an `FInfoCardPositioning` shown as "Placement": default To Cursor Down Right (2, 2), not following, clamp + flip, no overlap avoidance, From Keyboard Down, **ZOrder 1500** - the old hardcoded menu Z; or a Placement Preset); **Submenu** (Submenu Delay; **Submenu Arrow Image** (`SubmenuArrow`, `FContextMenuIcon`: Texture 2D / SVG); **Submenu Arrow** (`SubmenuChevron`, `FContextMenuChevronStyle`: Size 4.5 x 8, Thickness 1.5, Offset, Anti-Alias - the arrow drawn as two strokes by `UContextMenuChevron` / `SContextMenuChevron` when there is no image, centred in its slot: the old text "›" sat on the font's baseline, low in the row); **Submenu Arrow Size** (the square slot, 0: Icon Size); **Custom Submenu Placement** + **Submenu Placement** (off: beside the row on its right, gap = Panel Padding, as before; on: any placement or preset, default `MakeBeside(Right, 4, 2000)`)); **Tooltips** (Row Tooltips); **Panel** (**Menu Widget Class** first, then brush, padding, min / max width, max height then scroll); **Rows** (**Entry Widget Class** first, Row Button Preset, row height, row padding, **Highlight Inset**, Content Horizontal / Vertical Alignment (default Fill / Center), native highlight / pressed brushes, part gap, always reserve the icon column); **Text** (label font, normal / highlighted / disabled / destructive colours, shortcut font / colour, Label / Center Text / Right Text / Shortcut Alignment - `FContextMenuTextAlignment`: Justification, Horizontal, Vertical; defaults Left+Fill, Center+Center, Right+Right, Right+Right); **Bindings** (`FContextMenuBindingStyle`); **Icons** (Icon Size, tints per state, Icon Gap (4) and Icon Delimiter, check mark, radio mark; unset: text glyphs ✓, ●); **Dividers** (**Divider Widget Class** first, colour, thickness, padding, text divider font / colour / padding, uppercase, Text Divider Alignment - the default for entries left at Style Default); **Animation & Sound** (**Animations** (`OpenAnimations`, an `FInfoCardAdditiveAnimations`, default a mirrored fade + 0.96 grow) and Menu Sounds). The editor lays it out with `FContextMenuStyleAssetDetails` (the Style row hidden, each field added to its category, categories sorted by `GetCategoryOrder`) and greys out with `IsEnabled` what a custom widget lays out itself: while Entry Widget Class is a Widget Blueprint, Content Horizontal / Vertical Alignment, Part Gap, Always Reserve Icon Column, the four text alignments, Icon Gap, Icon Delimiter and Submenu Arrow Size; while the divider class in force (Divider Widget Class, else Entry Widget Class) is one, Divider Thickness, Divider Padding, Text Divider Padding and Text Divider Alignment; Submenu Placement until Custom Submenu Placement is on. No EditConditions on `FContextMenuStyle`'s own fields (it is also shown with ShowOnlyInnerProperties); conditions live in the nested structs and the customization. Resolve order: anchor Style Override > menu asset Style > Project Settings > Info Card > Context Menus > **Default Context Menu Style** > built-in (the style asset CDO).
  - **Bindings** (`FContextMenuBindingStyle`): Display Text / **Image** (each key's art from Project Settings > Menus > **Key Glyph Sets** through `UMenuInputSubsystem::GetKeyGlyph` - the player's device family; with no local player (designer) the project's sets directly, keyboard set or the Default Gamepad Family's - so nobody picks images per row; a key without art shows its name), Key Delimiter (`+`), Binding Separator (`, `), Key Gap, **Frame** None / Each Key (delimiters outside) / Whole Binding (delimiters inside) with Frame Brush (rounded outline) and Frame Padding, font override, Glyph Height, Max Bindings, Gamepad Bindings Only On Gamepad (on), Hide Keyboard Bindings On Gamepad (off). Key names: Ctrl / Shift / Alt / Cmd, gamepad keys by family (`MenuInputUtils::GetKeyLabel`), else the short display name; chords written Ctrl, Shift, Alt, Cmd, key.
  - **Row Tooltips** (`FContextMenuTooltipStyle`): Mode Engine Tooltip (default: the old plain tooltip) / **Tooltip Card**: a `UTooltipCardAnchor` (`TooltipAnchor`) around the row's button with Tooltip Template + Template Card ID, Override Text Style + Text Style (`FInfoCardTextStyle`, real font assets on the style asset CDO), Override Delay + Delay (on, 0.6 s), **Override Placement** + **Placement** (on; To Cursor Down Right (12, 20) with overlap avoidance, clear of a submenu, ZOrder 3000; or a Placement Preset). The tooltip anchor keeps other cards open, and the Z order rule keeps it in front of its menu (it had drawn under it: its ZOrder came from the template, 1000, below the menu's 1500).
  - `FContextMenuEntryOverride`: Entry ID (the title), **Remove** (shown as a check box beside the Entry ID by `FContextMenuEntryOverrideCustomization`; the other rows get `IsEnabled(!Remove)`), Enabled / Label / Checked each with its inline override toggle - their EditConditions name the toggle alone (an inline toggle only appears for a single-bool EditCondition: the old `bOverrideX && !bRemove` hid the toggles and left the fields greyed out for good). Enabled off greys the row out; it isn't removed.
  - `UInfoCardPayload_ContextMenu` ("Info Card Data (Context Menu)"): Menu, Style Override, Entry Overrides, Extra Entries, runtime states (from the anchor), the anchor (weak), focus-first flag. `BuildEntries`: asset entries, overrides (remove, enabled, label, checked), extra entries inserted (start, end, before / after an ID), runtime states, removed rows dropped, then stray dividers (first, last, doubled) tidied. Any Info Card entry whose Card Class is a Context Menu Widget can carry one; the old tag-list payload (`UContextMenuPayload`, "Tag Payload") is also read, a row per tag that has Button Actions data.
- **Menu (`UContextMenuWidget : UInfoCardWidget`):** native frame (Border `MenuPanel` > Size Box `MenuSizeBox` > Scroll Box `MenuScroll` > Vertical Box `EntriesBox`; a Widget Blueprint made from it fills those names). Applies the style's Animations / Menu Sounds once when the entry brought none. `BuildRows`: per entry, actions duplicated with the menu as outer (each open menu has its own instances, with a world), a Button Tag's actions instantiated and its text / icons used where the entry has none, then `Is Action Visible` / `Is Action Enabled` (runtime only) hide / grey rows; one row widget each. Keyboard / gamepad: Up / Down (wrapping, skipping what can't be chosen), Home / End, Right opens a submenu (focused), Left / Escape / B close a submenu level and refocus its row (Escape closes the root), Enter / A via the row's button, the entry's shortcut while open, type-to-select by first letter (cycling). Focus: the first row for keyboard openings, else the menu itself (next tick); on close, focus goes back to the anchor's content if the menu still had it. `HandleEntryChosen`: checks first (check box flips, radio clears its group in this menu; remembered on the anchor), inline actions get the whole context (`FContextMenuActionContext`: Entry ID, menu, button, anchor, source widget, all action payloads), tag actions get exactly their expected payloads index for index, then `OnEntryChosen` and the anchor's `On Menu Entry Clicked`, then the whole chain closes if Close Menu On Click.
- **Rows (`UContextMenuEntryWidget`):** button rows are [`SubmenuAnchor` >] [`TooltipAnchor` >] a **Context Menu Button** (`RowButton`) > Border `RowHighlight` > Size Box `RowSize` > Horizontal Box of parts: icon column (Size Box `LeftIconColumn`, as wide as `GetIconColumnWidth(style, N)` for the menu's widest row - N = most left icons, a check mark counting one, at least one with Always Reserve - so labels line up and all move along together, JetBrains-style; holding `CheckMark` or the `LeftIcon`, `LeftIcon_1`... list with Icon Gap / Icon Delimiter, the delimiter width measured with the font measure service), center icons, `LabelText` (ellipsis), `CenterText` + Spacer `CenterTextBalance` (the label and the spacer split the room, so Center Text is centred between the label's start and the right-hand parts; Center Text Alignment Left: right after the label, Right: just before Right Text), `RightText`, `ShortcutText` / `BindingsBox`, right icons, Size Box `SubmenuArrowBox` (Submenu Arrow Size, content centred) > `SubmenuArrow` (submenus and rows with an attached menu: an Image / SVG Image of the style's Submenu Arrow Image, else a `UContextMenuChevron` given the style's Submenu Arrow; tinted with the icon tints; a Widget Blueprint row may place a Context Menu Chevron named SubmenuArrow). **Fill fix:** `UButtonSlot` defaults to centre / centre, so the highlight had shrunk to the label; native rows set the button's parts slot (`GetPartsSlot()`: the content slot or the one kept for hidden parts) to Fill / Fill, padding 0, in `FillParts` after `ApplyButtonPreset` (which copies button properties only, never slots). Content alignment goes on `RowHighlight`'s content, text alignment on each text and its slot - native rows only (`bBuiltNativeTree`); a Widget Blueprint row keeps its own slots and justification. The highlight is inset from the panel edge by Panel Padding (+ Highlight Inset) and the label from the highlight by Row Padding. Shortcuts: `GatherBindings` (display: device rules, Max Bindings; matching: all; the Shortcut Inputs through `UMenuInputSubsystem::GetKeyForActionInContext`, or with no player (designer) the mapping context's own key, `MenuInputUtils::GetContextKey`) -> plain text in `ShortcutText` when Text, no frame, no gap; otherwise built into `BindingsBox` (separators, Whole Binding frames, keys as art or text, Each Key frames, delimiters), coloured with the shortcut colours (art keeps its glyph tint, faded when disabled). While open, `MatchesShortcut` chooses a row by any of its bindings. The button never closes a card or toggles an enabled state itself; a Row Button Preset (style's, or the entry's) is applied with `ApplyButtonPreset`, and then the native highlight is off. Dividers: Border `DividerInset` > Horizontal Box with `DividerLine` (and `HeaderText` for text dividers, lines before / after by alignment). **One lit row per menu:** `UContextMenuWidget::UpdateActiveRow` (each tick, before the rows tick) picks the row the mouse moved onto (it takes keyboard focus, so the keyboard carries on from there), else the focused row (the keyboard moved it; a resting cursor doesn't take it back), else a row the resting cursor is over; where two rows report hover (a Row Button Preset's shapes or hover scale reaching past the row over a wide Highlight Inset) the row whose own box holds the cursor wins. Each row's `SetRowActive` suppresses its button's hover / focus look when it isn't the lit row (`UContextMenuButton::SetHoverLookSuppressed`), and the native highlight follows the lit row (or an open submenu). **Closing:** the chosen row is held idle as the menu closes (`UContextMenuButton::HoldIdleLook`, in `HandleEntryChosen`), and every row of a menu whose chain is closing (`IsMenuChainClosing`) shows no highlight and is held idle - the row went back to Hovered under the cursor for the length of the exit animation. A Widget Blueprint row fills the same names; `On Menu Entry Set`, `On Highlight Changed`. **Submenus and attached menus:** the row sits in an Info Card Anchor (`SubmenuAnchor`, Custom source, focus triggering off) with one Highlight entry (`Submenu`): the style's Submenu Delay, Keep Open Until Cursor Leaves, Close Other Cards Scope Same Source Widget Class, the parent's anchor and action payloads. A submenu: `MakeBeside(Right, panel padding, 2000)`, or the style's Submenu Placement when Custom Submenu Placement is on; the parent's style; ZOrder at least 2000 (and in front of its menu by the Z order rule). An attached menu (Button rows): its own Placement and Style (else the parent's; menu class from that style), hover triggering only for Open On Hover; Open On Press opens it from `HandleEntryChosen` after the actions and events, and the menu stays open. Right opens either. Runtime entry states are read live from the root anchor, so they reach submenus.
- **Context Menu Anchor (`UContextMenuAnchor`):** Menu, Open With (Right Click, Left Click, Right Or Left Click, Only From Blueprint), Style Override, **Override Placement** (`bOverridePositioning` inline toggle + `Positioning`, an `FInfoCardPositioning` defaulting to `MakeAtCursor(1500)`; off: the style's Placement, shown read-only - synced at design time; a Placement Preset either way), **Entry Overrides** (synced from the menu by ID, `EditFixedSize`, unset rows show the asset's values), **Extra Entries**, **Action Payloads** (instanced, duplicated per spec). - **Button Actions (`Buttons/Actions/`):** `UButtonAction` gained `Execute Menu Action (Context)` (default calls Execute Action with the button and payloads), `Is Action Visible` / `Is Action Enabled`, `Find Action Payload`.
