# Widget Constraints and Pointer Effects

> **Standing expectation (the request's own words):** "There could be more use cases that users desire that I haven't thought of, but would be expected in a production-grade application." Each part has a *Beyond the request* list for it and a *Still open* list of what is still expected.

Two UI Components (Add Component on a widget's Details), both wrapping the widget's own Slate widget the way Drop Shadow does (`RebuildWidgetWithContent`), and one widget:
- **Constraints** (`Widgets/Constraints/`): the widget's place, turn, size and opacity tied to other widgets, the pointer, paths and areas.
- **Constraint Target** (`Widgets/Constraints/ConstraintTargetWidget.h`): an invisible point to tie constraints and Pointer Effects to and key with its Transform track (Rive's target group).
- **Pointer Effects** (`Widgets/Pointer/`): how a widget answers the pointer (tilt, lean, press, lights, ripples), and the pointer handed on to materials, shapes, Widget Animations and state machines.
Both are driven by Widget Animations through the **Interaction** tracks (`WidgetAnimation/Evaluators/WidgetAnimInteractionTracks.h/.cpp`).

## Constraints

### How production tools do it (researched)
- **Rive** (Translation, Rotation, Scale, Transform, Distance, Follow Path, IK, Scroll): a constraint stack applied in order; every constraint has **Strength** (0..1, animatable, blends from the unconstrained value); Source / Destination / Min-Max **space** (World or Local); **Copy** per axis with a factor; an **Offset** toggle (keep the starting offset); **Min / Max** limits. Distance has Closer / Further / Exact. Follow Path: Distance (0..100%, may exceed and loop), Orient, Offset.
- **Spine** path constraint: Position Fixed / Percent, Spacing, Rotate Tangent / Chain; **Unity**: Aim (Look At) with world-up, Position / Rotation / Scale / Parent constraints with weights; **Blender**: Limit Location / Distance, Transformation (map a source channel's range to a destination channel's range), Damped Track.
- **Framer Motion / web UI**: springs on derived values (`useSpring`), `useTransform` range mapping, drag constraints with elasticity; magnetic buttons and parallax are this.
- **Animating constrained rigs** (researched for the "constraints with animation" ask): Rive keys any property of a constraint on the timeline (Strength, Distance, Follow Path's Distance, offsets) and rigs eyes / heads by constraining to a **target** (an empty group or Solo) whose position is keyed or moved by a listener ("Align Target" to the pointer); Spine animates IK target bones and keys the constraint's mix; Blender / Maya key Empties / locators and the constraint's influence; Unity Animation Rigging animates target transforms and weights; After Effects ties layers to keyed nulls. Common to all: (1) constraint numbers are ordinary keyable properties, (2) places are keyed on a target object with the ordinary transform tools (2D keys, motion path, gizmo), never as numbers on the constraint, (3) procedural and keyed motion blend by the constraint's strength. Taken: all three - the Constraint track keys any number by name, the Constraint Target widget is the keyed place, Strength / While Animated blend.
- Taken: the stack, Strength, Copy factors, Offset / Keep Starting Offset, Min / Max relative to rest, Screen / Local source space, Distance modes, Follow Path (+ Closest To Target, Speed, Orient, path offset), Look At with limits and keep-upright, Stay Inside with elasticity, Remap (range -> range, curve), and - beyond Rive - Activation and spring Smoothing per constraint. Not taken: IK and bones (2D rigging, out of scope).

### Model
- **`UWidgetConstraintComponent`** ("Constraints"): `Constraints` (instanced `UWidgetConstraint` objects, applied in order), Strength (all at once), Solve In Designer, Show In Designer.
- **Never writes the Render Transform.** `SWidgetConstraintHost` arranges the widget with an extra transform `E` (about its pivot) over its own render transform (`Concatenate(Own, E)` in `MakeChild(..., Pivot)`), and multiplies its opacity. So Widget Animations, the gizmo and Blueprint keep owning the Render Transform; constraints layer on top; hit-testing follows what is drawn.
- **Space**: everything in the widget's layout space (Slate units from its laid-out box's top left; the host is never transformed). A pose (`FWidgetConstraintPose`) is the pivot's place, the angle (degrees, clockwise), scale and an opacity multiplier. Rest = laid out + own Render Transform. `E` is solved so the pivot lands on the pose: `L = Rot(dAngle) * Scale(ratio)`, `T = Pose - Pivot - L * OwnTranslation`.
- **Solver** (`UWidgetConstraintComponent::SolveAll`, on `FSlateApplication::OnPreTick`): every live component, depth first through what each depends on (targets, path / area widgets, constrained parents), so chains (a tail of dots following the cursor) solve in one frame; a cycle is broken where it closes. A constrained target is read where its constraints put it this frame (`SolvedLocalToDesktop`); anything else at its Render Transform as it is now over where it was laid out (`ReadPosedFrame`: its box by its accumulated layout transform, posed about its pivot, through its Slate parent's place on screen - a keyed target is followed this frame, not a frame behind as its last paint's geometry had it); a widget with no Slate parent falls back to its tick-space geometry.
- **Showing a change**: the host invalidates **Layout** when where it arranges its child changes (Paint only for opacity). A Paint invalidation alone left the child at its last geometry under invalidation (the designer's preview, Global Invalidation), so values set by a Widget Animation could show nothing until the widget was rebuilt.
- **Finding the component** (`FindConstraintComponent`, the tracks' `ResolveTarget`): the registered component of that widget whose Slate wrapper is alive first, then any - a leftover registered for the same widget (not yet collected, between rebuilds) no longer takes a track's writes while another is drawn. The pointer: `WidgetAnimInput::ReadPointer` (desktop, or a Diegetic Screen's world pointer); hover / press as the Widget Inputs read them.
- **Per constraint** (`UWidgetConstraint::Apply`): Solve -> what the widget would be at full strength; the change it adds (move, turn, scale ratio, opacity ratio) x Strength x component Strength x **Activation** (Always / While Hovered / While Pressed / Near Pointer within Activation Radius of its edges; faded over Activation Fade; a constraint whose target is missing fades out keeping its last change); **Smooth** springs that change (`FWidgetSpringParams` Duration + Bounce, `AdvanceSpring`), so the widget's own animation underneath is never lagged.
- **Targets** (`FWidgetConstraintTarget`): Widget (by name - dropdown - or Set Target Widget at runtime; Anchor 0..1 on it), Pointer (When Pointer Away: Release / Hold Last), Parent (Anchor), Point (Slate units from the rest pivot).
- **Widget pickers always show**: every Target is its own expandable group (no `ShowOnlyInnerProperties` - with it, the struct's EditConditionHides fields stayed hidden in a UI component's Details, which is why the Widget field showed on Follow Path and not on the others), and no widget-name field is hidden by an EditCondition: Target's Widget, Follow Path's Path Widget / Connection From / Connection To, Stay Inside's and Pointer Parallax's Area Widget. Picking a widget switches what it is for (`PostEditChangeProperty`): Target Kind -> Widget; Area -> Widget; Connection From / To -> Path Source Widget Path Connection; a Path Widget picked on Circle -> Shape Outline (a shape), Widget Path Connection (a layer) or Widget Edge. Parents of the constrained widget are in every dropdown.
- **While Animated** (`EWidgetConstraintWhileAnimated`, per constraint): **Act Over the Animation** (default, as before), **Let Go** (activation 0 while animated - the keys alone place it - fading over Activation Fade), **Follow the Keys** (the animated place is the target in place of the pointer / widget / point - `GetTargetPose` keeps the set target's turn and size; Copy Position goes all the way (amount 1) with its smoothing; Pointer Parallax reads it as the pointer; NearPointer / hover activations count as active - and the stack starts from the authored place (`Context.Rest`), so the keyed offset isn't added twice; limits are then from the authored place). "Animated" = the widget's Render Transform is away from its authored one (`GetAuthoredTransform`: the Widget Blueprint's own widget in the designer via `WidgetEditorHooks::FindDesignerTemplate`, else the widget's archetype), held 0.25 s after it comes back so a key passing through rest doesn't flick the target.
- **Motion paths** draw a constrained widget where its constraints put it - also a widget that isn't animated itself but whose constraints read one that is (`GatherWidgets` adds every constrained widget reading a moved widget; `Rebuild` takes the layers moving what it reads, and `PoseChainAt` hands their poses at each sample to `PreviewTransform(..., PosedWidgets)`, which reads those widgets at that pose via `ReadPosedFrame`): pupils tied to a keyed look target draw their looks inside their eyes. As before: where its constraints put it (`UWidgetConstraintComponent::PreviewTransform`: a stateless solve - `ApplyStateless`, `Context.bStateless`: no smoothing, fades, Travelled, starting offsets, debug or pointer memory written - over the sampled Render Transform), with its Constraint tracks' values at that moment applied for the sample and put back (`WidgetAnimMotionPath.cpp`, `PoseChainAt`); a widget with a Constraint track gets a path like one with a Transform track. So a pupil's keys show inside its eye, and a ball's Path Position track draws the ring it runs.

### Constraint types
- **Copy Position**: Screen (part of the way to the target, per axis: Copy Amount; Keep Starting Offset) or Local (the target's own animated Translation x amount); Offset; Limit Min / Max from rest.
- **Copy Rotation**: Local (target's Render Transform angle x amount: meshing gears with -1) or Screen (its turn as drawn); Angle Offset; limits from rest.
- **Copy Scale**: Local / Screen, per axis, amount of the change, Min / Max scale.
- **Copy Transform**: pinned to a widget (its anchor, turned and scaled with it): Offset in the target's own units, Angle Offset, Keep Starting Offset (as if parented); a pointer / point copies only the place.
- **Distance**: Within (Closer) / Outside (Further) / Exact Distance from the target.
- **Follow Path**: Path Source **Shape Outline** (a shape's outline as drawn - `MakeFrame` + `BuildOutline`, longest contour: an Ellipse ring, a Custom Shape), **Widget Edge** (any widget's box, rounded as drawn, or its ellipse), **Circle** (Radius round the Target, Start Angle), **Widget Path Connection** (a Widget Path Layer's line From -> To: `GetConnectionPath`); Path Offset (along normals, outward on closed paths); Mode **Distance** (Path Position as a fraction or Pixels, + Speed a second; Loop) or **Closest To Target** (projected onto the path - a knob dragged round a dial, a bead on a wire); Orient + Orient Offset; Get Current Fraction.
- **Look At**: Forward Angle (which way it points at rest), Angle Offset, limits from rest, Keep Upright (flips Y while pointing left).
- **Stay Inside**: the Parent or a widget, Area Shape Auto (an Ellipse is round) / Box / Ellipse, Margin, Keep Whole Widget Inside, **Elasticity** (rubber-band edge).
- **Remap (Drive)**: Measure (Offset X / Y, Distance - from edges or pivot, Direction, Target Angle / Scale / Opacity) from From Range to To Range (Clamp, optional curve) -> Drive (Offset X / Y, Angle, Scale, Scale X / Y, Opacity). The macOS-dock magnify, fade-in-as-you-approach, a needle following a slider.
- **Pointer Parallax**: shifts by Depth (and turns by Tilt) with the pointer across the screen (outermost User Widget) or an Area Widget.
- **Values by name** (`WidgetConstraintValues`, Blueprint `Set / Get Constraint Value By Name`, the **Constraint** track's Value): every number and switch a constraint's Details show, named as they show it, a Vector 2D's and a Target's parts after it - "Path Position", "Strength", "Distance", "Copy Amount X", "Offset Y", "Radius X", "Start Angle", "Target Point Y", "Target Anchor X", "Elasticity", "Margin", "Orient" (switches on above 0.5, whole numbers rounded). Names come from the properties (`FName::NameToDisplayString`), so they hold cooked. The old channels (`EWidgetConstraintChannel`: Strength, Path Position, Offset X / Y, Angle Offset, Distance; `Set / Get Constraint Value`) stay for tracks made before. A constraint is found by its Name, or - left unnamed - by its kind's name as the Details show it ("Follow Path", `GetDisplayName`); None: the first. Get Constraint Names lists them.
- **Registration**: the component registers when initialized (`OnInitialize` / `OnPreConstruct`) as well as when its Slate wrapper is built, and stays registered without one (found, not solved), so the Constraint track resolves it in the designer's preview; a value set at design time solves at once (`SolveAll(0)`).

### Constraint Target
- `UConstraintTargetWidget` ("Constraint Target", palette NameTBD): a `SLeafWidget` of Marker Size (16 x 16) that draws a crosshair and ring in the designer (Marker Color; Show At Runtime to see it in a game), Hit Test Invisible, nothing else. Its place is its laid-out box plus its Render Transform, so its **Transform track** keys it: 2D keys with every easing, spring, value input and state machine, its motion path and the gizmo. Point any constraint's Target (Widget), Follow Path's Circle centre, Stay Inside's / Parallax's area, or Pointer Effects' Pointer Widget at it. Set Target Offset (Blueprint) moves it by its Render Translation.

### Recipes
- Ball round a ring: Follow Path, Shape Outline of an Ellipse, Speed 0.25 - or a Constraint track: Add Track > Interaction > Constraint on the ball starts on **Path Position**, from where it is to one lap on (Loop on the track to keep it going).
- **Eyes looking where you key** (the Rive rig): add a Constraint Target, LookTarget. On each pupil: Copy Position -> Widget LookTarget (Copy Amount 1), then Stay Inside its eye (Ellipse, Keep Whole Widget Inside). Key LookTarget's Transform track: both pupils look there - a target outside an eye puts its pupil at the eye's edge toward it - and each pupil's motion path draws its look inside its eye. Smooth on Copy Position makes the eyes dart and settle behind the keys. To follow the cursor between keyed glances: give LookTarget its own Copy Position -> Pointer (While Animated: Let Go).
- Eyes following the cursor with keyed looks on each pupil: on each pupil, Copy Position -> Pointer (Copy Amount 0.15, Smooth, While Animated: Follow the Keys), then Stay Inside the eye (Ellipse, Keep Whole Widget Inside). Key a look on the pupil's Transform track (its motion path shows it inside the eye): it springs there and back to the cursor. Or Look At -> Pointer on an eye graphic that turns.
- Magnetic button: Copy Position -> Pointer, Copy Amount 0.3, Activation Near Pointer (80), Limit +-12, Smooth (Bounce 0.3). Or Pointer Effects' Magnet.
- Dial knob: Follow Path (Circle round the dial, or its Ellipse), Closest To Target -> Pointer (Hold Last), Activation While Pressed.
- Tail of dots: dot 1 Copy Position -> Pointer (Smooth); dot N Copy Position -> dot N-1 (Smooth, slower).
- Label pinned to a moving marker: Copy Transform -> marker, Offset (0, -24), Copy Rotation off.

### Beyond the request (production expectations added)
- From the "work well with animation" ask: any number of a constraint keyable by name (Rive keys any property) with a dropdown of names and of the constraints on the open widgets; a new Constraint track starting on its constraint's main number (a lap of a Follow Path, a Distance); the track's bar and tooltip naming what it animates ("Constraint · Path Position"); the Constraint Target widget (Rive / Spine / Blender's keyed target) with designer marker; motion paths for widgets driven by keyed targets; widget targets followed at their current pose (no frame of lag behind a keyed target); Blueprint Set / Get Constraint Value By Name.
- Let Go as well as Follow the Keys (Rive / Unity rigs blend procedural and keyed motion the same way); the authored place as the rest the followed keys move from; Constraint tracks drawn on motion paths; finding a constraint by what the Details show it as; picking a widget sets what it is for.
- Activation (hover / press / proximity) with fades; spring smoothing that never lags the underlying animation; Local space to mirror another widget's animation; Remap for any pointer- or widget-driven value; parallax; dependency-ordered solving; designer preview with debug lines (magenta: links to targets, paths, limit boxes, distance circles); Diegetic Screen pointers; runtime API (add / find / remove constraints, set targets to widgets made at runtime, reset motion).

### Decisions made without asking
- **Fix and extend the Constraint track rather than replace it**: production tools key constraint numbers on the same timeline as everything else, and the shared timeline (keys, easing, springs, value inputs, state machines) is what a replacement would have to rebuild. 2D places are keyed on a Constraint Target's Transform track (as Rive / Spine / Blender key a target object) rather than as vector keys on the Constraint track, which would need a second key type and give no motion path or gizmo.
- The Constraint track's Value is a name (the property as the Details show it) rather than a new channel enum: it covers every constraint kind, a game's own too, and the rule against appending to old enums. Tracks made before (Value None) keep their Channel.
- Widget fields are always shown and enabled; picking one changes the Kind / Area / Path Source rather than greying the field.
- "Animated" is read from the Render Transform being away from the authored one (no player to ask: any Widget Animation, Blueprint or the gizmo counts), held 0.25 s; Follow the Keys follows the place only (a Copy Rotation following the keys keeps its target's turn).
- Motion paths preview constraints statelessly at each sample (no smoothing), so the path shows where the constraints settle, not their springs.
- Instanced `UWidgetConstraint` objects (each type its own class, a "+" picker in Details, settable from Blueprint by reference) rather than an `FInstancedStruct` list.
- Constraints apply over the Render Transform (an extra transform) rather than writing it, so they never fight animations or the designer.
- Copy Position's Copy Amount means "how far toward the target" (Screen) - the UI meaning - not Rive's multiply-the-coordinate; Local multiplies the target's offset.
- Limits are relative to where the widget rests (UI-friendly), not absolute coordinates.
- Solved on Slate's pre-tick, from geometry of the last paint (no layout pass of its own).

### Still open
- Dragging a key's diamond on a constrained widget's motion path moves the keyed (unconstrained) place by the mouse's move; where a Stay Inside clamps it, the diamond lags the mouse.
- The Constraint track's Value dropdown lists every kind's numbers (a static GetOptions can't see which constraint the track names); a value the named constraint doesn't have does nothing. A customization listing only that constraint's would be tidier.
- Diamonds of a target's keys on the paths of the widgets tied to it (they show on the target's own path); a target's parents' animation on those paths (only the target's own layers are posed per sample).
- A "Look At" mode for Copy Position (pupil offset = direction to target x a radius, without a Stay Inside); a canvas handle to drag a Point target.
- 2D rigging: IK chains, bones, mesh deformation (out of scope, as asked).
- Rive's Scroll constraint (content following a scroll with physics) - the Flow List covers lists; a general one isn't done.
- Path offset on sharp concave corners (simple normal offset); a Follow Path that spaces several widgets along one path (Spine's spacing) - today one constraint per widget.
- A canvas gizmo to set targets / anchors by dragging (today: Details).
- Order between several UI components on one widget (Constraints, Pointer Effects, Drop Shadow each wrap the widget; which is outermost follows the component list).

## Pointer Effects

### How production UIs do it (researched)
- Card tilt (CSS `perspective` + rotateX/Y from the pointer, "VanillaTilt", holographic trading-card demos: tilt + glare + a rainbow foil shifting with the angle), magnetic buttons (translate a fraction toward the cursor with a spring), the "spotlight border" (a radial gradient on the border following the cursor across a grid of cards - Vercel / Linear), shine / shimmer bands following the pointer, Material ripples from the press point, press scale. Taken: all of these; plus gamepad focus as hover (consoles) and a virtual pointer for sticks.

### Model
- **`UPointerEffectsComponent`** ("Pointer Effects"): Preset (named for what sets it off: **Tilt Card Hover**, **Holographic Card Hover**, **Shimmer Hover**, **Magnetic Hover**, **Ripple Click**, Custom - quick starts; Spotlight Border and Lift are gone: `UMETA(Hidden)` kept so old assets load, read as Custom in `PostLoad`, `MakePreset` leaves the effects as set; the hover presets no longer add a press), **Preset Asset** (`UPointerEffectsPresetAsset`, Data Asset "Pointer Effects Preset": Tilt, Magnet, Press, Lights, Ripple, Overlays; **Save As Preset** (CallInEditor), Apply Preset Asset, Copy To Preset Asset; built-in presets leave Overlays as they are), Intensity (all effects; animatable), **Active When** (a condition over every effect), **Tilt** (Max Angle, Press Away / Rise Toward, Perspective, Hover Scale, spring), **Magnet** (Pull, Max Offset, Range beyond the edges, spring), **Press** (Press Scale, spring), **Lights** (`FPointerLight` list: Spotlight / Sheen / Border Glow / Holographic, Show While Hovered / Near Pointer / Always, Color (alpha = strength), Radius, Sheen Angle / Width, Border Width), **Ripple** (Color, Duration), **Overlays** (`FPointerOverlay`: Image (`FWidgetEffectImage` - texture, material or SVG), Placement Fill (cut to the corners) / Follow Pointer (Size, cut to the widget - `ClipPolygon` against the rounded outline) / Follow Pointer (Uncut), Tint, Behind Widget), corners (Match Widget via `ReadCaster`, or Corner Radius), Proximity Range, Hover Fade, React To Focus, **React While Disabled** (default off), **Outputs**, Preview In Designer + Designer Pointer + **Preview Conditions As Met**.
- **Show When** (`FPointerEffectCondition` on Tilt, Magnet, Press, Ripple, every Light and Overlay; Active When on the component): Trigger (`EPointerEffectTrigger`: Default - the effect's own: Tilt / Overlays hovered, Magnet as near (its Range), Press pressed, Ripple each press, a Light its Show -, Always, While Hovered, Near Pointer, While Pressed, While Focused, Condition Only) + an optional named **Condition** (+ Invert). Conditions are answered by, in order: **Set Effect Condition** (Blueprint / C++; Clear Effect Condition), the widget or its User Widget implementing **Pointer Effects Condition** (`GetPointerEffectCondition(Name, bMet) -> answers`, asked every frame, once per name), then built-ins **On / Off** (a Context Menu Button's Enabled toggle - `GetEnabledState`) and **Usable / Disabled** (Is Enabled up the parents). Each effect's gate eases over Hover Fade (lights and overlays) or its spring (tilt, magnet, press).
- **Overlay materials** get every frame: the Outputs' Pointer (U, V, hover, pressed), Pointer Hover and Pointer Velocity (x, y, speed, proximity) names, plus PointerProximity, PointerPressed, EffectStrength (gate x Intensity) and WidgetSize; UVs 0..1 over the widget (Fill) or the square (Follow Pointer); one instance per overlay (`FWidgetEffectMaterials` on each surface).
- **Fixes ("buggy with Context Menu Button states")**: focus counts as hover only when navigation put it there (`GetKeyboardFocusedWidget()->HasAnyUserFocus()` not `EFocusCause::Mouse`) - a clicked button keeps focus and stayed "hovered" (tilted, lit) after the pointer left, which read as the effect sticking on the On state; hover is kept while the pointer stays inside the laid-out box (`bWasOver`), so a tilted, leaning or sunk widget whose drawn edge moves out from under the pointer doesn't flicker - nor its button's Hovered / Normal states with it; a press is caught as it happens (`OnPreviewMouseButtonDown`, never handled) and held 0.12 s, so a click quicker than a frame still sinks and ripples, at the press point; a rebuilt widget's host takes over the old one's motion (`CopyMotionFrom`) instead of snapping to rest; a disabled widget lies still (React While Disabled off); the component registers on initialize (the Pointer Effects track in the designer's preview).
- **Slate**: `SPointerEffectsHost` (measures the pointer on its own untransformed box, springs everything, arranges the content with the lean and lift / press scale about its middle) -> `SShapeBox` (the tilt: Angle + Perspective; flat - no offscreen cost - at rest) -> overlay of a **behind surface** (`SPointerEffectsSurface` with Behind: overlays set Behind Widget), the widget, and the front `SPointerEffectsSurface` (lights, ripples and overlays, tilted with it, hit-test invisible). Lights are per-vertex colors on the widget's rounded outline (fill or inside rim) cut into a grid (4..16 units) and cached by size and corners.
- **Pointer**: `WidgetAnimInput::ReadPointer` (desktop or Diegetic Screen), `IsPointerOver` / `IsPointUnder`; navigation focus (descendants) = hover at the middle; Set Virtual Pointer overrides; pressed = a left press that started over it, still held. Velocity eased (12/s). Runtime only: in the designer it is posed once at Designer Pointer, hovering (and again whenever an animation sets the pointer, or every frame while it follows a widget).
- **Pointer Source** (`EPointerEffectsPointerSource`: Pointer (default) / Widget) + **Pointer Widget** (always shown; picking one makes the source Widget; Set Pointer Source Widget at runtime): the pointer is that widget's middle - a Constraint Target whose Transform track is keyed sweeps the tilt, lights and overlays along its motion path. Over while inside the box, near by distance (Proximity Range), like a pointer; stepped on a timer in the designer too while following one.
- **Animated inputs** (`EPointerEffectsInput`: Pointer X, Pointer Y (0..1 across / down), Hover (0..1), Press (above 0.5; rising past it is a click with a ripple); `Set / Clear / Get Animated Input`, kept on the component so a rebuilt widget keeps them): over whatever is read - the real pointer, focus, Virtual Pointer, Pointer Widget. With X or Y set the other axis is the middle and the widget counts as hovered while the point is inside it; Hover sets the hover amount (gates follow it, so 0.5 shows half a tilt and half the lights). Honoured in the designer (no ripples there - nothing ages) and ignored while the widget lies still disabled.
- **Outputs** (`FPointerEffectsOutputs`, every change; shown as its own group): materials (Image / Border `GetDynamicMaterial`, a shape's material paint - the widget and, with Include Children, through panels and User Widgets 6 deep): vector Pointer (U, V, hover, pressed), scalar Pointer Hover, vector Pointer Velocity (x, y, speed, proximity); shapes' Radial Gradient centers (fill and stroke); a Widget Animation Vector 2D value (-1..1) and a hover value (`SetWidgetAnimationValue*`); state machine inputs (Vector 2D, hover Number, proximity Number, any machine); `On Pointer Effects Updated`; `Get Pointer State`.
- Channels (`EPointerEffectsChannel`: Intensity, Tilt Angle, Magnet Pull, Light Strength) - Set / Get Effect Value, the **Pointer Effects** track's Effect Setting.
- `FindPointerEffects` prefers the registered component whose Slate wrapper is alive, as `FindConstraintComponent` does.

### Also for animations
- **Pointer Distance and Motion** value input (`FWidgetAnimInput_PointerMotion`, offered on every value track): Distance, Proximity (Range), Direction (degrees), Speed, Velocity X / Y - beside the existing Pointer Position, Hover / Press / Focus, Drag and Scroll inputs.

### Beyond the request (production expectations added)
- From the "the track isn't useful" ask (researched: card-reveal sheens, attract modes, console UIs showing the selection hovered, Rive driving effects from timeline-keyed inputs): the track animates the pointer the effects see - Pointer X / Y, Hover, Press with its ripple - and a new track starts as a sweep across; Pointer Source: Widget for keyed 2D sweeps on a Constraint Target with a motion path; Blueprint Set / Clear / Get Animated Input and Set Pointer Source Widget.
- Overlays with any material handed the pointer every frame (designers build effects in a material, no Blueprint); Show When per effect with named conditions from code, an interface, or built-ins (a button's toggle, disabled); Active When over all; preset assets; Behind Widget overlays (glows under a card); React While Disabled; designer preview of condition-gated effects.
- Gamepad / keyboard focus and a virtual pointer (stick) so console UIs get the same polish; Diegetic Screen pointers; proximity effects that start before the pointer arrives; presets; designer preview; outputs to materials / shapes / animations / state machines with no Blueprint; press ripples; animatable intensity.

### Decisions made without asking
- The Pointer Effects track animates the effects' **input** (where the pointer is, how hovered, pressed) rather than more of their settings: the effects then do everything they do for a real pointer (springs, gates, lights, outputs), which is what a showcase or a selected state needs. Its old settings stay as Effect Setting. A new enum (`EWidgetAnimPointerEffectsValue`) rather than appending to `EPointerEffectsChannel`.
- An animated axis without the other puts the other in the middle (not the real pointer's): a keyed sweep looks the same wherever the mouse is.

## Interaction tracks (Widget Animations)
- **Constraint** (`FWidgetAnimConstraintParams`: Constraint - its Name or its kind's ("Follow Path"), dropdown; None the first -, **Value** - any number by name (see Values by name), dropdown -, Channel (shown while Value is None: tracks made before), Start / End Value) and **Pointer Effects** (`FWidgetAnimPointerEffectsParams`: **Animates** - Effect Setting / Pointer X / Pointer Y / Hover / Press -, Channel (Effect Setting), Start / End Value), listed under **Interaction**. Target: the Track Group's widget's component, or the first widget inside it with one. Baselines carry the name, value, channel or pointer part (and, for a pointer part, whether it was set: put back unset) and are put back by value. Like every registered type they can be keyed, eased, sprung, value-driven (fed by a Value Input - the pointer) and played by state machines.
- **New tracks** (`FWidgetAnimEvaluator::InitializeNewTrack`, called by `SWidgetAnimTimeline::AddLayer` for a registered type added from the menu, with the group's preview widget): a Constraint track on a Follow Path starts on Path Position from its value now to one lap on (100 px in Pixels), on a Distance on Distance (+40), else Strength 0 -> 1; a Pointer Effects track on Pointer X 0 -> 1. Saved tracks never pass through it, so struct defaults keep their old meaning.
- **Motion paths** pose each sample with the value the track names (Value, else Channel) through `SetTrackValue` / `GetTrackValue` - the same calls the track plays through. (Before fix2 they read the Channel alone, so a Path Position track was drawn as a Strength fade: a straight line from where the widget is laid out to the path.)
- Constraint tracks start **Linear** (`PrefersLinearEasing`): eased out, two laps in two seconds ran most of the way in the first moments. A track that can't write (no such constraint or value) logs a warning once (LogWidgetAnimInteraction), naming the constraints the widget has.
- The track's bar names what it animates after its type ("Constraint · Path Position", from `GetTrackSummary`, for non-cue registered types) and its tooltip has an Animates row.
- Unverified: the player treating a component (not a widget) as a track's resolved target throughout (baselines, previews).
