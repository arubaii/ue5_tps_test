# Widget Animations (architecture, key workflow, Dope Sheet)

## Widget animation architecture (short)
- **Data**
  - **Track Group** is the UI name of what the code still calls a layer group (Workflow v1 renamed it everywhere it is shown - menus, Details, tooltips, transactions, scripts' messages, AI docs - because "Layer" now means a state machine layer). Code identifiers are unchanged: `FWidgetAnimLayerGroup`, `UWidgetAnimPresetAsset::LayerGroups`, `FWidgetAnimLayer::LayerGroup`. An unnamed group now reads **"Track Group N"** (`FWidgetAnimLayerGroup::MakeDefaultName`); names stored under the old default "Layer Group N" (a state machine use's target rows, `PreviewTargetPaths`, a layer's Mask Targets / Measured On) are still found: `FWidgetAnimLayerGroup::UpgradeLegacyName` / `MakeLegacyDefaultName` / `IsSameTargetName` (exact name first, so a group named "Layer Group 2" by hand still matches).
  - A Track Group's `PreviewTarget` is shown as **Target Widget** (MotionPaths v1 fix1); older sections of this handoff call it Preview Target.
  - `FWidgetAnimLayer` is a track and `FWidgetAnimSettings` is its played form (`WidgetAnimLibrary.h`).
  - The track type is `EWidgetAnimType`: Fade, Scale, Slide, Rotate, Pulse, Shake, MaterialScalar, MaterialVector, Custom, Transform, ShapeBox, Shape, **Design** (new, appended last).
  - Value-key tracks use `FWidgetAnimValueKey` (Value, plus `ValueY` for Scale).
- **Keyframed tracks**
  - Transform, ShapeBox, Shape and Design use `FWidgetTransformAnim` (`WidgetAnimTransform.h`), with `EWidgetKeyframeContent` Transform/ShapeBox/Shape/Design.
  - Each `FWidgetTransformKeyframe` holds a Transform, a ShapeBox, or `ShapeValues` (an `FInstancedPropertyBag`).
  - Per-key "Use Authored" flags: `bUseAuthoredShape` (Shape, Shape Box and Design) and `bUseAuthoredTransform` (Transform; new, default false).
- **Evaluators**
  - Registered `TWidgetAnimEvaluator<Params>` types (`WidgetAnimEvaluator.h`) handle cues (Sound, Event, Play Animation), shapes and design.
  - They're played through authoritative writes on a channel, with baselines captured and restored.
  - Editing hooks (NiagaraUI fix3): `RefreshParams(FInstancedStruct&)` - called by `SWidgetAnimTimeline` after every Selection-panel edit of a Custom track (`OnProxyEdited`: the track, each represented track and the proxy; the shadow path: the track), to bring derived settings up to date; `GetParamsLayoutHash` - folded into `ComputeLayoutSignature`, so a type whose rows come from an asset (a property bag) gets its Selection panel rebuilt when they change. Tracks are only refreshed when edited (never just by viewing), so unedited assets stay untouched.
- **Editor**
  - `SWidgetAnimTimeline` covers the track editor, Selection / details panel, context menus, header and save.
  - `SWidgetAnimGraphEditor` is the curve editor.
  - `WidgetAnimMotionPath.h/.cpp` draws the motion paths on the designer's canvas (see Motion paths).
  - `IWidgetAnimPanelSource` / `FWidgetAnimAssetPanelSource` (`WidgetAnimPanelSource.*`) handle timelines vs. saved animation assets, and saving.
  - Selection edits go through `UWidgetAnimPresetSelectionShadow` and `CopyEditedLayerProperty`.
  - Registered types' settings are laid out by `FTypeParamsDetails` (an `FInstancedStructDataDetails`). Since NiagaraUI fix4 a settings field can carry `meta = (ShowWhen = "Action=BurstAtTarget|Play", EnableWhen = "bUseWidgetSystem=false")`: comma-joined terms that must all hold, each naming an earlier sibling field and its allowed values separated by `|` (a bool's true/false, an enum's value name, read with `GetValueAsFormattedString(PPF_None)`), applied as the row's Visibility / IsEnabled. **Use these instead of EditCondition on an `FInstancedPropertyBag` inside Type Params:** a bag under an engine EditCondition comes back read-only (the same quirk the Shape key rows already avoid by not showing fields rather than edit-conditioning them).
  - Widget pickers (TargetLabels v1): the first option of a Track Group's / track's Target Widget, and of the state machine preview's Plays On and per-group rows, is **"(this widget)"** (stored as None) - `WidgetAnimTargetOption.h` (`ThisWidget()`, `IsThisWidget`, `FromPath`, `ToPath`). Never compare options against `"None"` again. The component's own `FWidgetAnimGroupTarget::ThisWidget` ("(This Widget)", a stored value) is mapped to it in `WidgetAnimationComponentDetails`. Scripts still accept `None`, and now "(this widget)" too.
- **Transport and controls pill** (`SWidgetAnimTimeline::MakeTransport`, fix2 of WidgetGizmo v1): the pill shows **one set at a time** in an `SWidgetSwitcher` - Preview Controls (Loop, Ping Pong, Invert | Speed - **one divider**, Workflow v2) or Track Controls (Snapping, Linked Edges | **Auto Key**, Motion Path + Paths Only - one divider, Auto Key left of Motion Path; the Keyframe Only toggle is gone, see Dope Sheet) - switched by a small segmented button beside it (two icons, `WidgetAnim_PreviewControls.svg` / `WidgetAnim_TrackControls.svg`, the shown one lit), remembered in `UWidgetAnimEditorSettings::bControlsShowTrackControls` (config, no Details row). The time sits right of the pill (group: switch, pill, time). Stacked (under the tracks list): the transport buttons centered on the first row, the group centered under them; one row (along the bottom): the group on the left, the transport centered. Auto Key icon `WidgetAnim_AutoKey.svg`, tooltips `AutoKeyTooltip`, `PreviewControlsSwitchTooltip`, `TrackControlsSwitchTooltip`.
- **Spring presets** (editor, `WidgetSpringPresets.h/.cpp`): `FWidgetSpringParamsCustomization` on every `FWidgetSpringParams` - a Preset menu (built-ins, all Duration and Bounce, by feel: Smooth, Quick, Snappy, Gentle, Bouncy, Wobbly, Jelly, Interactive, Slow, Heavy; the project's own; Save As Preset; Remove Preset), what the spring matches, and a summary (visual duration, damping ratio, settle time). With Show Only Inner Properties (track springs) the menu is a row of its own. Project presets: `UWidgetSpringPresetSettings` (Project Settings > Plugins > Spring Presets, `config = Editor, defaultconfig` - DefaultEditor.ini, shared by the team).
- **Palette and strings**
  - Colors and tunables: `NameTBDEditor/Public/NameTBDColors.h`.
  - Tooltip strings: `NameTBDEditor/Public/NameTBDTooltips.h`.
- **Editor settings**
  - `UWidgetAnimEditorSettings` holds track colors, snapping, linked edges, frames display and preview FPS.

## Key workflow (Workflow v1)
- **Why:** with hundreds of keys and dozens of timelines, editing track by track and saving each timeline as an asset before a state machine can use it was the overhead. What production tools do, and what was taken from each:
  - **After Effects:** every property is its own row with its own keyframes; select many keys across properties and type or drag once to change them all; keyframe navigator. -> Key Values (only the values a key changes), multi-select value boxes, one drag/typed value edits them all.
  - **Blender:** Dope Sheet (keys only, no bars, box-select and move keys); any number field takes Python-like math and relative edits; Alt-drag edits every selected field. -> **Keyframe Only** mode; typed math (`+8`, `*2`, `x * 2 + 1`); a drag of one picked box moves every picked box.
  - **Rive / Unity Animator / UE Animation Blueprint:** drag an animation from the asset list onto the state machine graph and a state is made for it. -> drop Widget Animations (Content Browser) and this Widget Blueprint's timelines (new **Animations** list) onto the graph.
  - **Sequencer / Figma:** a track's start shown as a time, not a chain of offsets; the class icon of what a track binds to on its row. -> **Start Time** in place of Starts + Delay; the target widget's class icon on a Track Group's row.
- **Track Properties** (`FWidgetAnimSelectionDetails::CustomizeLayer`, multi: `FWidgetAnimMultiLayerDetails`, animation tracks: `CustomizeAnimationTrack`): no **Anim Type** row (a track is the type it was added as; `AddTypeNameRow` removed), no **Starts**, no **Delay**, one **Name** row (at the top, before Track Group; TrackName with its type as hint - the duplicate after Target Widget is gone). **Start Time** (`WidgetAnimTimeline::AddStartTimeRow`): where the track (or the earliest of several) starts, played seconds (a percent on a percentage timeline); typed or dragged; `SWidgetAnimTimeline::GetLayersStartTime` / `SetLayersStartTime(Layers, Seconds)` (moves them together, every other track stays put: `ApplyLayerSpans` rewrites each Delay against its Starts, exactly as a drag does) / `BeginStartTimeDrag` / `EndStartTimeDrag` (one transaction, spans taken at the press). Starts / Delay stay in the data (scripts, AI tools, runtime unchanged). **Duration** (and a percentage timeline's Duration) is a spin box now: `WidgetAnimTimeline::FSpinEdit` (one transaction per drag, `InteractiveChange` steps, a final `SetValue`).
- **Start and end keys** (`UWidgetAnimEditorSettings::bShowEdgeKeys`, "Start And End Keys", default on; `ShowsEdgeKeys()` = it; `GetKeyTimes` also shows them on a Dope Sheet): `SWidgetAnimTimeline::GetKeyTimes` gives every start-to-end track its start and end as keys always (before: only once it had a key between, or in the Graph Editor), so the Track Editor draws them and a click shows that value. They still can't move as keys (`CanMoveKey`); `SWidgetAnimTimelineTracks::GetEdgeOfKey` makes `HitTest` report such a key with its edge, and a press there picks the key (unless several tracks are picked and this one among them - then they resize together) and, dragged, resizes the track from that edge (`ELayerDrag::ResizeStart/End`, unchanged). A picked start/end key among several picked keys drags the keys instead (the edge is ignored). The motion paths now draw those edges as ordinary key diamonds (they read `GetKeyTimes`).
- **Keyframe Only** (Workflow v1) was **removed in Workflow v2** (setting `bKeyframeOnly`, `SetKeyframeOnly`, `KeyframeOnlyTooltip`, `WidgetAnim_KeyframeOnly.svg`, the pill toggle): replaced by **Dope Sheet** timelines - see "Dope Sheet (Key Mode, Workflow v2)" below. Its lane painting and lane press were kept and now draw/serve Dope Sheet rows.
- **Key Values** (`WidgetAnimKeyValues.h/.cpp` - the model; `SWidgetAnimKeyValues.h/.cpp` - the widget):
  - A track's **channels**: every number its keys hold - Fade Opacity; Scale X/Y; Slide Distance; Rotate Angle; Material Scalar Value; Material Vector R/G/B/A; a registered type's value label and/or color R/G/B/A; Transform Translation X/Y, Scale X/Y, Shear X/Y, Angle; Shape Box / Shape / Design every number down through their structs (`CollectFields`, as the Graph Editor gathers its field channels; enums, bools, brushes left out; at most 160). Keys counted as the Track Editor does (start-to-end tracks: point 0 = start value, last = end value). `Read` / `CanWrite` (why not: a Slide's end, a registered type's start/end - its settings, a Shape key using the authored shape) / `Write` (a Transform key using the authored transform is switched off at identity, the pose it stood for - the gizmo's rule) / `IsAltered` (differs from the key before or after; tolerance 1e-4 relative) / `IsKeyAuthored` / `Evaluate`.
  - **Typed math** (`WidgetAnimKeyValues::Evaluate(Text, Current)`): numbers, `+ - * / % ^`, parentheses, unary minus (`-2^2` = -4), `x`/`v` = the box's own value; leading `+8`, `*2`, `/4`, `^2` and `+=`/`-=`/`*=`/`/=`/`%=`/`^=` are relative; a plain `-8` is minus eight. Tested outside the engine (30 cases).
  - **Timeline API:** `FValueCell {Layer, Key, Channel}`, `GetKeyChannels(Layer)` (cached per layer index by type + bag layout + registered struct: `KeyChannelCache`), `GetKeyValue`, `CanSetKeyValue`, `SetKeyValues(Cells, Values)` (one transaction, or a drag step), `BeginKeyValueDrag` / `EndKeyValueDrag`, `GetSelectedValueCells` / `SetSelectedValueCells` (cleared by every `RefreshDetails`), `IsShowingAllKeyValues` / `SetShowAllKeyValues` (refreshes next tick), `MakeKeyValues(Keys)`.
  - **The widget:** keys grouped by track (at most `MaxTracks` 12, then a note). One key: rows of name + box. Several: a table per track - header of channel names, a row per key (`SListView`, so hundreds of keys only make the rows in view; 320 px tall at most; scrolls sideways when wide), a box only where that key alters the channel; **Show All Values** fills every cell (unaltered ones dimmed). Since Workflow v2_fix5: keys picked (a single key, several keys) always list every value they hold (unaltered dimmed) and have no Show All Values; only a picked track's **Keys** list (`SWidgetAnimKeyValues::ForTracks`, `MakeKeyValues(Keys, bForTracks)`, `AddKeyValuesRow(..., bForTracks)`) lists altered values with the Show All Values checkbox (`bListAll`). The "Ctrl+click boxes..." hint line and its tooltip are gone (Ctrl/Shift+click and typed math still work). The key label (Start / End / Key N + time) moves the playhead to it. Cells (`SWidgetAnimValueCell`): `SNumericEntryBox<double>` with `FInterface` (keeps what was typed; text left as shown is no edit, so clicking in and out never copies a value into the other picked boxes); `OnPreviewMouseButtonDown`: Ctrl/Cmd toggles the box in the pick, Shift picks a run down its column, a plain press on an unpicked box picks it alone; typed: the expression worked out for every picked box against its own value; dragged: every picked box moves by the same amount; framed `KeyValueCellSelected` when picked. **Dragging (Workflow v2_fix6_fix6):** as a Details panel number - no Min / Max Value (unset, see the standing rule), a bar only for a channel with `SliderMin` + `SliderMax` (colors and Opacity 0-1, a setting's UIMin/UIMax or ClampMin/ClampMax), else the spin box's own free drag (faster the bigger the number, Shift x10, Ctrl x0.1); `Delta` 0 (1 for a whole number), no `LinearDeltaSensitivity`; `FChannel::DragStep`, `GuessDragStep` and `MakePointChannel`'s step argument are gone. **Choice boxes** (an enum - a corner's Bevel / Chamfer): the drop-down's entries are widgets (`MakeChoiceMenu`: own `Menu.RadioButton` mark + `Menu.Label` text, Button entries) carrying the panel's styled tooltip "Name: description" - the plugin's line from `NameTBD::Tooltips::WidgetAnimEditor::KeyChoiceDescription("<Enum>.<Entry>")` (Bevel, Chamfer so far), else the entry's own enum tooltip.
  - **Where:** a single key's Key category starts with its Key Values (Transform: the Transform struct row is gone - all of it is there; Shape Box / Shape / Design: their full settings folded under **All Shape / All Design Settings**; value keys: the Start/End/Value/Value Y rows are gone, a color keeps a folded **Color Picker**, a Slide's start keeps Direction, a registered type keeps its settings). A picked track gets a **Keys** category (every key, `WidgetAnimTimeline::GetAllKeys`); several picked tracks too; several picked keys: under the curve controls in the several-keys panel (`KeyValuesHost`, filled by `RefreshDetails`).
- **Track Group icon:** the group row in the Animation Tracks list shows its target's class icon (`SWidgetAnimTimeline::GetGroupTargetIcon`: the preview's widget, else the Widget Blueprint tree's by name, `(this widget)` = the User Widget; `FSlateIconFinder::FindIconBrushForClass`, cached per group by target + preview; `GroupTargetIconSize` 14).
- **State machine drops** (`SWidgetAnimStateMachineEditor`):
  - `SWidgetAnimMachineDropZone` lies over the graph (in an `SOverlay` with `GraphHost`), visible only while a drag carries Widget Animations (`WidgetAnimMachineAnimationDrop::IsDraggingAnimations`), so it takes the drop before the graph panel (no reliance on the engine's `DroppedAssetsOnGraph` signature). Accepts `FAssetDragDropOp` with `UWidgetAnimPresetAsset`s (state named without `WA_`) and `FWidgetAnimMachineAnimationDragOp` (timelines).
  - **Timelines** and **Animations** sections (in the Inputs panel, after Widget Inputs - split in Workflow v2): Timelines = this Widget Blueprint's timelines (`SWidgetAnimMachineAnimationRow` with the timeline / Dope Sheet icon: drag, or double-click to add at the view's middle; `TimelinesPanelTooltip`; relisted when the timelines change - `ComputeTimelineListSignature` in `Tick`). Animations = every Widget Animation asset in the project (`AnimationAssets` from the asset registry, not loaded; `SSearchBox` filter `AnimationAssetFilter`, case-insensitive name contains; at most 200 rows, then "N more"; rows are `SWidgetAnimMachineAnimationRow` with `.Asset(FAssetData)` - dragged as an `FAssetDragDropOp`, so the drop zone takes it exactly as a Content Browser drag; double-click loads and adds the state, named without `WA_`). Gathered again on the tick after the registry reports a Widget Animation added / removed / renamed (`OnAnimationAssetsChanged` -> `bAnimationAssetsDirty`; handles removed in the destructor). Every left-panel section folds on its heading (`MakePanelSection(..., IsFolded, OnToggleFold)`, `FoldedPanelSections` by heading - Inputs, Widget Inputs, Timelines, Animations, Preview; not saved).
  - `AddStatesForAnimations(Animations, Names, ScreenPosition)`: one transaction, states side by side 260 apart from the drop point (`GetViewLocation` + local / zoom), selected after. `ResolveAnimationForMachine`: an asset as it is; a timeline as it is in the Widget Blueprint's own machine (same package - it plays timeline edits at once); in a machine asset, `WidgetAnimTimelineAssets::SaveAsAsset` (its Saved Asset brought up to date, or `WA_<name>` made in the Default Save Folder / beside the WBP and remembered; saved to disk; a notification says so).
  - **Save State Machine To / Save** (`SaveDraftTo`, `SaveDraftToSavedAsset`): after the copy, `WidgetAnimMachineAnimationDrop::ReplaceTimelinesWithAssets` swaps every timeline the copy plays (states, Random Variations, legacy Random Animations, Blend Samples, transition animations) for its saved asset - an asset can't hold the WBP's private objects.
  - `WidgetAnimTimelineAssets` (`WidgetAnimPanelSource.h/.cpp`): `FindTimeline(Animation, OutBlueprint, OutIndex)` (outer is the WBP's `UWidgetAnimTimelinesExtension`), `SaveAsAsset(Blueprint, Index)`. `FWidgetAnimBuilderToolbar::OpenAnimationInPanel` opens a timeline in Animation Timeline mode (a state's Open Animation / double-click).

## Dope Sheet (Key Mode, Workflow v2)
- **What:** a timeline is made either as a **Track Sheet** (tracks from a start to an end - called "Timeline" before fix5; menu **New Track Sheet**, empty panel **New Track Sheet** button, own icon `Resources/WidgetAnim_TrackSheet.svg` / `FNameTBDStyle::TrackSheetIcon`, bars on lanes) or as a **Dope Sheet** - chosen when it is made (timeline menu **New Dope Sheet**, or the empty panel's **New Dope Sheet** button; `IWidgetAnimPanelSource::CreateTimeline(Name, CopyOf, bDopeSheet)`), kept for its life (no toggle; a duplicate is what it copies). Each timeline is named with its kind's icon (`TrackSheetIcon()` / `DopeSheetIcon()`, `TimelineKindIconName(bDopeSheet)`: picker, timeline menu list, New entries, State Machine Timelines); the clapper `TimelineIcon` stays for "a timeline" in general (mode button, Script area). Stored as `UWidgetAnimPresetAsset::bDopeSheet` (`UPROPERTY()`, **runtime since fix5** - no longer `WITH_EDITORONLY_DATA`), copied to saved assets by `CopyTimelineInto`, so an asset opened in Edit Existing Asset is a Dope Sheet too. Rows are tracks, keys are their keys; **one playback difference (fix5):** `FWidgetAnimEntryBase::BuildSettings` sets `FWidgetAnimSettings::bHoldStartPose` on every own track of a Dope Sheet, so a row shows its first key's value before it gets there (as any dope sheet) instead of the widget as authored - a row of one key holds it for the whole animation. Before, a row snapped from authored to its key when reached. Helper `WidgetAnimDopeSheet::IsDopeSheet(Animation)` (`NameTBDEditor/Private/WidgetAnimDopeSheet.h`); `SWidgetAnimTimeline::IsDopeSheet()` (never the compact panel).
- **How production tools do it (researched):** Blender's Dope Sheet / Action Editor and Spine's Dope Sheet are their own mode of the timeline - rows are channels (an object's property), keys are diamonds colored by channel/timeline type (Spine colors keys by type), there are no clip bars, and keys are inserted anywhere on a row; Unity's Animation window lists properties on the left with a per-row key toggle and previous/next key buttons (After Effects' keyframe navigator is the same idea); interpolation is set per key/segment. Taken: type-colored keys, rows with no sections, keys placed before/after anything, per-row navigator, per-segment easing.
- **Rows:** each row is one kind of key (a track of that type) on its group's widget. Its first and last keys are its start and end: dragging, deleting or adding before/after them rewrites the track's start, length and key fractions so every other key stays put on the time axis (`SetDopeKeyTimes(Layer, Seconds)` - played seconds on the axis; value tracks: fractions; keyframed tracks: curve times from the first key, first key at local 0; then `ApplyLayerSpans` with `TrackRuns[Layer]` updated first). A row starts as **one key** - its two points a hair apart (`MinLayerSeconds`) holding the same values (`IsSingleKeyRow`, read off `GetPointTimes`) - shown, picked, counted and listed as ONE key everywhere (`GetKeyTimes` trims it to one, fix2; Dope Sheet keys are named "Key N", never Start / End); a value or gizmo edit of either point is mirrored onto the other (`SyncSingleKeyRow`, from `SetKeyValues`, `UpdateGizmoKeying`, `UpdateKeyPositionDrag`). Spring-timed and derived-length rows keep track behaviour (`CanDopeKeys` false).
- **Add Key** (`AddLayer` in a Dope Sheet, no preset): where the menu was opened, or at the playhead; `Duration = MinLayerSeconds`; keyframed rows rebuilt as 2 curve keys (via `DeleteKey(GetFirstKeyHandle())` + `AddKey`, handles kept) with key 0 copied to key 1; since fix5 no key Uses Authored (`bUseAuthoredTransform` / `bUseAuthoredShape` false - identity transform, the box's outline, the shape/design settings seeded by `SetShapeKind` / `SetDesignKind`), so every field is editable and the key still changes nothing until edited; value rows copy their end to their start (the widget at rest). The new key is selected.
- **Keys:** `AddDopeKey(Layer, Seconds)` (between keys: `AddKey`; before the first / after the last: the edge point becomes an inner key holding its value - a value track's `StartCurve` moves to it - and the new edge holds the same value; keyframed: curve and keyframe times shifted first when before, so `SyncKeysToCurve` matches them, the new keyframe a copy of its neighbour; a single-key row spreads its two points). `AddKey` routes outside / single-key cases there. `RemoveDopeKey` (no transaction): inner keys as before; first/last hand their place and value to the next one in (`CopyRowPoint`, via Key Values channels / whole keyframes); two keys leave a single key; a single key returns true and `DeleteKey` / `DeleteSelectedKeys` delete the row. `CanMoveKey` / `CanDeleteKey` true for any key of a dope row. Key drag: `BeginKeyDrag` records each row's keys on the axis (`DopeDragTimes`, `bDopeKeyDrag`; a single-key row carries both points); `UpdateDopeKeyDrag` moves them by one delta (snap, kept `MinLayerSeconds` from fixed neighbours, never before 0) and calls `SetDopeKeyTimes` per row.
- **Track Editor:** rows are their keyframes only (fix3: no lane, section or line between keys; between keys is empty space; keys sized by DEVELOPER ONLY "Dope Sheet Key Size", hit radius half of it + 2) - keys in the row's type color (`DopeKeyDarkLuminance` 0.12: below it the outline is white, `DopeKeyLightOutline`; selected keys keep their color with the orange outline + glow; `DopeKeyHoverLift`, `DopeKeyPressedDim`). No edges: `Hit.Edge` ignored, no resize cursor. A press on a lane picks the row and boxes keys. Right-click on a row's line off its keys opens the row's menu with **Add Keyframe Here (time)** - before the first key or after the last too. Auto Key (gizmo) keys a dope row anywhere along it (`FindGizmoKeyTracks` skips the run window for `CanDopeKeys` rows). fix5: the Key Group line draws its band again, from the group's first key to its last (`GetGroupKeySpan`), keys summarized over it; a hidden row draws an eye over each key (`DopeKeyHiddenGlyph*`); cue keys wear their cue's icon inside (`GetCueTrackIcon`, the same icon a cue track's name has; `DopeKeyIconScale`, dark on light keys / light on dark); a Sound key draws a bar from the key for as long as its sound plays (`FWidgetAnimSoundCueEvaluator::GetSoundLength`, pitch included; `DopeSoundBar*`); scrubbing by hand (ruler press/drag, range click) is pulled onto the nearest key within `ScrubKeySnapPixels` 6 px (`SnapScrubToKeys`, `SWidgetAnimTimelineTracks::ScrubSecondsAt`); transport Previous/Next Key (`StepToMarker`) steps key to key only - no row edges or pass ends.
- **Keys viewer** (the Animation Tracks list on a Dope Sheet; header "Keys", `ComputeListSignature` includes `IsDopeSheet()`): each row - group band, the type's diamond (`SWidgetAnimKeyGlyph`), the type name (no rename), its key count, and `MakeKeyRowControls`: previous key (`StepRowKey` - since fix5 the previous/next key of the whole sheet, every row's, picked with `SelectKey`; at one moment this row's key wins), a diamond filled while a key of the row is at the playhead - click to take it off or place one (`ToggleRowKeyAtPlayhead`, `KeyRowAddTooltip` / `KeyRowRemoveTooltip`), next key; then pin / eye / lock as tracks have.
- **Wording:** rows are "Key"s, the diamonds "Keyframe"s: Add Key (`AddDopeKeyTooltip`; only types with keys - no Pulse/Shake, no Insert Existing Widget Animation, no From Preset), Hide / Show / Pin / Focus / Invert / Lock / Duplicate / Delete / Cut / Copy Key(s), Collapse Keys (default name "Collapsed Keys"), Delete Keyframe, Curve To Next Keyframe, "N Selected Keys", Selection title "... key", Selection panel **Key Properties** / **Key Values** (no Name row, no Preset row).
