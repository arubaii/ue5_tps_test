# Search

Files: `Source/NameTBD/Search/` - `SearchBar.h/.cpp` (the Search Bar widget, its style, style asset, history save), `SearchLibrary.h/.cpp` (matching), `SearchableItemInterface.h` (what an item is found by), `W_SearchBarBase.h/.cpp` (the hand-built base, kept).

## Search Bar (`USearchBar`, "Search Bar", palette NameTBD)
- **Why:** the old way needed a Widget Blueprint child of `UW_SearchBarBase` with an Editable Text Box named exactly `SearchText` (plus optional `FilterBox` / `ClearButton`), and every consumer wiring On Search Changed to its own filtering. The Search Bar is a `UWidget` that builds its own Slate: placed, it works.
- **Slate:** `SSearchBarHost` (`SCompoundWidget`; `OnFocusChanging` reports focus coming in / leaving, the suggestions popup counting as inside - `AlsoInside`) > `SMenuAnchor` (Combo Box placement, Use Current Window - the suggestions) > `SBorder` (Background / Hovered / Focused brush by state, Padding) > a row: search icon (`SBox`, content set in `SynchronizeProperties`: the style's `FMenuImage` through `SMenuImage` - texture, material or SVG - or the vector `SSearchBarGlyph`), the field (`SEditableText` with the hint as an `STextBlock` over it while empty - Hint Color is its own), the result count, the clear button (`NoBorder` button, not focusable, shown while text is typed), the filter (`SComboBox` of `FSearchFilterOption`, All first under a reserved key, shown when Filter Options has any). Colours, fonts, brushes and padding are attributes read from the active style each paint, so the designer shows edits at once.
- **Looks** (`ESearchBarLook`): Dark (default), Light, Pill (half-height rounding), Minimal (no box until hovered / typing), Custom (Style). `FSearchBarStyle::MakeLook` / `FillLook`; the look's style is made when first drawn (`GetActiveStyle`, cached per look). Picking Custom starts Style from the look it was (`PreEditChange` keeps the old look; written to the Widget Blueprint's widget through `WidgetEditorHooks::FindDesignerTemplate`). **Style Asset** (`USearchBarStyleAsset`, Data Asset "Search Bar Style") wins over both. Fonts in the constructors are the engine's Roboto asset (`UWidget::GetDefaultFontName`), so a saved style keeps a real font.
- **Typing:** Debounce Seconds (0.15, restarted per key; 0 = at once), Enter searches at once and commits (recent search, On Search Committed), Escape closes the suggestions, then clears (Clear On Escape), and on an empty bar is left unhandled (the screen's Back). Select All On Focus. `bSettingText` keeps Set Text from reading as typing.
- **Results, no Blueprint:** **Results Widget** (name, `GetOptions` = the tree's widgets; or `SetResultsWidgetObject`): a `UListView` (List / Tile / Tree View: its items captured when a search starts - `SourceItems` - and `SetListItems` with the matches, best first when Best Match First; put back when the search is cleared; `SetSearchSourceItems` for code that changes the items mid-search) or any `UPanelWidget` (children that don't match are Collapsed and their own visibility is given back later - `HiddenChildren`; a child the game hid itself is left alone and not counted; the bar itself and the No Results widget are skipped). **No Results Widget** shown (Self Hit Test Invisible) while searching with nothing matching, else Collapsed. Text Set in the designer filters on the first sync at runtime.
- **What an item is found by** (`GetItemTexts`): a Searchable Item - Search Text, Search Keywords (with the Search Keywords option), Search Filter Category; a widget - every Text Block / Rich Text (tags stripped) / Editable Text in it, joined (Search Inside Widgets), the first as its label; any other object - a `DisplayName` / `Name` / `ItemName` / `Title` / `Label` / `Text` property (Text, String or Name), read by reflection.
- **Suggestions:** a list under the bar while it has the focus: recent searches when empty; otherwise matches of what is typed among recent searches (+3), Suggestions (designer list or Set Suggestions) and the results' labels (Suggest Results; the first 500 items), ranked, de-duplicated, without the text already typed, Max Suggestions (6). Rows highlight the matched letters (Match Color, `GetMatchRanges`), a clock glyph marks recent ones. Up / down (D-pad too) move the highlight, Enter / Tab take it, click takes it. The list isn't focusable, so typing carries on.
- **Recent searches:** Remember Recent Searches, Max Recent Searches (8), Recent Searches Save Slot (a `USearchBarHistorySave` save game per bar; loaded on first use, written with `AsyncSaveGameToSlot`; empty = this session only).
- **Events:** On Search Changed (Query, Active Filter - None for All), On Search Committed, On Search Cleared, On Results Changed (count), On Suggestion Picked, On Search Focus Changed. **Functions:** Set Text (search or not), Get Text / Get Query, Clear Search (immediate), Focus Search, Has Search Focus, Set Filter Options, Set Active Filter, Get Active Filter, Set Suggestions, Add Recent Search, Clear Recent Searches, Get Recent Searches, Set Results Widget Object, Set Search Source Items, Refresh Results, Get Result Count (-1 with no Results Widget), Matches Query, Highlight Query, Set Look, Set Style Asset.

## Matching (`USearchLibrary`)
- The original functions are unchanged (Fuzzy Match, Fuzzy Match With Score, Fuzzy Filter Ranked, Filter Searchable Objects).
- **`FSearchMatchOptions`:** Match Mode (`ESearchMatchMode`: Fuzzy - the subsequence match, now tried from every place the first letter occurs and the best kept, letters skipped before the match not penalized; Contains; Starts With; Word Starts - spaces, punctuation, underscores, CamelCase and letter-to-digit start words; Exact), Each Word Separately (terms split on whitespace, every one must match, scores summed), Ignore Accents (Latin-1 and Latin Extended-A folded one character for one, so indices still line up), Case Sensitive, Min Query Length (shorter matches everything), Search Keywords.
- **Functions:** Search Match (`MatchWithOptions`), Search Filter Ranked, Get Match Ranges (start, length; merged), Highlight Matches (rich text, `<Match>` by default, `&`, `<`, `>` escaped), Normalize For Search, Filter Searchable Objects With Options; C++ `MatchAny` (an item's texts, keywords ranked 5 under the label).
- **`ISearchableItemInterface::GetSearchKeywords`** (new; native event with an empty default implementation, so existing C++ implementers still compile).

## Hand-built base (`UW_SearchBarBase`)
- Kept for layouts built entirely by hand; its class comment points to the Search Bar. Fixes: the filter box is no longer collapsed on construct when Set Filter Options was called before (straight after Create Widget); **On Search Committed** (Enter); **Hide Clear Button When Empty** (default off - as before).

## Production expectations
"There could be more use cases that users desire that I haven't thought of, but would be expected in a production-grade application."
- **Beyond the request:** filtering a list or panel by name with no Blueprint and an empty-state widget; looks and a shareable style asset; suggestions with highlighted matches and keyboard / D-pad picking; recent searches kept between sessions; match modes, multi-word queries, accent-insensitive matching, minimum length, keywords / synonyms; highlight helpers for result rows; result count; filter categories set in the designer; Escape behaviour that leaves Back to the screen; designer text filters at runtime start.

## Still open
- A global focus shortcut ("/" or Ctrl+F) - the screen calls Focus Search for now.
- Filtering a Flow List or Dynamic Entry Box by name (they are neither a List View nor a plain panel); reordering a panel's children by relevance.
- Sorting options (by name / rarity) beside the filter; multi-select filter chips.
- The filter dropdown uses the engine's Combo Box look (not the bar's style); the suggestion popup has no open / close animation.
- Gamepad: picking a suggestion with a face button while the virtual keyboard is up depends on the platform keyboard.
- Search inside the Settings Menu still uses its own box (`SMenuSettingsPanel::BuildSearch`).

## Unverified (no engine here: written, not compiled or run)
- `SSearchBarHost::OnFocusChanging` being called on widgets of both the old and the new focus path; `SMenuAnchor::SetIsOpen(.., bFocusMenu false)` keeping the focus in the field with Use Current Window; `MenuPlacement_ComboBox` sizing the popup to the bar; a non-focusable `SListView` still firing On Mouse Button Click; `SEditableText::GoTo(ETextLocation::EndOfDocument)` and whether `SetText` fires On Text Changed (guarded either way); `SComboBox::SetSelectedItem` with `ESelectInfo::Direct`; `UListView::SetListItems` with a `TArray<UObject*>` and `GetListItems` iteration; `FSlateDrawElement::MakeLines` with `TArray<FVector2f>` in 5.7; `HalfHeightRadius` rounding; `AsyncSaveGameToSlot` from a widget; the hint overlay lining up with the field's text; UHT accepting `TEXT("Match")` as a default for an `FString` parameter.

## Check by hand
- Place a Search Bar over a Wrap Box of item widgets, set Results Widget, type: items hide and come back; set No Results Widget to a Text Block.
- Point it at a List View with item objects that have a Name property; type, clear - the original items come back in order.
- Focus it with recent searches saved: the list appears; up / down / Enter; Escape twice.
- Each Look in the designer; Custom keeps the colours of the look it came from.
