## What production menus do (the research this is built on)
- **Settings as data, not screens.** Lyra's GameSettings plugin: a registry of setting objects (discrete, scalar, action, collections / pages), each with edit conditions (enable / visible, with a reason), dependencies (one setting re-evaluates others), a value source split between machine settings (`GameUserSettings`: display, scalability) and per-user shared settings (save game), and screens generated from it with a description panel. Here: Settings Schema assets + a per-player subsystem; the built-in pages ship in code.
- **Apply, confirm, revert.** PC games stage display changes and ask "Keep these settings? Reverting in 15 s" (Windows' own pattern); consoles apply instantly. Unapplied changes are asked about on Back. Reset to defaults per page. Here: an Apply policy per screen, a confirmation countdown for flagged settings, Revert to the session start, Reset Page.
- **Vendor tech through the vendors' Unreal plugins.** NVIDIA ships DLSS (Super Resolution, DLAA, Ray Reconstruction) and Streamline (Frame Generation, Reflex); AMD ships FidelityFX FSR (upscaling, frame interpolation) and Anti-Lag 2; Intel ships XeSS (upscaling, XeSS-FG, XeLL). All are driven by console variables, and their Blueprint libraries answer "supported on this GPU?". Games show only what the card supports, with Auto picking DLSS on RTX, FSR on AMD, XeSS on Intel, TSR otherwise. Modes are fixed render ratios (Quality 1.5x, Balanced 1.7x, Performance 2x, Ultra Performance 3x; DLAA / Native AA 1x).
- **Accessibility** (Xbox Accessibility Guidelines, Game Accessibility Guidelines, CVAA): colour blindness filters (Slate's colour vision correction, as Lyra), text / UI size, subtitles (size, background, speaker names), reduce motion, flashing reduction, camera shake, toggle instead of hold, remapping every input, screen-reader narration of menus (XAG 104), notification time.
- **Input switching.** CommonUI's input pre-processor: the last device used (with thresholds against a resting mouse or a drifting stick) switches the input method and the gamepad family (Xbox / PlayStation / Switch prompts) from the hardware the platform reports; prompts follow; the cursor hides on a pad; focus is given back to the screen for pad navigation.
- **Rebinding** through Enhanced Input's user settings (player mappable keys, key profiles, slots), with conflict handling (swap / unbind / refuse), reserved keys, a "press a key" capture with cancel and timeout.
- **Art-directed settings screens** (Deadlock, Valorant, Call of Duty, Forza Horizon; CommonUI button / text styles in Lyra): every part is the artists' - framed rows, brushed tabs, custom slider knobs and fills, chevrons that bump on a step, segmented options whose highlight slides, glowing focus frames - authored per state (normal, hovered, focused, pressed, selected, disabled), often one material reading state parameters; whole parts (tabs, prompts, dialogs) are UMG the art team owns, while the framework keeps focus, input routing and accessibility. Uppercase and tracked type, centred tab bars and palette-matched scroll bars are common finishing touches.
- **Performance overlays and benchmarks** (stat unit, RTSS, CapFrameX, in-game benchmarks): fps, frame time and per-thread times graphed, average fps and 1% / 0.1% lows, percentiles, hitches, a CSV.

Sources: Lyra `GameSettings` / `LyraSettingsLocal` / `LyraSettingsShared` (edit conditions, Apply / Revert, safe-zone and colour-blind settings, `SetColorVisionDeficiencyType`), CommonUI `FCommonInputPreprocessor` / `UCommonInputSubsystem` / platform gamepad names, Enhanced Input `UEnhancedInputUserSettings` (5.3+), NVIDIA DLSS / Streamline UE plugin docs (`r.NGX.DLSS.*`, `r.Streamline.DLSSG.*`, `t.Streamline.Reflex.*`), AMD FSR 3 UE plugin docs (`r.FidelityFX.FSR3.*`, `r.FidelityFX.FI.Enabled`), Intel XeSS UE plugin docs (`r.XeSS.*`), Xbox Accessibility Guidelines.

## Settings
- **A setting** (`UMenuSetting`, instanced in schemas): Id (what it is saved under, what conditions and code use), Display Name, Description, Keywords (search), Preview image; **Target** (where the value goes, below; none = Saved Value), Scope (Machine / User), Apply Mode (Default = the screen's policy / Immediately / On Apply), Requires Confirmation, Requires Restart, Reapply When Changed (ids); Shown When / Enabled When conditions (+ Disabled Reason), Platforms (`Windows`, `Desktop`, `Console`, `Mobile`...), When Unavailable (Hide / Disable).
- **Kinds:** Bool (On / Off text), Number (Min / Max / Step, Format Number / Percent / Percent Value / Multiplier, Decimals, Units, Min Text / Max Text - "Off", "Unlimited"), Choice (Options with Label, Description, Preview, Hidden Unless Current - Overall Quality's "Custom"; Wrap; Display Auto / Selector / Dropdown / Buttons), Key Binding (Mapping Name, Device, Slot Count), Action (Event / Auto-Detect Graphics / Reset Page / Reset All / Reset Key Bindings / Run Benchmark; Button Text; Confirm Text), Info (read-only text from its target).
- **Values are text** (the save, conditions and the AI use one form): Bool "true" / "false", Number "1.5", Choice its option's Value.
- **Conditions** (`FMenuSettingCondition`): another setting's value Equals / Not Equals / Greater / ... / Is True / Is False / Is Any Of (comma list); numbers compare as numbers. **System values**: `@ActiveUpscaler`, `@ActiveFrameGeneration`, `@ActiveLatencyReduction`, `@GPUVendor` (NVIDIA / AMD / Intel / Any), `@Platform`, `@RayTracingSupported`, `@InputDevice` (KeyboardMouse / Gamepad / Touch), `@Editing`. A condition on a setting that doesn't exist fails (its row hides).
- **Schemas** (`UMenuSettingsSchema`, Primary Data Asset): Pages (Id, Display Name, Icon, Order, Platforms, Sections (Id, Title, Settings, Key Bindings (+ device, categories), Shown When)), Priority. Merged over the built-in pages in Priority order: a page with an existing Id adds its sections; a section with an existing Id (or title) adds its settings; a setting with an existing Id replaces it in place. Sources: the built-in pages (Include Built In Pages), Project Settings > Menus > Schemas, a Settings Menu's Extra Schemas, Register Schema at run time. Project settings also hide pages / settings by Id and set project defaults by Id. Validation: duplicate ids, missing ids.

## Targets (where a value goes)
- **Console Variable**: any cvar (Name, Also Set, Scale, Invert, Value Map), written with Game Setting priority; unavailable while the cvar doesn't exist (a plugin off). Read back (so a quality preset's changes show).
- **Game User Settings**: Window Mode, Resolution (options from the monitor; Windowed lists convenient sizes), VSync, Frame Rate Limit, Overall Quality, the ten scalability groups, Resolution Scale, Dynamic Resolution, HDR Output / Nits (only where supported), Audio Quality. Applied (`ApplyResolutionSettings` / `ApplyNonResolutionSettings`) and saved by the engine.
- **Sound Volume**: Channel (Master, Music...) -> the project's sound class through a settings sound mix (made at run time if the project names none); reapplied after map loads.
- **Built-in**: Display Gamma, UI Scale (`UUserInterfaceSettings::ApplicationScale`), Color Blind Mode / Strength, Subtitles, Background Volume, Vibration / Strength (the controller's force feedback, by reflection), Reduce Motion / High Contrast / Menu Narration (plugin flags, `MenuAccessibility`), Controller Button Style, Field Of View.
- **Notification Preference**, **Language** (cultures with game localization, saved to config), **System Info**, **Graphics Feature** (below), **Saved Value**, and **Blueprint Target** (your own: Write Value / Read Value / Can Be Used events, Use Saved Value, Reapply After Map Load).
- C++: subclass `UMenuSettingTarget` (Is Available, Read, Write, Get Default, Get Options, Uses Saved Value, Reapply After Map Load, Writes Default On Start, Save).

## The subsystem (`UMenuSettingsSubsystem`, per local player)
- **Start:** the built-in schema, key binding contexts registered with Enhanced Input user settings, pages merged, the machine save (`NameTBD_Settings`, user 0) and the player's (`NameTBD_PlayerSettings`, platform user index) loaded; values: saved (when the target uses saved values), else the target's current value, else the default. **Only what the player changed is written on start** (an untouched cvar, volume or camera stays the game's) - except targets that must hold from the first frame (the upscaler, its mode, frame generation, latency reduction: Auto picks DLSS on RTX). A 0.25 s watch notices the player's controller arriving or changing (PIE start, map loads) and writes again what a map or pawn resets (sound mixes, force feedback, field of view), and binds the pawn-change event.
- **Changing:** Set Setting Value (made valid; disabled settings refuse) -> the target's Write -> stored in the scope's save -> every readable target read again (a preset's effect shows) -> settings listing it in Reapply When Changed written again -> On Setting Changed for each value that changed. Restart-required settings notify once (a notification). Step Setting, Reset Setting (back to default and out of the save, so the engine decides again), Reset Page, Reset All, Get / Set All Setting Values (cloud saves, presets).
- **Editing session** (Begin / End Editing, nesting): the snapshot Revert returns to (values, saves, keys). With the Apply Button policy, settings with Apply Mode Default wait (Get Setting Value shows them); Apply Settings commits them, starting the **confirmation** for Requires Confirmation ones: Confirmation Seconds (15) in real time (capped delta), On Confirmation Started / Ended; Confirm Settings(Keep) or the timeout reverts. Revert Settings puts values, saves and key bindings back. End Editing saves (async by default; sync on shutdown).
- **Key bindings:** Can Rebind Keys, Get Bound Key / Default (mapping, device, slot index -> the mapping's slots of that device in slot order), Bind Key (reserved keys refused, wrong device refused, conflict policy Swap / Unbind / Allow / Refuse with a message), Unbind, Reset Key Binding / All, Find Key Conflict, display names; saved with Enhanced Input's user settings. Key binding sections list one row per mapping of the device, sorted by category (the screen puts a heading over each).
- **Benchmark** (Start Benchmark, On Benchmark Finished, notifications) and the **performance overlay** (a Stat Graph put on the player's screen in the project's corner for Video > Performance Overlay; back after map loads).
- **Console:** `NameTBD.Settings.List [filter]`, `NameTBD.Settings.Set <Id> <Value>`, `NameTBD.Settings.Reset [Id]`, `NameTBD.Settings.Graphics` (features: installed, supported, active, Auto's pick), `NameTBD.Benchmark [seconds]`.

Status: installed / supported / why not ("Needs an NVIDIA graphics card").

## Input (`Input/`)
- **Menu Input Subsystem** (per local player): a Slate pre-processor sees every key, stick, mouse move and touch (never takes them) for this player's Slate user; switches Keyboard & Mouse / Gamepad / Touch with thresholds (Mouse Switch Distance 6 px, Stick Switch Threshold 0.4); the gamepad family from the hardware name (`FInputDeviceScope`; Project Settings Gamepad Hardware map, contains-match) or the platform; the Button Prompts setting overrides. Get Key For Action (the player's mapping, Enhanced Input `QueryKeysMappedToAction`) and Get Key Glyph (Key Glyph Sets per family + keyboard, else a family label: Cross / Circle / Square / Triangle, L1, ZL...). On Input Device Changed.
- **Menu Key Prompt** (palette NameTBD): Input Action or Keyboard / Gamepad Key, Show Device (Current / KBM / Gamepad), Label, Hide When Unbound (and on touch), Key Cap style (height, font, colours, corner), clickable (On Prompt Clicked), hold progress; refreshes on device and binding changes.
- **Input modifiers:** Scale By Setting (sensitivity X / Y settings, invert X / Y settings, base scale) and Dead Zone By Setting (radial / axial, setting + default), read every frame.
- **Rebinding UI:** a row's slots (primary / secondary; one for gamepad), Accept or click to capture ("Press a key..."), a capture pre-processor consumes the next key / mouse button / wheel for the player (Escape, or Menu on a pad row, cancels; the wrong device says so and keeps waiting; Key Capture Timeout 8 s), Delete / right-click unbinds, messages for swaps and refusals.

- **Skin** (`FMenuStyle::Skin`, `FMenuStyleSkin`): art for every part - Row, FocusBar, ModifiedDot, SectionHeading, CategoryHeading, TabBar, Tab, TabIndicator, SwitchTrack, SwitchKnob, SliderTrack, SliderFill, SliderThumb, SelectorBox, SelectorArrow, Pip, Segment, Dropdown, DropdownArrow, KeySlot, PrimaryButton, SecondaryButton, GhostButton, FooterPrompt, SearchBox, DescriptionPanel, Footer, DialogCard, ListCard, ListOption, Scrim, ScrollThumb, ScrollTrack. Each part (`FMenuPartSkin`): an image (`FWidgetEffectImage`: Image Source Texture 2D (texture or material brush, Material Parameters) or SVG) for Normal and, switched on one by one, Hovered / Focused / Pressed / Selected / Disabled (picked in that order of precedence: Disabled, Pressed, Selected, Focused, Hovered); Tint With Palette (multiplies by the colour the built-in look gives the part now, so one white image follows every palette and High Contrast), Tint, Outset (grow past the part: frames, glows), Keep Built In (draw the built-in shape under it). The scroll bar's thumb / track take a texture or material brush (not SVG) or the palette's Track colour. A style with any material in its skin makes the screen volatile (repainted each frame) so animated materials move under invalidation.
- **Layout and type for art direction:** Title Alignment and Tabs Alignment, Tab Padding, Button Padding, Switch Size, Slider Track Height / Thumb Size, Selector Arrow Size, Pip Height, Dialog Width, Scroll Bar Thickness (0: the engine's), Uppercase Tabs / Sections (on: as before) / Labels / Buttons.
- **Custom Widgets** (`FMenuStyle::Widgets`): your own Widget Blueprints for parts - Tab (`UMenuTabWidget`: On Tab Assigned, On Tab State Changed (selected, hovered, pressed), Select Tab; LabelText filled), Heading (`UMenuHeadingWidget`: sections and key binding categories), Footer Prompt (`UMenuFooterPromptWidget`: Back / Reset / Apply / Revert and the tab prompts; On Glyph Changed with the key for the device in use, On Prompt State Changed, Press; LabelText / KeyText filled), Description (`UMenuDescriptionWidget`: On Description Changed with `FMenuSettingDescription` - title, value line, current / default, body, option text, warning, notes, preview, enabled, restart; TitleText ... ## Decisions made without asking
- **Settings in schemas + a per-player subsystem**, not a menu-owned store: any widget, Blueprint or system reads the same values; the built-in pages are made in code so they need no asset and stay current with the plugin.
- **Vendor technology by console variables and reflection**, never a build dependency: the plugin builds with none of the vendor plugins installed; a missing plugin hides its options; new versions are table rows. The shipped variable names are the vendors' documented ones as known; a wrong one only hides that option.
- **Untouched settings are never written** (except the upscaler family): the project's scalability, device profiles and inis keep deciding until the player changes something; Reset returns a setting to that state.
- **Instant policy by default** (console standard; display changes still confirm), Apply Button available per screen.
- **Real time** for confirmation countdowns, benchmark, graphs and dialog timeouts (menus are often shown paused); the panel's sounds are throttled in real time because the shared UI sound player throttles on world time, which stops while paused.
- **Machine scope** for display, graphics, audio, colour blindness and UI scale (one screen, one audio device); **user scope** for controls, accessibility and gameplay.
- Menu Manager additions default to the old behaviour (the project rule); the pause / multiplayer contract is unchanged.
- Key bindings stay in Enhanced Input's own save (its user settings), not the plugin's.
- The Menu Settings Screen's On Back Requested always reports handled: the menu decides, and closes itself through the manager.
- **Skin images are `FWidgetEffectImage`** (the plugin's image-or-material-or-SVG with per-instance materials), not plain brushes: SVGs and live material inputs come for free, and the project rule for image properties holds.
- **One image per state, picked by precedence** (Disabled > Pressed > Selected > Focused > Hovered > Normal) rather than layered states: what UMG's button styles and CommonUI do; a material can blend states itself from the inputs.
- **Custom parts are hosted, not handed the screen:** the screen keeps input, focus, sounds and narration, so a custom tab or row can't break pad navigation; your widget only draws and may call Select Tab / Press / Choose.
- **Custom rows stay `SMenuSettingRow`s** (the row is the focus target and the UMG widget its content) rather than making the panel accept arbitrary widgets as rows: every row feature works on them unchanged.
- **Custom dialogs fill the dialog layer and draw their own scrim** (the built-in scrim isn't added under them): a designer's dialog is often full screen.
- **A style change rebuilds the Settings Menu's screen** (on the page shown, focus kept) instead of patching it in place: custom part classes, alignments and the scroll bar follow at once; style edits at run time are rare.
- **The built-in scroll bar now follows the palette** (Track colour thumb, no track) instead of the engine's: it read as foreign on every preset.
- **Standalone controls bind by Setting Id** like Setting Control, and keep their own value when unbound, so they work in any UMG.
